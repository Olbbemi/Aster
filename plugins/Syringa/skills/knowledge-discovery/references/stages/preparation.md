# 실행 준비 단계 수행 지침

- 단계 식별자: `preparation`.
- 상대 링크는 이 문서가 있는 디렉토리를 기준으로 한다.

## 공통 흐름과의 연결

시작, 분기와 재개는 [진행 흐름](../workflow.md)을 따른다.
스크립트의 인자와 데이터 형식은 [실행 계약](../execution.md)에서 확인한다.

## 단계 역할

필수 입력과 모델 및 분석 범위를 확인하고 실행 상태를 생성한다.

## 입력과 시작 시 확인

새 실행을 시작할 때 적용한다.
분석 대상과 저장 기준 경로는 사용자가 지정한 입력을 사용한다.

## 수행 흐름

### 실행기와 필수 입력

[실행 계약](../execution.md)을 읽고 단계별 실행 스크립트 제공 여부를 확인한다.
필요한 스크립트가 없거나 실행할 수 없으면 진행을 중단하고 이유를 알린다.
파일을 직접 써서 실행기의 검증과 저장 절차를 우회하지 않는다.

[필수 입력](../../SKILL.md#필수-입력)이 모두 있는지 확인한다.

[모델 선택 절차](../model-selection.md)에 따라 이번 실행의 모델과 강도 및 승인 범위를 확인한다.
실행기는 별도 AI를 호출하거나 모델을 변경하지 않는다.

### 분석 범위 확인

`inspect_inputs.py`로 두 입력을 검사한다.
대상에 디렉토리가 있으면 내용을 읽기 전에 구조를 제시하고,
포함할 파일과 하위 디렉토리 범위를 확인한다.
범위 없이 디렉토리 경로만 주어졌다면 반드시 되묻되,
사용자가 이미 명확히 지정한 범위는 재확인하지 않는다.

파일이 참조한다는 이유로 다른 파일까지 분석 범위를 넓히지 않는다.

### 실행 생성

범위와 모델 승인을 확인한 뒤 확정한 파일 목록을 `start_run.py`에 전달한다.
[시작 객체](../execution.md#시작-객체)에 실제 확인 근거를 넣고 반환된 `run`을 이후 호출에 사용한다.

## 완료 확인과 인계

입력, 범위와 모델 확인 및 실행 생성이 성공하면 [후보 제시](candidate-proposal.md)로 이동한다.
실행 생성 전 실패에는 `run`이 없으므로 원인과 누락 조건을 보고하고 중단한다.
