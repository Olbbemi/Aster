# 상세 분석과 저장 단계 수행 지침

- 단계 식별자: `analysis-and-save`.
- 상대 링크는 이 문서가 있는 디렉토리를 기준으로 한다.

## 공통 흐름과의 연결

시작, 분기와 재개는 [진행 흐름](../workflow.md)을 따른다.
스크립트의 인자와 데이터 형식은 [실행 계약](../execution.md)에서 확인한다.

## 단계 역할

승인된 주제별 상세 내용을 원자료와 대조하고 독립 파일로 저장한다.

## 입력과 시작 시 확인

승인된 후보와 고정된 자료를 사용한다.
재개할 때는 [상태 확인](completion.md) 결과의 완료, 실패와 미처리 주제를 구분한다.

## 수행 흐름

상세 작성에 필요한 원자료는 같은 실행의 `read_source.py`로 다시 확인한다.

승인된 주제를 하나씩 처리하되 주제마다 다시 승인받지 않는다.
주제 안의 승인된 개념을 상세 분석하고 `save_topic.py`으로 한 파일에 저장한 뒤 다음 주제를 이어간다.
각 개념에 대제목을 붙이고 아래 항목 중 자료에서 뒷받침되는 내용만 포함한다.

- 개념 설명: 의미와 역할.
- 문법과 사용 형태: 자료에서 확인한 표현과 사용 방식.
- 동작과 조건: 실제로 드러난 처리 원리, 조건과 제약.
- 최소 예시: 이해에 필요한 코드 또는 명세의 최소 부분.

해당 내용이 없는 항목은 제목 자체를 생략한다.
원본을 다시 열지 않아도 위키 작성의 재료가 되도록 설명하되 자료에 없는 사실을 보충하지 않는다.

자료에 명시된 타입, 적용 대상, 조건과 제약을 설명에서도 유지한다.
특정 예시에서 확인한 동작을 모든 경우에 적용되는 규칙으로 일반화하지 않는다.

프로젝트 전용 이름과 맥락은 기술적 의미를 보존할 수 있을 때 일반화한다.
의미를 보존할 수 없는 내용은 억지로 일반 기술 지식으로 바꾸지 않는다.

저장 전에 작성한 설명을 원자료와 대조하여 적용 범위를 넓히거나 조건을 빠뜨리지 않았는지 확인한다.
조건이 빠졌으면 설명에 반영하고, 자료만으로 확인할 수 없는 주장은 근거가 있는 범위로 좁힌 뒤 저장한다.

출처 구역, 원본 경로, 행 번호와 원문 참조 링크는 결과 본문에 넣지 않는다.
문법의 일부인 일반 경로 문자열까지 무조건 삭제하지는 않는다.

## 완료 확인과 인계

저장에 성공하면 다음 승인 주제를 처리하고 모두 끝나면 [종료와 결과 확인](completion.md)으로 이동한다.
실패나 중단 요청이 있으면 새 주제 처리를 멈추고 종료 단계에서 실제 결과를 확인한다.
