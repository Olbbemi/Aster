# Knowledge Discovery 진행 흐름

## 문서 역할과 읽는 시점

상대 링크는 이 문서가 있는 디렉토리를 기준으로 한다.
현재 단계에서 필요한 문서를 읽으며 다음 단계의 상세 분석을 미리 수행하지 않는다.

| 문서 | 역할 | 읽는 시점 |
| --- | --- | --- |
| [실행 준비](stages/preparation.md) | 필수 입력, 실행 환경, 모델과 자료 범위 확인 및 실행 생성 | 새 실행을 시작할 때 |
| [후보 제시](stages/candidate-proposal.md) | 자료 읽기, 일반 기술 후보 선별 및 주제별 제시 | 범위를 고정한 뒤 후보를 만들 때 |
| [일괄 승인](stages/approval.md) | 사용자 선택 해석과 승인 집합 고정 | 후보를 제시하고 답변을 기다리거나 처리할 때 |
| [상세 분석과 저장](stages/analysis-and-save.md) | 승인된 주제별 내용 작성, 원자료 대조와 저장 | 승인 집합이 확정된 뒤 |
| [종료와 결과 확인](stages/completion.md) | 실제 상태 확인, 완료/실패/미처리 구분과 보고 | 완료, 빈 결과, 중단, 실패 또는 재개 시 |
| [실행 계약](execution.md) | 기능별 호출, 입력/응답 스키마, 상태와 저장 및 오류 계약 | 각 단계에서 스크립트를 호출하거나 오류를 해석할 때 |
| [모델 선택 절차](model-selection.md) | 모델과 강도 확인 및 승인 범위 | 실행 준비 또는 기존 승인 범위를 벗어날 때 |

## 기본 순서와 분기

1. 실행 준비에서 두 경로, 모델과 분석 범위를 확인하고 실행 상태를 생성한다.
2. 후보 제시에서 확인된 자료만 읽고 후보를 등록한 뒤 사용자에게 제시한다.
3. 일괄 승인에서 선택 답변을 확인하고 승인 집합을 고정한다.
4. 상세 분석과 저장에서 승인된 주제를 하나씩 처리한다.
5. 종료와 결과 확인에서 실제 저장 결과와 남은 작업을 보고한다.

준비 조건이 충족되지 않으면 해당 입력이나 범위를 확인할 때까지 분석을 시작하지 않는다.
정상적인 후보 없음 또는 명시적 전체 제외는 상세 분석 없이 종료 단계로 이동한다.
선택 답변이 없거나 모호하면 승인 단계에 머물며, 실패를 빈 결과로 바꾸지 않는다.
명시적인 중단 요청이나 실행 실패가 발생하면 종료 단계에서 실제 상태와 이유를 확인한다.

단계 이동 자체를 위한 추가 승인을 요구하지 않는다.
각 단계에서 정한 입력 확인과 후보 선택 및 모델 승인 조건을 따른다.

## 재개

사용자가 지정한 같은 실행의 `run`이 있으면 먼저 종료 단계의 상태 조회 절차를 따른다.
실행기를 통한 상태 조회 없이 저장 성공이나 다음 단계를 추정하지 않는다.
실행 상태의 의미와 보관 조건은 [명령과 실행 상태](execution.md#명령과-실행-상태)를 따른다.

| 확인한 상태 | 이어서 할 작업 |
| --- | --- |
| collecting | 후보 제시 단계에서 자료와 후보를 확인한다 |
| awaiting-approval | 일괄 승인 단계에서 등록된 후보에 대한 선택 답변을 확인한다 |
| processing | 상세 분석과 저장 단계에서 승인된 미처리 또는 재시도 가능한 실패 주제를 처리한다 |
| empty 또는 excluded | 종료 단계에서 파일이 없는 정상 결과를 보고한다 |
| completed | 종료 단계에서 저장 완료 파일을 보고한다 |

복구 필요 오류가 있으면 위 단계 재개보다 오류 처리를 우선하고 저장을 계속하지 않는다.
사용자가 중단한 실행은 재개 요청 전까지 새 주제를 처리하지 않는다.
`run`이 없거나 상태를 잃었다면 다른 실행을 자동 검색하지 않고 준비 단계에서 새 실행으로 시작한다.
자료가 변경된 경우에는 기존 후보와 승인을 재사용하지 않으며 범위와 후보 선택을 새로 확인한다.
