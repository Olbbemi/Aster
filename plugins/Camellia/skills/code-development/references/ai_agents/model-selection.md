# 모델 제안과 승인

작업을 시작하거나 재개할 때 범위와 기존 모델 승인을 확인하고, 해당 작업 묶음을 수행하기 전에 읽는다.
상대 경로는 이 파일이 있는 references/ai_agents/ 디렉토리를 기준으로 한다.
상대 CLI의 호출은 [교차 검증 실행 안내](review-execution.md)를 따른다.

## 공용 선택 기준 읽기

범위를 파악하는 데 필요한 자료를 확인한 뒤 모델을 제안하기 전에
[Aster 공용 모델 선택 기준](https://github.com/Olbbemi/Aster/blob/main/shared/model-selection.md)을 읽는다.
정본은 Aster main의 `shared/model-selection.md`이며 설치된 플러그인에서는 위 URL로 접근한다.
스킬 안에 권장표 사본을 두거나 Aster 저장소의 로컬 경로를 필수로 요구하지 않는다.

같은 작업에서 읽은 표는 제안마다 다시 읽지 않는다.
문서가 갱신됐거나 기존 선택 근거를 재검토할 필요가 있을 때 다시 확인한다.
읽지 못하면 그 사실을 알리고 사용자에게 모델과 강도를 지정받는다.
이미 사용자가 해당 범위의 조합을 지정했다면 그 지정을 사용하고 다시 묻지 않는다.

## 작업 묶음과 제안

| 기본 묶음 | 포함할 작업 |
| --- | --- |
| 논의와 설계 | 요구사항, 기존 코드 확인, 구조와 테스트 계획 |
| 구현 | 코드와 테스트 작성, TDD와 리팩터링 |
| 검증과 QA | 검증 수행, 결과 판단과 사용자 참여 QA |

묶음은 선택의 출발점이며 단계마다 모델을 고정하는 규칙이 아니다.
작업 성격과 변경 영향에 따라 같은 모델/강도로 진행할 범위는 합치고,
복잡한 분석처럼 별도 판단이 필요한 부분은 나눈다.
교차 검토 모델은 진행 모델과 역할을 구분하여 해당 검토 범위와 함께 제안한다.
검토의 수행 시점과 조건은 [교차 검증 지침](../guidelines.md#교차-검증의-연결-위치)을 따른다.

모델명, 추론 강도, 담당 범위와 선정 이유를 함께 제시하고 사용자 승인을 받는다.
단계나 교차 검토의 승인 요청과 함께 확인할 수 있지만 각각의 승인 범위는 구분한다.
모델 승인은 단계 완료, 명세 변경이나 별도 에이전트 실행 및 외부 변경의 권한을 대신하지 않는다.

## 승인 유지와 변경

| 상황 | 처리 |
| --- | --- |
| 승인한 모델/강도/범위에서 단계 진행, 수정 또는 재검사 | 기존 승인을 재사용하며 단계마다 다시 받지 않는다. |
| 모델이나 강도 변경 또는 승인 범위 밖의 작업 추가 | 이유와 변경할 조합/범위를 제시하고 적용 전에 승인받는다. |
| 사용자가 모델/강도/범위를 직접 지정 | 해당 지정을 그 범위의 승인으로 인정한다. |
| 승인 대상이 불명확하거나 무응답 | 해당 묶음의 수행을 대기하고 필요한 확인을 요청한다. |

기존 report에 권장 조합만 있으면 실행 승인으로 간주하지 않는다.
해당 범위를 수행하기 전에 승인과 실제 적용을 확인하되 과거 결과나 승인은 재작성하지 않는다.

## 실제 적용과 확인

- 승인한 조합을 현재 세션이 사용 중이면 그대로 진행한다.
  별도 실행이 허용되어 있고 모델을 지정할 수 있으면 승인한 조합으로 호출한다.
- 현재 모델과 강도는 확인 가능한 실행 상태를 우선 사용한다.
  설정 파일의 기본값이나 사용 가능한 모델 목록만으로 실제 적용 상태를 확정하지 않는다.
- 직접 확인할 수 없으면 사용자 확인을 근거로 진행한다.
  직접 확인과 사용자 확인을 구분하며 사용자 확인을 독립 검증으로 표현하지 않는다.
- 전환이 필요하지만 직접 바꿀 수 없으면 사용자에게 전환을 요청한다.
  직접 확인 가능한 상태 또는 사용자의 변경 완료 확인을 받은 뒤 해당 묶음을 진행한다.
- 승인한 조합을 사용할 수 없으면 대안과 이유를 제안하고 승인받는다.
  임의로 대체하거나 실제로 바꾸지 않은 모델을 변경했다고 보고하지 않는다.

## report 기록

모델을 결정한 단계 report의 "작업 모델과 승인"에 담당 범위, 모델/강도, 이유,
승인 근거와 적용 확인의 출처를 모아 기록한다.
같은 승인으로 후속 단계를 진행하면 해당 report와 항목을 참조한다.
새 승인이나 실제 적용 상태의 변경이 있으면 그 단계 report에 이전 근거와 변경 내용을 연결한다.
정확한 모델/강도를 직접 확인할 수 없다면 사용자 확인 여부를 구분하고, 어느 쪽도 없으면 미확인으로 남긴다.

기록은 [report 저장 시점](../guidelines.md#report-저장-시점)에 반영한다.
첫 report 생성 전에는 대화의 승인을 유지하고 첫 저장 때 포함한다.
모델표와 동일한 승인을 단계마다 복사하거나 별도 모델 기록 파일을 만들지 않는다.
