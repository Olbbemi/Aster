# 교차 검증 실행 안내

교차 검증을 수행하기로 한 경우 상대 CLI를 호출하고 결과를 확인할 때 읽는다.
상대 경로는 이 파일이 있는 references/ai_agents/ 디렉토리를 기준으로 한다.
수행 시점, 검토자 역할과 지적 처리는 [교차 검증 지침](../guidelines.md#교차-검증의-연결-위치), 모델의 선택은 [모델과 추론 강도 안내](model-selection.md)를 따른다.

## 실행 방식

Codex가 작성한 산출물은 Claude가, Claude가 작성한 산출물은 Codex가 직접 검토한다.

아래 명령은 모델과 추론 강도를 지정하는 기본 형식이다. 예시의 조합을 모든 검토에 고정하지 않는다.

별칭과 실제 모델은 구분하고, 사용할 모델/옵션과 파일 접근 가능 여부를 현재 환경에서 확인한다.

## Codex에서 Claude 호출

```bash
claude -p '프롬프트' --model opus --effort high
```

| 옵션 | 역할 |
| --- | --- |
| `-p '프롬프트'` | 전달한 요청을 비대화형으로 실행하고 결과를 반환한다. |
| `--model opus` | 호출할 모델을 선택한다. `opus`는 별칭이며 실제 모델은 실행 시 확인한다. |
| `--effort high` | 해당 실행의 추론 강도를 지정한다. |

특정 버전으로 고정해야 하면 `--model`에 환경에서 지원하는 전체 모델 식별자를 사용한다.
예: `claude-opus-5`, `claude-sonnet-5`. 제공 환경에 따라 지원 식별자와 별칭의 해석이 다를 수 있다.

### 명령 구성

- 셸 실행 도구에 `claude -p` 명령을 직접 전달한다. Python 등의 실행 래퍼로 감싸지 않는다.
- Codex 0.154.0에서 셸 명령에 작은따옴표 이스케이프 `'\''`가 포함되면 API 연결이 실패하고, 해당 표기를 피하면 성공하는 동작을 확인했다. 기본형은 내부에 작은따옴표가 없는 요청문을 작은따옴표로 감싸 전달한다.
- 검토할 원문은 파일 경로로 전달한다. 인용 문제를 피하려고 코드, 테스트나 기준 자료의 원문을 임의로 바꾸지 않는다.

### 도구와 파일 권한

- `--tools`에는 검토자가 사용할 도구를 지정한다. 리뷰 파일을 작성해야 하면 `Write`를 포함한다. 테스트를 재실행해야 하면 `Bash`와 해당 테스트 명령의 허용 규칙을 검토 범위에 맞게 추가한다.
- 파일 경로 권한은 `--allowedTools`에 `Read(경로)`와 `Edit(경로)`로 지정한다. `Write` 도구의 파일 생성 권한도 `Edit(경로)`로 지정한다. `Write(경로)` 규칙은 파일 경로 검사에 사용되지 않는다. 표기와 적용 범위는 [Claude 파일 권한 문서](https://code.claude.com/docs/en/permissions#read-and-edit)를 따른다.
- 허용 규칙에 사용할 경로는 `readlink -f` 등으로 실경로를 확인한 뒤, 슬래시 두 개로 시작하는 파일 시스템 절대 경로로 구성한다. 예를 들어 실경로 `/home/user/project/review.md`의 쓰기 규칙은 `Edit(//home/user/project/review.md)`다. 심볼릭 링크 별칭을 그대로 규칙에 넣지 않는다.
- 읽기 허용에는 검토 대상 코드, 테스트, 선행 자료와 리뷰 템플릿을 포함한다. 쓰기 허용은 요청에서 지정한 리뷰 파일 한 경로로 한정한다.

## Claude에서 Codex 호출

```bash
codex exec '프롬프트' --model gpt-6-astra -c 'model_reasoning_effort="high"'
```

| 옵션 | 역할 |
| --- | --- |
| `exec '프롬프트'` | 전달한 요청을 비대화형으로 실행하고 결과를 반환한다. |
| `--model gpt-6-astra` | 호출할 모델의 식별자를 지정한다. |
| `-c 'model_reasoning_effort="high"'` | 해당 실행의 추론 강도 설정을 지정한다. |

다른 권장 모델의 식별자는 `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-5.6-sol`이다.
추론 강도는 `--effort`가 아니라 `-c`의 설정값으로 전달한다.

## 요청과 작업 경로

- 검토 대상 프로젝트를 작업 디렉토리로 사용하고, 대상 자료와 리뷰 저장 위치를 명확히 전달한다. 새 CLI가 현재 대화 내용을 알고 있다고 가정하지 않는다.
- 요청에 포함할 자료, 기준과 검토자의 변경 범위는 [요청 전달 지침](../guidelines.md#요청-전달과-검토자-역할)을 따른다.
- 요청에는 실행 대상인 에이전트/CLI와 실제 사용할 옵션 이름 및 값을 식별할 수 있게 전달한다. 셸 명령 전체를 요청문 안에 다시 삽입해 중첩 인용을 만들지 않는다. 실제 호출 명령은 호출자의 실행 근거에 남긴다. 프롬프트 전문은 명령 기록에서 생략할 수 있다.
- 요청문에는 [리뷰 템플릿](../../assets/review_reports/review-template.md)의 위치를 전달하고, 검토자가 자신의 에이전트 이름과 실제 모델명/버전, 전달받은 호출 정보 및 직접 확인한 실행 결과를 작성하도록 안내한다. 정확한 모델을 확인하지 못하면 추정하지 않고 `확인 불가`로 적는다. 사용자가 요청을 전달한 경우에는 그 전달 방식과 확인 가능한 근거를 기록하고 직접 CLI 호출로 기재하지 않는다.
- 검토 자료를 읽고 지정 리뷰 파일을 작성할 수 있는지 확인한다. 필요한 작업 경로와 권한 옵션은 해당 실행 환경에 맞게 정한다.
- Codex를 Git 저장소 밖에서 실행해야 할 때는 `--skip-git-repo-check`를 사용할 수 있다. 모든 호출에 기본으로 붙이지 않는다.

## 결과 확인과 기록

1. 호출자는 상대 CLI의 종료 결과와 반환 내용을 확인한다. 실패나 미수행을 검토 완료로 기록하지 않는다. 종료 결과와 간략한 반환 내용은 원본 report의 "보완 요청과 처리 결과"에 리뷰 링크와 함께 남긴다. 실제 리뷰가 없으면 링크 대신 미수행 사실과 사유를 기록한다.
2. 지정 경로의 리뷰 파일을 읽고 대상 report, 검토 범위와 결과가 요청에 대응하는지 확인한다. 리뷰 작성 형식은 [리뷰 템플릿](../../assets/review_reports/review-template.md)을 따른다.
3. 검토자가 작성한 실행 대상/근거와 검토자/모델 정보를 실제 호출에 대조한다. 리뷰의 실행 결과는 검토자가 확인한 검토 수행 및 파일 작성 결과이며, 호출 종료 뒤에만 알 수 있는 종료 코드를 미리 기록하지 않는다. 원본 작성자는 리뷰를 수정하지 않는다. 정보가 누락되거나 맞지 않으면 원본 report에 차이를 남기고 검토자에게 확인을 요청한다. 별도 신원 인증이나 세션 식별자 대조를 필수로 요구하지 않는다.
4. [리뷰 의견 검토와 사용자 합의](../guidelines.md#리뷰-의견-검토와-사용자-합의)에 따라 지적을 판단하고 후속 처리를 진행한다.

직접 호출이나 실제 검토를 수행할 수 없으면 [수행 불가와 진행](../guidelines.md#수행-불가와-진행)을 따른다.
