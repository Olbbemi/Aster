# 작업 기록의 정형 검사

이 문서는 code-development 사용 중 report와 연결 자료를 검사할 때 읽는다.
스킬 소스 자체나 제품 코드의 테스트를 대신하지 않는다.
검사는 선택한 작업을 읽기만 하며 상태, 체크리스트와 파일을 변경하지 않는다.

## 실행 시점

- 저장한 결과를 최종 검토/승인에 제출하기 전에 실행한다.
- 재개하거나 다음 단계에서 기존 report를 입력으로 사용하기 전에 실행한다.
- 같은 파일 상태에 대한 검사 근거가 있고 변경이 없으면 재사용한다.
  매 응답이나 저장마다 반복하지 않는다.
- manifest, report 또는 연결 자료를 보완하면 영향받는 작업을 다시 확인한다.
  검사 통과는 기존 [선행 report 대조](guidelines.md#다음-단계-진입-시-선행-report-확인)를 대신하지 않는다.

아직 작업 주제를 선택하지 않았거나 최초 report를 저장하기 전에는 실행하지 않는다.
검사를 위해 미시작 단계의 report나 디렉토리를 생성하지 않는다.

## 실행 환경과 명령

Python 3.10 이상과 [requirements.txt](../scripts/requirements.txt)의 패키지를 사용한다.
입력은 UTF-8이며 BOM과 CRLF도 허용한다.
필요한 패키지가 없으면 프로젝트 Python 환경과 기존 권한 범위에서 준비한다.
검사기는 패키지를 자동 설치하지 않는다.

아래 `<스킬 경로>`는 현재 로드한 code-development의 실제 설치 경로이며,
`<작업 주제 경로>`는 선택한 프로젝트의 `specs/<대주제>/<작업 주제>/` 절대 경로다.
현재 작업 디렉토리에 의존하지 않도록 두 경로를 절대 경로로 전달한다.

```bash
python3 -m pip install -r <스킬 경로>/scripts/requirements.txt
python3 -B <스킬 경로>/scripts/check_reports.py <작업 주제 경로> --json
```

[검사기](../scripts/check_reports.py)는 `--json`을 생략하면 텍스트로 출력한다.
입력 폴더 상위의 `freight-manifest.md`에서 선택한 작업의 항목을 찾는다.
결과는 표준 출력으로 제공하며 검사기가 별도 로그나 캐시를 저장하지 않는다.
네트워크와 Aster 개발 저장소를 실행 의존성으로 요구하지 않는다.

## 기계적으로 확인하는 범위

### report 형식과 연결

형식과 연결의 기준은 [report 작성과 인계](guidelines.md#report-작성과-인계),
[저장 구조](guidelines.md#저장-구조와-작업별-기록)와 단계별 템플릿이다.
검사 범위는 다음으로 한정한다.

| 항목 | 판정 |
| --- | --- |
| 프론트매터 | YAML 매핑, 중복 키, 필수 status/base_on과 타입 및 허용값 |
| 현재 report의 공통 영역 | H2 단계 결과, 인계 사항, 완료 체크리스트와 사용자 승인 각각의 존재와 중복 |
| manifest | 선택 작업의 H2 디렉토리 링크, stages/reference_reports 필드와 중복 없는 단계 식별자 목록 |
| report 파일명 | 해당 작업 stages에 포함된 단계와 001부터 사용하는 양수 번호 형식. 세 자리보다 큰 번호도 허용 |
| report 개정 | 단계별 가장 큰 번호가 현재 report이고 이전 번호는 superseded인지 |
| base_on | 첫 단계는 null, 이후는 같은 작업의 바로 앞 단계 report 파일인지 |
| 선행 상태 | 현재 진행/승인용 report의 선행 입력이 completed인지. hold/superseded의 과거 연결은 보존 |

단계 순서는 선택 작업의 stages를 사용하며 현재 기본 목록으로 덮어쓰지 않는다.
미시작 후속 report 부재와 번호 공백만으로 오류를 만들지 않는다.
과거 superseded 본문에는 현재 템플릿의 제목을 소급 강제하지 않는다.
추가 메타데이터 필드의 의미, 개별 H3 이하 제목, 문서 내용과 승인 진위는 검사하지 않는다.
코드 예시/주석/인용문 속 제목을 필수 본문 영역으로 세지 않는다.

### 로컬 링크

선택 manifest 항목, 현재 report와 현재 design report 번호의 상세 디렉토리를 검사한다.
다른 작업이나 과거 report는 링크 대상/절 확인에 필요한 만큼 읽으며 재귀 검사하지 않는다.
하위 심볼릭 링크 디렉토리는 순회하지 않고 미판정으로 알린다.

CommonMark 파서가 인식하는 링크와 이미지의 로컬 대상을 해당 문서 위치 기준으로 해석한다.
`/`로 시작하는 로컬 경로는 파일시스템 절대 경로이며 저장소 뷰어의 루트 경로를 추정하지 않는다.
HTML의 href/src 속성은 검사하지 않는다.
참조형 링크도 포함하며 코드 예시, 주석과 프론트매터 속 경로는 추출하지 않는다.
외부 URL/별도 URI는 SKIP이며 실제 접근을 확인한 것이 아니다.
쿼리의 동적 의미와 자연어로 쓴 파일 경로는 판정하지 않는다.
실제 링크로 작성한 아직 없는 대상은 누락으로 보고하므로 생성 예정 경로는 코드 표기로 구분한다.

Markdown 절은 제목의 텍스트/인라인 코드/이미지 대체 텍스트를 기준으로 판정한다.
앞뒤 공백을 제거하고 소문자로 바꾸며 ASCII 공백을 `-`로 치환한다.
문자/결합문자/숫자와 `-`, `_`를 유지하고 다른 문자를 제거한다.
동일 이름은 문서 순서대로 `-1`, `-2` 등을 붙이며 HTML id/a name도 인정한다.
코드 예시/주석의 제목과 앵커는 제외한다.
일반 연결 문서와 상세 파일은 첫 `---`부터 닫는 구분자 사이가 유효한 YAML 매핑일 때만 프론트매터로 제외한다.
그 외는 일반 Markdown으로 읽는다. report의 필수 프론트매터 검사는 별도로 유지한다.
URL 인코딩은 한 번 해제하며 잘못된 인코딩과 NUL은 실패다.
대상 문서의 UTF-8 디코딩 실패는 링크 문법 위반이 아닌 읽기 오류다.
비Markdown 파일/디렉토리의 절은 미판정으로 표시한다.
이 정책은 모든 뷰어의 앵커 생성 방식을 보증하지 않는다.

### ASCII 도식의 형식 보조

[설계 도식 기준](stages/design.md#ascii-도식의-작성과-표시-확인)에 따라
`text ascii-flow`로 표시한 fenced code block만 대상으로 한다.
일반 코드와 기존의 표시 없는 도식을 자동으로 추정하거나 변환하지 않는다.
닫는 코드 블록 구분자, 탭 및 제어문자, Unicode 박스/블록/기하 도형(U+2500-25FF)을 확인한다.
이름에 ARROW가 있는 비ASCII 기호, en/em dash(U+2013/U+2014)와 전각 `+ - | < >`도 확인한다.
한글 설명 자체를 금지하지 않는다.

결과에는 검사한 도식 수를 표시한다.
0개라는 결과가 모든 흐름을 확인했다는 뜻은 아니다.
문자 형식 통과는 연결선의 정렬, 실제 글꼴/뷰어에서의 표시와 가독성 통과가 아니다.

## 결과와 후속 처리

결과에는 범위, 읽은 파일, 항목별 상태/식별자/위치와 이유를 포함한다.
읽은 파일은 실제 경로 기준으로 중복을 제거하고 과거 본문 검사에서 제외한 report도 나열한다.
링크의 줄 번호는 링크가 포함된 Markdown 블록의 시작 위치다.

| 종료 코드 | 의미 |
| --- | --- |
| 0 | 적용한 정형 검사 통과 |
| 1 | 형식 또는 연결 위반 발견 |
| 2 | 입력/의존성/읽기 오류 또는 미판정. FAIL이 함께 있으면 그 항목도 확인 |

실패/미판정 항목의 위치와 이유를 확인하고 기존 보완/회귀 규칙에 따라 처리한다.
같은 종료 2라도 ERROR와 UNCHECKED는 항목별 상태와 이유로 구분한다.
미판정 절 링크를 지워 통과를 만들지 않으며 필요한 수동 대조 결과는 별도로 기록한다.
입력이나 의존성이 부족하여 실행하지 못했으면 그 사실과 필요한 준비를 알린다.
수동 대조를 하더라도 검사기 실행 통과로 기록하지 않는다.
기존 [검사 결과 구분](guidelines.md#검사-결과-구분)과 승인 절차를 유지한다.

통과만으로 사용자 승인, 단계 완료, 설계 타당성, 분할 필요성이나 도식 표시 확인을 판정하지 않는다.
검사기가 해당 판단을 강제하는 훅이나 상태 변경기를 추가하지 않는다.
