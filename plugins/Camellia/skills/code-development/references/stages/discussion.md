# 논의 단계 수행 지침

- 단계 식별자: `discussion`
- 상대 링크는 이 파일이 있는 디렉토리를 기준으로 한다.

## 공통 흐름과의 연결

시작과 재개는 [workflow.md](../workflow.md)의 흐름을 따른다. report 작성, 승인 및 회귀 절차는 [guidelines.md](../guidelines.md)의 해당 상세 지침을 따른다. 논의 단계에는 선행 단계 report가 없으며, 신규 회차에서 참고할 직전 회차 자료는 아래 [입력과 시작 시 확인](#입력과-시작-시-확인)에 따라 확인한다.

대화 내용의 기록, 단계 진입 시 인계 반영과 저장 후 대조는 guidelines의 [여러 단계의 내용이 섞인 대화의 기록과 인계](../guidelines.md#여러-단계의-내용이-섞인-대화의-기록과-인계)를 따른다.

## 단계 역할

사용자의 개발 요청을 설계가 이어받을 수 있는 목적, 대략적인 범위와 기대 방향으로 정리한다. 확인된 사실과 제약을 바탕으로 방향을 논의하고, 구체적인 구조와 동작 및 검증 기준은 설계 단계에서 정한다. 아직 확인하지 못한 가능성은 확정된 사실과 구분하여 남긴다. 세부 기준이 부족하다는 이유만으로 설계 진입을 막지 않는다.

확인된 사실이나 기술적 제약과 명백히 충돌하는 내용을 실현 가능한 합의로 확정하지 않으며, 불확실한 가능성은 미확인 전제와 설계에서 확인할 질문으로 남긴다.

## 입력과 시작 시 확인

- 기존 작업을 이어가는 경우 관련 report와 실제 변경 상태. 신규 회차 생성, manifest의 stages 기록 및 기존 회차의 단계 목록 확인은 [회차 생성과 manifest 갱신](../guidelines.md#회차-생성과-manifest-갱신)을 따른다. 신규/재개는 [작업 시작과 재개](../workflow.md#작업-시작과-재개)의 상태 확인 및 사용자 확인 절차를 따른다.
- 같은 회차에 discussion report가 있으면 번호가 가장 큰 파일을 확인한다. 최초 생성과 회귀 시 새 파일 작성은 공통 생성 규칙을 따르며, 읽기만으로 상태를 바꾸지 않는다.
- discussion report의 base_on은 null이다. 회귀 계기 자료는 report의 본문 공통 기록을 따른다. 신규 회차는 [직전 회차 참조와 이관](../guidelines.md#직전-회차-참조와-이관)에 따라 미처리 항목과 필요한 근거만 본문에 이관한다. 이미 완료한 항목과 완전히 제외하기로 한 항목은 새 회차로 이관하지 않는다.
- 사용자의 개발 요청과 현재 프로젝트 자료. 신규 개발이 아니면 아래 [선택적 분석 자료](#선택적-분석-자료)에 따라 기존 코드와 자료를 확인한다.

### 선택적 분석 자료

- 신규 개발이 아니면 기존 코드를 분석한 자료가 있는지 사용자에게 묻는다. 있으면 경로를 요청하여 실제 코드와 함께 참고하고, 없으면 자료 없이 기존 코드를 확인하며 진행한다.
- 분석 자료는 선택 입력이다. 별도 분석 스킬의 설치/실행이나 분석 자료의 존재를 진입/완료 조건으로 요구하지 않는다. 다른 스킬은 독립적으로 동작하며 필요한 자료만 선택적으로 활용한다.

## 사용자 역할

아래 수행 흐름과 report 템플릿의 항목을 바탕으로 사용자와 논의하고, 이번 작업에서 합의할 내용과 이후로 넘길 내용을 함께 정한다. 정리한 결과의 체크리스트 상호 확인과 사용자 승인은 guidelines의 공통 규칙을 따른다.

## 수행 흐름

1. 개발 요청과 대상, 사용 주체와 상황, 목적과 기대 방향을 사용자와 이야기하며 구체화한다. 현재 대화나 확인한 자료에서 명확하게 파악된 내용은 불필요하게 되묻지 않되, 불명확하거나 상충하는 내용은 확인한다. 이 대화를 별도 준비 단계로 분리하거나 추가 승인을 요구하지 않으며, 공통 규칙에 따른 재확인과 승인은 수행한다. 신규 개발에서는 기존 문제가 있었다고 가정하거나 만들어내지 않는다.
2. 포함 범위와 제외 범위, 기능 및 품질 요구사항을 정리한다. 제외 항목의 구분과 작성 방식은 report 템플릿을 따른다.
3. 관련 자료에서 확인한 사실과 근거, 지켜야 할 제약, 미확인 전제를 구분한다. 자료가 없는 경우와 아직 확인하지 않은 경우를 구분한다.
4. guidelines의 [미결정 사항과 제외 범위의 이관](../guidelines.md#미결정-사항과-제외-범위의-이관)에 따라 각 안건을 논의 단계에서 해결할 사항, 설계 등 같은 회차의 이후 단계에서 결정할 사항, 다음 회차로 보류할 사항, 완전히 제외할 사항으로 구분한다. 사용자와 합의한 처리 방향과 아직 합의하지 않은 제안을 구분하여 report에 기록하며, 별도 관리 파일은 만들지 않는다.
5. 대화 중 미리 나온 설계 내용은 guidelines의 [공통 기록과 인계 규칙](../guidelines.md#여러-단계의-내용이-섞인-대화의-기록과-인계)에 따라 인계한다.

## report 작성과 인계

- [report 템플릿](../../assets/stage_reports/discussion-template.md)을 사용하여 선택된 회차 디렉토리에 `discussion-report-<번호>.md` 형식으로 작성한다. 번호는 `001`부터 시작하는 세 자리 순번이며, 기존 report의 재사용 또는 새 파일 생성 여부와 새 번호 부여는 guidelines의 공통 규칙을 따른다. status/base_on 처리도 같은 규칙을 따른다.
- 템플릿의 단계 결과, 인계 사항, 완료 체크리스트와 사용자 승인 영역에 실제 결과를 기록한다. 템플릿 원본은 유지하고 실제 report의 제목과 자료 참조를 작업에 맞게 작성한다.
- 설계에서 참조할 요구사항과 제약, 관련 자료 및 결정할 질문을 인계한다.

## 완료 확인과 이관

[상호 확인과 체크리스트 갱신](../guidelines.md#상호-확인과-체크리스트-갱신)을 적용한다. 항목별 상호 확인 전에는 체크하지 않고, 확인 후 근거와 KST 기준 완료 시각을 기록한다.

report 템플릿의 체크 항목과 작업별 확인 근거를 사용자와 검토한다. 질문을 단순히 인계 영역에 적은 것만으로 설계 진입이 가능하다고 판단하지 않는다.
[완료 확인과 사용자 승인](../guidelines.md#완료-확인과-사용자-승인)에 따라 이관한다. 같은 discussion report의 변경은 [변경 후 체크리스트 재확인](../guidelines.md#변경-후-체크리스트-재확인) 규칙을 적용한다.
