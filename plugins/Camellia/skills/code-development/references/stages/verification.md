# 검증 단계 수행 지침

- 단계 식별자: `verification`
- 상대 링크는 이 파일이 있는 디렉토리를 기준으로 한다.

## 공통 흐름과의 연결

시작과 재개는 [workflow.md](../workflow.md)의 흐름을 따른다. 선행 report 확인, report 작성, 승인 및 회귀 절차는 [guidelines.md](../guidelines.md)의 해당 상세 지침을 따른다. 검증 대상으로 사용할 승인된 implementation report와 관련 자료는 아래 [입력과 시작 시 확인](#입력과-시작-시-확인)에 따라 확인한다.

대화 내용의 기록, 단계 진입 시 인계 반영과 저장 후 대조는 guidelines의 [여러 단계의 내용이 섞인 대화의 기록과 인계](../guidelines.md#여러-단계의-내용이-섞인-대화의-기록과-인계)를 따른다.

## 단계 역할

에이전트가 design report에 정한 검증용 항목과 판정 기준에 따라 구현 결과를 검사하고, 실제 검사 범위와 결과, 판정 근거 및 확인하지 못한 사항을 verification report에 기록한다.

## 입력과 시작 시 확인

- 필요한 선행 report가 없으면 이 단계 작업을 시작하거나 계속하지 않고 [중간 단계 시작의 기록 연결](../guidelines.md#중간-단계-시작의-기록-연결)에 따라 사용자와 회귀 또는 신규 플로우 진행을 결정한다.
- 기존 verification report가 있으면 같은 회차에서 가장 큰 번호를 확인한다. 파일 생성과 hold 재개는 공통 규칙을 따르며, 읽기만으로 상태를 바꾸지 않는다.
- 기준으로 사용할 implementation report를 확인한다. 후보가 여러 개면 현재 참조와 상태를 제시하고 사용자 확인을 받는다.
- 선택한 implementation report가 completed 상태인지 확인하고, 같은 디렉토리의 전체 파일명을 base_on에 기록한다.
- implementation report에 연결된 코드, 테스트와 실행 정보를 확인한다. 해당 report가 참조하는 design report에서 검증용 항목과 판정 기준을 확인하고, 실행 환경과 알려진 미검증 사항을 함께 확인한다.

검증에 필요한 환경은 설계 단계에서 준비된 상태를 전제로 한다. 이후 장애나 변경이 발생하면 guidelines의 [환경 준비와 이후 예외 대응](../guidelines.md#환경-준비와-이후-예외-대응)을 따르며, 검증 단계의 필수 조건을 충족했는지 실제 결과로 확인한다.

## 사용자 역할

검사의 내부 작업은 에이전트가 수행한다. 사용자는 제출된 검사 결과와 근거, 확인하지 못한 사항을 검토하고, 체크리스트 상호 확인과 단계 종료 승인에 참여한다. 교차 검증을 수행한 경우 지적 사항과 작성 에이전트의 검토 의견을 함께 살펴보고 처리 방향을 정하며, 수행하지 못한 경우에는 그 사유를 확인한다. 세부 절차는 guidelines의 공통 규칙을 따른다.

## 수행 흐름

1. guidelines의 [SDD 기준](../guidelines.md#sdd와-설계-및-구현의-경계)과 [테스트 수행 기준](../guidelines.md#테스트-실행과-재검증)에 따라 implementation report의 검증 대상 및 실행 준비 정보를 확인하고, 해당 report가 참조하는 design report의 검증용 항목과 판정 기준에 연결한다. 이미 정한 계획과 기준을 이 단계에서 중복 정의하지 않는다.
2. design report에서 검증용으로 정한 항목을 해당 판정 기준에 따라 실제로 실행하고, 항목별 결과와 판정 근거를 verification report에 기록한다. 통합 테스트와 E2E는 이번 작업에 적용하기로 한 검증용 항목에 포함된 경우 수행하며, 구현 단계의 사전 실행 결과로 이를 대신하지 않는다.

   최종 구현 상태에서 이번에 작성하거나 수정한 유닛 테스트와 변경 영향을 받는 기존 유닛 테스트를 재실행한다. 저장소 전체의 매번 실행은 강제하지 않는다. 실행하지 못한 대상은 그 이유와 확인하지 못한 범위를 기록한다. 수정 후 재검증은 guidelines의 [테스트 실행과 재검증](../guidelines.md#테스트-실행과-재검증) 기준을 따른다.

3. design report에서 통합 테스트를 제외하기로 한 경우, 해당 결정과 이유를 참조하고 그로 인해 확인하지 못하는 범위를 verification report에 기록한다. 수행하기로 했지만 실행할 수 없는 검사는 제외한 검사와 구분하여, 실행을 막는 제약과 확인하지 못한 범위를 기록한다.
4. 통과, 실패, 미실행 및 판정 불가를 구분한다. 각 결과의 의미는 guidelines의 [검사 결과 구분](../guidelines.md#검사-결과-구분)을 따른다. 확인한 범위 밖까지 문제없다고 일반화하지 않는다.
5. design report의 QA용 계획과 연결하여 검증 결과 전체와 QA 진행에 미치는 영향을 인계한다. 검증에서 판정을 확정하지 못한 항목을 QA에서 추가로 확인하려면, 그 이유와 범위, 확인 방법 및 진행 조건을 사용자와 합의한다. 원래 미검증 기록을 보존하고, 실제로 실패한 항목을 미검증으로 바꾸어 인계하지 않는다.

설계의 [검증과 QA의 대상 구분](design.md#검증과-qa의-대상-구분)과 design report에 따라 검증한다. 자동 검사의 통과가 사용자 QA를 대체하지 않는다.

## report 작성과 인계

- [report 템플릿](../../assets/stage_reports/verification-template.md)을 사용하여 선택된 회차 디렉토리에 `verification-report-<번호>.md` 형식으로 작성한다. 번호는 `001`부터 시작하는 세 자리 순번이며, 기존 report의 재사용 또는 새 파일 생성 여부와 새 번호 부여는 guidelines의 공통 규칙을 따른다. status/base_on 처리도 같은 규칙을 따른다.
- 템플릿의 단계 결과, 인계 사항, 완료 체크리스트와 사용자 승인 영역에 실제 결과를 기록한다. 템플릿 원본은 유지하고 실제 report의 제목과 자료 참조를 작업에 맞게 작성한다.
- 검사 결과와 근거, 실패 및 확인하지 못한 범위, 사용자 확인이 필요한 내용과 QA 진행에 미치는 영향을 QA 단계에 인계한다.

## 완료 확인과 이관

아래 [교차 검증](#교차-검증)과 [완료 구분](#완료-구분)을 확인하여 결과와 한계를 제출한다.

guidelines의 [상호 확인과 체크리스트 갱신](../guidelines.md#상호-확인과-체크리스트-갱신)을 적용한다. 항목별 상호 확인 전에는 체크하지 않고, 확인 후 근거와 KST 기준 완료 시각을 기록한다.

선택한 완료 구분의 조건과 체크리스트를 충족하고 사용자 승인을 받은 뒤 status를 `completed`로 변경한다.

guidelines의 [완료 확인과 사용자 승인](../guidelines.md#완료-확인과-사용자-승인)에 따라 이관한다. 같은 verification report의 변경은 [변경 후 체크리스트 재확인](../guidelines.md#변경-후-체크리스트-재확인) 규칙을 적용하며, hold 상태의 verification report를 재개하는 경우에도 일반 승인 흐름을 거친다.

### 교차 검증

검사 결과와 근거를 준비한 뒤 최종 사용자 승인 전에 코드 중심 교차 검증을 진행한다. 구현 코드와 테스트 코드, 설계와의 일치 여부, 테스트 기준과 실제 실행 결과 및 누락된 검증을 중심으로 검토한다. 요청, 수행 불가와 지적 처리는 guidelines의 [공통 절차](../guidelines.md#교차-검증의-연결-위치)를 따른다. 사용자는 지적 사항의 처리 결과 또는 교차 검증을 수행하지 못한 사유까지 확인하고 승인한다.

### 완료 구분

- `all_passed`: 모든 검증용 대상이 판정 기준을 충족한 경우다.
- `qa_handoff`: 나머지 항목이 통과했고, 확정하지 못한 항목의 이유와 범위 및 QA 확인 방법과 진행 조건을 사용자와 합의한 경우다. 실제 실패를 미검증으로 바꿔 이관하지 않는다.

verification report의 사용자 승인 영역에 키워드와 설명을 기록한다. 기록 형식과 단계 종료/전체 통과의 구분은 guidelines의 [완료 구분 공통 기준](../guidelines.md#검증-및-qa의-완료-구분)을 따른다.
