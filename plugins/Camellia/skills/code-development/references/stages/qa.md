# QA 단계 수행 지침

- 단계 식별자: `qa`
- 상대 링크는 이 파일이 있는 디렉토리를 기준으로 한다.

## 공통 흐름과의 연결

시작과 재개는 [workflow.md](../workflow.md)의 흐름을 따른다. 선행 verification report 확인, qa report 작성, 승인 및 회귀 절차는 [guidelines.md](../guidelines.md)의 해당 상세 지침을 따른다. QA의 입력으로 사용할 승인된 verification report와 관련 자료는 아래 [입력과 시작 시 확인](#입력과-시작-시-확인)에 따라 확인한다.

대화 내용의 기록, 단계 진입 시 인계 반영과 저장 후 대조는 guidelines의 [여러 단계의 내용이 섞인 대화의 기록과 인계](../guidelines.md#여러-단계의-내용이-섞인-대화의-기록과-인계)를 따른다.

## 단계 역할

design report에서 정한 QA용 항목과 판정 기준을 바탕으로 사용자와 에이전트가 함께 확인한다. verification report의 결과와 합의한 추가 확인 사항을 참고하여 진행하고, 실제 결과와 사용자 판단, 근거 및 확인하지 못한 사항을 qa report에 기록한다.

## 입력과 시작 시 확인

- 현재 qa report와 선행 verification report의 선택 및 base_on은
  [참조 기준](../guidelines.md#프론트매터와-참조-확인)을 따른다.
  [선행 report 확인](../guidelines.md#다음-단계-진입-시-선행-report-확인)을 마친 뒤 시작한다.
- verification report의 검사 결과와 근거, 완료 구분과 미해결 사항, 합의한 QA 추가 확인 항목을 확인한다. 연결된 design report의 QA용 항목과 판정 기준, 대상 코드와 시나리오, 환경 및 테스트 데이터를 함께 확인한다.

QA에 필요한 환경은 설계 단계에서 준비된 상태를 전제로 한다. 이후 장애나 변경이 발생하면 guidelines의 [환경 준비와 이후 예외 대응](../guidelines.md#환경-준비와-이후-예외-대응)을 따르며, QA 단계의 필수 조건을 충족했는지 실제 결과로 확인한다.

## 사용자 역할

사용자는 QA 항목에 필요한 조작과 결과 판단에 참여한다. 에이전트는 확인 절차와 기대 결과를 안내하고, 실행 보조와 기록을 통해 실수와 누락을 줄인다. 정리한 결과의 체크리스트 상호 확인과 단계 종료 승인은 guidelines의 공통 규칙을 따른다.

## 수행 흐름

1. design report의 QA용 항목, 확인 절차와 판정 기준 및 verification report의 결과 전체를 확인한다. qa_handoff로 합의한 추가 확인 항목이 있으면 함께 포함하고, 각 항목을 수행할 환경과 테스트 데이터, 필요한 사용자 조작을 준비한다. 수행할 검사는 이번 작업에서 합의한 범위를 따르며, 모든 프로젝트에 동일한 검사를 강제하지 않는다.
2. 각 QA 항목의 확인 절차, 기대 결과와 판정 기준을 사용자에게 안내한다. 사용자가 수행할 조작과 판단, 에이전트가 보조할 작업을 구분하고, 합의한 절차에 따라 함께 진행한다.
3. 각 QA 항목의 실제 결과와 사용자 판단, 그 근거를 qa report에 기록한다. 자동 검사 결과나 에이전트의 판단만으로 사용자가 확인하거나 승인했다고 기록하지 않는다. 결과 구분은 guidelines의 [검사 결과 구분](../guidelines.md#검사-결과-구분)을 따른다.
4. 발견한 문제는 재현 조건과 영향을 qa report에 기록한다. 미실행 또는 판정 불가인 항목은 그 이유와 확인하지 못한 범위를 구분하여 기록하며, 실제로 실패한 항목을 미실행이나 판정 불가로 바꾸지 않는다.
5. QA에서 확인한 범위와 결론, 관련 코드와 테스트의 참조, 남은 사항을 qa report에 정리하여 사용자에게 제출한다. 커밋, 푸시, 배포는 사용자가 별도로 요청하지 않으면 제안하거나 실행하지 않는다.

설계의 [검증과 QA의 대상 구분](design.md#검증과-qa의-대상-구분)과 design report에 따라 확인한다. 수정이 필요하여 이전 단계로 회귀하면 guidelines의 [테스트 실행과 재검증](../guidelines.md#테스트-실행과-재검증) 기준을 따른다.

### 별도 QA 테스트 항목이 없는 경우

별도 QA 테스트 항목이 없으면 verification report와 근거를 사용자와 함께 검토한다. 통합/E2E가 없어도 TDD 유닛 테스트 결과는 확인 대상이다. 확인 범위, 실패/미확인 사항과 제약을 함께 검토하고 qa report에 결과를 남긴다. 테스트 재실행은 필수가 아니며, 항목별 상호 확인과 단계 종료 승인은 동일하게 적용한다. 실행 불가나 판정 불가를 QA 항목 없음으로 바꾸지 않는다.

## report 작성과 인계

- [report 템플릿](../../assets/stage_reports/qa-template.md)으로 `qa-report-<번호>.md`를 작성한다.
  저장 위치와 생성/번호/상태 처리는 [공통 report 규칙](../guidelines.md#report-작성과-인계)을 따른다.
- 템플릿의 단계 결과, 인계 사항, 완료 체크리스트와 사용자 승인 영역에 실제 결과를 기록한다. 템플릿 원본은 유지하고 실제 qa report의 제목과 자료 참조를 작업에 맞게 작성한다.

### 최종 완료와 인계의 기록

- 사용자와 수행한 테스트 결과, 판단 근거와 남은 사항을 qa report에 기록하고 이번 작업의 결과를 사용자에게 제출한다. 아래 [완료 구분](#완료-구분)에 따라 새 작업 주제 이관을 선택하면 미처리 내용과 이관 근거도 남긴다.
- 신규 작업 주제로 넘기기로 합의한 미처리 항목은 guidelines의 [이관 규칙](../guidelines.md#이전-작업-참조와-이관)을 따른다. manifest 변경이 필요하면 갱신하되 작업 항목이나 상태를 중복 기록하지 않는다. 다음 작업의 reference_reports는 신규 작업 주제 진행을 사용자와 확정할 때 기록하며 아직 시작하지 않은 report를 미리 생성하지 않는다.
- QA 완료를 커밋/푸시/배포 승인으로 해석하지 않는다. 요청 여부에 따른 처리는 [SKILL.md의 권한 경계](../../SKILL.md#항상-지킬-경계)를 따른다.

## 완료 확인과 이관

아래 [교차 검증](#교차-검증) 조건을 확인하고 [완료 구분](#완료-구분)에 따라 결과와 남은 사항을 제출한다.
선택한 완료 구분의 조건도 충족해야 단계 승인을 받을 수 있다.

템플릿의 체크 항목과 근거는 [상호 확인](../guidelines.md#상호-확인과-체크리스트-갱신)하고,
[공통 승인 절차](../guidelines.md#완료-확인과-사용자-승인)에 따라 단계 종료와 인계를 처리한다.
같은 report의 보완은 [체크리스트 재확인](../guidelines.md#변경-후-체크리스트-재확인),
hold 상태의 재개는 [재개 절차](../guidelines.md#hold-상태인-후속-단계-재개)를 따른다.

### 교차 검증

QA에서 발견한 문제와 관련 코드, 수정 내용 또는 기존 검증 결과에 미치는 영향에 추가 검토가 필요하거나 사용자가 요청하면, guidelines의 [공통 절차](../guidelines.md#교차-검증의-연결-위치)에 따라 교차 검증을 진행한다. 모든 QA 승인 전에 일괄 수행하도록 요구하지 않는다. 코드 수정이 필요하면 회귀 절차를 따르며 QA의 사용자 주관적 판단을 검토자가 대신 승인하지 않는다.

### 완료 구분

- `all_passed`: 모든 QA 대상이 판정 기준을 충족한 경우다.
- `next_cycle_handoff`: 남은 실패/미확인 항목과 이유, 영향 및 다음 확인 조건을 사용자와 합의하여 새 작업 주제로 넘긴 경우다. 현재 작업에서 해결하기로 했다면 필요한 단계로 회귀한다.

`next_cycle_handoff`는 기존 report 형식을 유지하기 위한 키워드이며 새 작업 주제로의 이관을 뜻한다. 별도 round 디렉토리 생성을 요구하지 않는다.
실제 작업의 시작 시점과 todo 기록은 guidelines의 [보류와 이관 기준](../guidelines.md#미결정-사항과-제외-범위의-이관)을 따른다.

qa report의 사용자 승인 영역에 키워드와 설명을 기록한다. 기록 형식과 단계 종료/전체 통과의 구분은 guidelines의 [완료 구분 공통 기준](../guidelines.md#검증-및-qa의-완료-구분)을 따른다.
