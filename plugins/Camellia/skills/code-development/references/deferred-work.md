# 보류 항목의 기록과 정리

현재 플로우 밖으로 미룰 일을 합의할 때와 전체 완료를 준비할 때 읽는다.
보류 기록은 향후 작업의 입력이며 착수 시점이나 다음 플로우의 순서를 확정하지 않는다.

## 분류와 완료 기준

| 구분 | 판단과 처리 |
| --- | --- |
| 인계 | 같은 플로우의 후속 단계나 번들에서 처리할 내용. 현재 report의 인계 사항에 기록 |
| 보류 | 현재 플로우에 포함하지 않고 나중에 수행하거나 재검토하기로 합의한 작업. deferred에 기록 |
| 일시 중단 | 현재 범위를 유지하며 중단. 현재 report에 결과/남은 일/재개 조건을 보존 |
| 완전 제외 | 수행하지 않기로 한 결정. 현재 report에 이유를 보존하며 보류 항목을 만들지 않음 |

새로 나온 범위 밖 안건과 현재 범위에서 사용자 합의로 뺀 작업을 모두 보류로 다룬다.
기존 범위의 작업을 보류하려면 변경할 범위와 완료 기준을 사용자와 합의하고,
필요한 [회귀와 승인](guidelines.md#보완-복귀와-재검증)을 거친다.
보류 사유나 사용자 승인만으로 변경하지 않은 필수 완료 조건을 면제하지 않는다.

"다음으로"가 다른 안건, 후속 단계/번들 또는 플로우 밖 작업 중 무엇인지 불명확하면 먼저 확인한다.
명확한 기존 합의는 재확인하지 않는다.
현재 단계의 필수 미결정 사항은 해결해야 하며 단순 아이디어나 미확정 제안은 자동 보류하지 않는다.
일시 중단 자체로 status를 바꾸지 않으며 `hold`는 회귀의 후속 report에만 사용한다.

## 항목 기록

작업 루트의 `deferred/<작업을 식별할 이름>.md`에 항목별로 기록한다.
번들이 있어도 보류 항목은 같은 작업 루트에 모은다.
첫 보류 항목을 기록할 때 디렉토리를 만들고 빈 디렉토리나 예정 파일은 만들지 않는다.
별도 공용 todo 작성은 요구하지 않는다.

[보류 항목 템플릿](../assets/deferred-item-template.md)을 사용하여 필요한 작업,
보류 이유와 현재 범위, 논의 내용과 근거, 재검토 조건과 미결정 사항을 정리한다.
출처 프로젝트/작업/번들을 식별하고 기록만으로 향후 논의를 시작할 수 있게 작성한다.
모르는 조건은 미정으로 남기며 다음 플로우에서 바로 수행할 수 있다고 가정하지 않는다.

현재 report에는 범위에서 뺀 내용, 이유와 현재 채택한 방식을 남긴다.
향후 작업의 상세는 보류 파일을 정본으로 삼고 같은 내용을 양쪽에 복제하지 않는다.
필요한 근거 링크는 실제 위치를 사용하며 아직 없는 목적지 링크를 만들지 않는다.

## 전체 완료 전 이동

1. 단일 플로우 또는 모든 번들의 최종 QA에서 작업 루트의 `deferred/`와 실제 파일을 확인한다.
   읽을 수 없으면 확인 실패로 알리며 항목이 없는 것으로 처리하지 않는다.
2. 파일이 있으면 항목과 목적지를 사용자와 논의하고 지정받은 위치로 이동한다.
   목적지를 고정하거나 프로젝트/전역 todo 경로로 추정하지 않는다.
   항목별 목적지가 다르면 그 합의를 따른다.
3. 목적지 부재, 권한 부족, 동명 충돌이나 이동 실패가 있으면 원본을 유지하고 이유를 알린다.
   사용자와 후속 처리를 합의할 때까지 이동과 전체 완료를 대기한다.
   목적지 생성이나 기존 파일 대체는 합의한 범위에서만 수행한다.
4. 이동한 파일의 내용과 출처를 대조하고 이동으로 영향을 받은 상대 참조를 갱신하여 확인한다.
   복사로 이동했다면 대조를 마친 항목의 원본만 정리한다.
5. 미이동 파일이 없고 `deferred/`가 실제로 비었는지 확인한 뒤 빈 디렉토리를 삭제한다.
   최종 QA에 이동 위치/확인 결과와 디렉토리 정리 결과를 기록한다.

전체 완료의 조건은 항목을 지정 위치에 보존하고 `deferred/`까지 정리하는 것이다.
디렉토리 삭제를 위해 항목을 버리거나 미이동 항목을 누락하지 않는다.
보류가 없으면 불필요한 목적지 질문 없이 완료 절차를 진행하고, 빈 디렉토리만 남았다면 비었는지 확인 후 정리한다.
