# Code Development 진행 흐름

code-development로 소프트웨어를 개발할 때의 단계 순서와 지침 연결을 안내한다.

## 역할과 참조 기준

SKILL.md는 적용 조건과 핵심 제약, 이 문서는 진행 흐름, guidelines.md는 상세 규칙을 담당한다.
상대 링크는 이 파일이 있는 references/ 디렉토리를 기준으로 한다.

1. 자료 사용과 수행 주체의 [공통 기준](guidelines.md#공통-적용과-자료-사용-기준)을 확인한다.
2. 현재 단계 지침과 그 작업에서 연결하는 상세 절을 읽는다.
3. report는 각 단계의 결과, 다음 단계에 전달할 사항, 완료 체크리스트와 사용자 승인을 함께 기록하는 문서다. 작성할 때는 해당 단계 지침에서 연결한 템플릿을 사용한다.

## 단계 순서와 지침

아래는 기본 흐름이며 실제 회차의 적용 순서는 `freight-manifest.md`의 해당 회차 `stages`를 따른다.

| 순서 | 단계 식별자 | 단계 지침 | 담당 결과 |
| --- | --- | --- | --- |
| 1 | discussion | [논의](stages/discussion.md) | 목적, 범위, 요구사항과 제약 정리 |
| 2 | design | [설계](stages/design.md) | 구현 구조, 동작과 테스트 계획 정리 |
| 3 | implementation | [TDD 기반 작성 및 리팩터링](stages/implementation.md) | 코드와 테스트 작성, 수행 근거 기록 |
| 4 | verification | [검증](stages/verification.md) | 에이전트가 검사한 결과와 확인 범위 제출 |
| 5 | qa | [QA](stages/qa.md) | 사용자 참여 테스트 결과와 판단 기록 |

## 작업 시작과 재개

1. [등록 지침](guidelines.md#스킬-호출-시-등록-정보-확인)에 따라 등록 파일 확인과 필요한 생성을 먼저 수행한 뒤, 주제와 저장 루트를 확인한다. 같은 세션의 선택 유지와 스킬 재호출 시 확인도 이 지침을 따른다.
2. [시작과 재개의 확인 절차](guidelines.md#작업-시작과-재개의-확인-절차)에 따라 요청, 회차와 report를 대조하고 사용자와 신규/재개 및 시작 단계를 확인한다.
3. 필요한 선행 report가 없으면 [중간 단계 시작의 기록 연결](guidelines.md#중간-단계-시작의-기록-연결)에 따라 해당 단계 진입을 차단하고 진행 방향을 확인한다.
4. 신규 회차는 [회차 생성과 manifest 갱신](guidelines.md#회차-생성과-manifest-갱신) 및 [직전 회차 이관](guidelines.md#직전-회차-참조와-이관)을 따른다. 재개는 기존 기록을 사용하며, hold 상태이면 [hold 재개 절차](guidelines.md#hold-상태인-후속-단계-재개)를 먼저 따른다.
5. 확인한 회차와 단계로 [현재 단계 수행](#현재-단계-수행)을 이어간다.

## 현재 단계 수행

1. 현재 단계 지침의 입력 자료를 확인하고 필요한 [선행 report 확인](guidelines.md#다음-단계-진입-시-선행-report-확인)을 마친다. [대화 기록과 인계 기준](guidelines.md#여러-단계의-내용이-섞인-대화의-기록과-인계)에 따라 현재 단계에 해당하는 인계 내용과 배치 미확정 사항을 확인하여 반영한다.
2. 단계 지침에 따라 작업한다. 명세와 구현에는 [SDD 기준](guidelines.md#sdd와-설계-및-구현의-경계), 환경 준비와 문제 대응에는 [설계 환경 준비](stages/design.md#환경-준비)와 [공통 환경 대응](guidelines.md#환경-준비와-이후-예외-대응), 테스트 실행과 변경 후 확인에는 [실행 및 재검증 기준](guidelines.md#테스트-실행과-재검증)을 적용한다.
3. 단계 템플릿과 [report 작성과 인계](guidelines.md#report-작성과-인계)에 따라 report를 생성하거나 유지하고 결과와 인계 사항을 기록한다. 저장 후 대화 내용과 실제 기록을 대조한다.
4. [교차 검증 조건](guidelines.md#교차-검증의-연결-위치)에 해당하면 해당 절차를 거쳐 [완료 확인과 사용자 승인](guidelines.md#완료-확인과-사용자-승인)을 진행한다. 교차 검증 대상이 아닌 경우에도 완료 확인과 사용자 승인을 진행한다.
5. 승인 후 해당 회차의 `stages`에 따른 다음 단계에서 이 절차를 반복한다. 마지막 QA까지 마쳤으면 [최종 완료와 인계](#최종-완료와-인계)로 연결한다.

수행 중 보완이나 회귀가 필요하면 [보완, 복귀와 재검증](guidelines.md#보완-복귀와-재검증)을 따른다.
필수 규칙과 충돌하는 요청은 [공통 규칙 위반 대응](guidelines.md#공통-규칙-위반-대응)으로 연결한다.

## 최종 완료와 인계

마지막 QA의 [완료 구분](stages/qa.md#완료-구분)과 사용자 승인을 확인하고, [최종 인계 기록](stages/qa.md#최종-완료와-인계의-기록)에 따라 결과와 남은 사항을 제출한다.
새 회차 진행을 사용자와 확정하면 [작업 시작과 재개](#작업-시작과-재개)로 연결한다.
