# Code Development 진행 흐름

code-development로 소프트웨어를 개발할 때의 단계 순서와 지침 연결을 안내한다.

| 단계 목록과 담당 결과 확인 | [단계 순서와 지침](#단계-순서와-지침) |

## 역할과 참조 기준

SKILL.md는 적용 조건과 핵심 제약, 이 문서는 진행 흐름, guidelines.md는 상세 규칙을 담당한다.
상대 링크는 이 파일이 있는 references/ 디렉토리를 기준으로 한다.

1. 자료 사용과 수행 주체의 [공통 기준](guidelines.md#공통-적용과-자료-사용-기준)을 확인한다.

2. 현재 단계 지침과 그 작업에서 연결하는 상세 절을 읽는다.

3. report는 각 단계의 결과, 다음 단계에 전달할 사항, 완료 체크리스트와 사용자 승인을 함께 기록하는 문서다.
   작성할 때는 해당 단계 지침에서 연결한 템플릿을 사용한다.

## 단계 순서와 지침

아래는 기본 흐름이며 실제 작업의 적용 순서는 대주제의 `freight-manifest.md`에 있는 해당 작업 항목의 `stages`를 따른다.
같은 주제의 순차 묶음은 [작업 묶음 지침](work-bundles.md)에 따라 공통 뼈대 이후 각 묶음의 설계 또는 구현부터 QA까지 수행한다.

| 순서 | 단계 식별자 | 단계 지침 | 담당 결과 |
| --- | --- | --- | --- |
| 1 | discussion | [논의](stages/discussion.md) | 목적, 범위, 요구사항과 제약 정리 |
| 2 | design | [설계](stages/design.md) | 구현 구조, 동작과 테스트 계획 정리 |
| 3 | implementation | [TDD 기반 작성 및 리팩터링](stages/implementation.md) | 코드와 테스트 작성, 수행 근거 기록 |
| 4 | verification | [검증](stages/verification.md) | 에이전트가 검사한 결과와 확인 범위 제출 |
| 5 | qa | [QA](stages/qa.md) | 사용자 참여 테스트 결과와 판단 기록 |

## 작업 시작과 재개

1. [주제 확인 지침](guidelines.md#스킬-호출-시-프로젝트와-주제-확인)에 따라 프로젝트 루트와 specs 아래의 대주제/작업 주제를 확인한다.
   같은 세션의 선택 유지와 스킬 재호출 시 확인도 이 지침을 따른다.

2. [시작과 재개의 확인 절차](guidelines.md#작업-시작과-재개의-확인-절차)에 따라 요청, 작업 주제와 report를 대조하고 사용자와 신규/재개 및 시작 단계를 확인한다.

3. [모델 제안과 승인](ai_agents/model-selection.md)에 따라 현재 작업 묶음의 모델/강도/범위 승인과 실제 적용을 확인한다.

4. 필요한 선행 report가 없으면 [중간 단계 시작의 기록 연결](guidelines.md#중간-단계-시작의-기록-연결)에 따라 해당 단계 진입을 차단하고 진행 방향을 확인한다.

5. 신규 작업 주제는 [작업 주제 생성과 manifest 갱신](guidelines.md#작업-주제-생성과-manifest-갱신) 및 [이전 작업 참조](guidelines.md#이전-작업-참조)을 따른다.
   첫 report와 manifest 항목은 첫 저장 시점에 만든다.
   기존 번호 형식은 [기존 기록 지침](legacy-records.md)에 따라 재개하며 자동 변환하지 않는다.
   재개는 기존 기록을 사용하며, hold 상태이면 [hold 재개 절차](guidelines.md#hold-상태인-후속-단계-재개)를 먼저 따른다.

6. 확인한 작업 주제와 단계로 [현재 단계 수행](#현재-단계-수행)을 이어간다.

## 현재 단계 수행

1. 현재 단계 지침의 입력 자료를 확인하고 필요한 [선행 report 확인](guidelines.md#다음-단계-진입-시-선행-report-확인)을 마친다.
   [대화 기록과 인계 기준](guidelines.md#여러-단계의-내용이-섞인-대화의-기록과-인계)에 따라 현재 단계에 해당하는 인계 내용과 배치 미확정 사항을 확인하여 반영한다.

2. 단계 지침에 따라 작업한다.
   논의와 설계의 범위가 바뀌는 지점에서는 아래 [전환 안내](#논의와-설계-범위의-전환-안내)를 적용한다.
   설계는 [in_review 점검](stages/design.md#설계-점검과-승인-전이)을 마친 후 승인 요청으로 넘어간다.

   - 명세와 구현에는 [SDD 기준](guidelines.md#sdd와-설계-및-구현의-경계)을 적용한다.
   - 환경 준비와 문제 대응에는 [설계 환경 준비](stages/design.md#환경-준비)와 [공통 환경 대응](guidelines.md#환경-준비와-이후-예외-대응)을 적용한다.
   - 테스트 실행과 변경 후 확인에는 [실행 및 재검증 기준](guidelines.md#테스트-실행과-재검증)을 적용한다.

3. [저장 시점](guidelines.md#report-저장-시점)에 단계 템플릿과 [report 작성과 인계](guidelines.md#report-작성과-인계)에 따라 누적 결과와 인계 사항을 반영한다.
   저장 후 대화 내용과 실제 기록을 대조한다.
   최종 검토/승인 전과 기존 report를 입력으로 사용할 때는 [정형 검사 안내](report-checks.md)에 따라 검사하며,
   역할별 실행 기준으로 필요한 검사와 유효한 기존 결과를 선택한다.
   검사 결과와 실제 승인/내용 판단을 구분한다.

4. [교차 검증 조건](guidelines.md#교차-검증의-연결-위치)에 해당하면 해당 절차를 거쳐 [완료 확인과 사용자 승인](guidelines.md#완료-확인과-사용자-승인)을 진행한다.
   교차 검증 대상이 아닌 경우에도 완료 확인과 사용자 승인을 진행한다.

5. 승인 후 작업 방식에 따라 다음 단계로 연결한다.

   - 단일 플로우는 해당 작업의 `stages`에 따른 다음 단계에서 이 절차를 반복한다.
   - 순차 묶음은 공통 design 승인 후 첫 묶음의 진입을 확인하고 해당 묶음의 시작 단계로 연결한다.
     묶음 안에서는 단계 순서를 따르며 QA 승인 후 [다음 묶음 진입](work-bundles.md#묶음-진입과-회귀)을 확인한다.
     모든 묶음과 마지막 전체 QA까지 마쳤으면 [최종 완료와 인계](#최종-완료와-인계)로 연결한다.

수행 중 보완이나 회귀가 필요하면 [보완, 복귀와 재검증](guidelines.md#보완-복귀와-재검증)을 따른다.
필수 규칙과 충돌하는 요청은 [공통 규칙 위반 대응](guidelines.md#공통-규칙-위반-대응)으로 연결한다.

## 논의와 설계 범위의 전환 안내

대화 주제와 공식 단계를 구분한다.
논의에서는 목적과 큰 범위를 정하고, 설계에서는 공통 뼈대와 현재 범위의 구체적인 동작/검증을 정한다.
번들 후보와 질문의 깊이는 [작업 묶음 지침](work-bundles.md)을 따른다.
대화에 설계 아이디어가 나와도 기존 기록/승인 없이 단계나 설계 확정 상태를 바꾸지 않는다.

| 전환을 확인할 시점 | 안내와 처리 |
| --- | --- |
| 논의의 목적/큰 범위가 정리되어 구조나 동작의 결정으로 넘어가려 할 때 | 합의한 목적/범위와 설계에서 정할 내용을 짧게 요약한다. 기존 논의 완료/사용자 승인과 설계 진입 절차를 따른다. |
| 공통 뼈대에서 특정 번들의 상세로 들어가려 할 때 | 확정된 뼈대, 지금 다룰 번들과 후속으로 남길 범위를 알린다. 공통 설계 승인과 해당 번들의 기존 진입 조건을 확인한다. |
| 후속 번들의 세부 질문이 나오려 할 때 | [질문 기준](work-bundles.md#질문의-깊이와-현재-범위)으로 지금 필요한지 판단한다. 후속 안건이면 처리할 위치를 남기고 현재 범위의 논의를 이어간다. |

안내는 논의의 깊이나 수행 범위가 바뀌는 지점에만 하며 매 응답마다 단계명을 붙이지 않는다.
새 단계나 별도 승인 절차를 추가하지 않고 기존 확인/승인과 함께 안내한다.
상세 아이디어를 먼저 이야기할 수 있으며, 기록은 [대화 기록과 인계](guidelines.md#여러-단계의-내용이-섞인-대화의-기록과-인계)에 따라
현재 합의와 미확정 제안을 구분하여 남긴다.

## 최종 완료와 인계

순차 묶음이면 [전체 완료 기준](work-bundles.md#전체-완료)을 먼저 대조한다.
[보류 항목 이동과 정리](deferred-work.md#전체-완료-전-이동)를 마친 뒤 마지막 QA의 [완료 구분](stages/qa.md#완료-구분)과 사용자 승인을 확인하고, [최종 인계 기록](stages/qa.md#최종-완료와-인계의-기록)에 따라 결과와 남은 사항을 제출한다.
새 작업 주제 진행을 사용자와 확정하면 [작업 시작과 재개](#작업-시작과-재개)로 연결한다.
