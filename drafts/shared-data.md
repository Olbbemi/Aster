# 공유 작업 데이터 구조 초안

이 문서는 Aster 저장소 밖에서 Codex와 Claude가 함께 사용하는 작업 데이터 구조에
관해 현재까지 합의한 내용을 기록한다. 최종 명세의 파일 배치와 분할 방식은 아직
확정하지 않았다.

## 목적

공유 작업 데이터의 위치와 역할을 구분하고, 같은 사실이 여러 곳에 중복되지 않게
관리한다. Aster 저장소의 코드와 문서 산출물 자체는 이 디렉토리에 복사하지 않는다.

## 논리 구조

```text
~/.local/share/aster/
|-- INDEX.md
|-- pending/
|-- work/
|   |-- codex/
|   `-- claude/
`-- verifications/
```

`decisions/`는 두지 않는다. 확정된 내용은 성격에 따라 저장소의 `AGENTS.md`,
`standards/`, 완료된 작업 기록 또는 검증 이력에 둔다.

## 정본 구분

### 저장소 `AGENTS.md`

Aster 세션에서 항상 적용해야 하는 운영 규칙의 정본이다.

- 공유 디렉토리를 읽거나 기록해야 하는 조건
- 작업 시작, 완료 및 보류 시 수행할 행동
- 교차 검증을 수행해야 하는 조건
- 에이전트별 수정 권한

공유 데이터 파일의 상세 형식을 반복해서 정의하지 않는다.

### 공유 데이터 명세

공유 데이터의 구조와 생명주기를 정의하는 정본이다. 최종 파일 위치는 아직 정하지
않았다.

- 각 기록의 필수 항목
- 생성, 상태 변경 및 제거 조건
- 작성 및 수정 권한
- 허용 상태와 상태 전이
- 기계 검사 가능한 조건

### `INDEX.md`

공유 데이터의 배치와 탐색 방법만 설명하는 색인이다.

포함하는 내용:

- 각 디렉토리의 용도
- 데이터를 저장할 위치를 판단하는 기준
- 각 디렉토리의 진입점
- 정본 명세의 위치

포함하지 않는 내용:

- 작업 이력과 완료 작업 목록
- 개별 파일 목록
- 검증 결과와 진행 상황의 요약
- Aster 운영 규칙과 상세 파일 형식

## `pending/`

아직 착수하지 않았거나 진행 중 보류된 항목을 저장한다. 후보 하나당 마크다운 파일
하나를 사용한다.

```markdown
# 항목 제목

## 발견한 내용

해야 할 일이나 남아 있는 문제를 기록한다.

## 보류 이유

현재 처리하지 않거나 작업을 중단한 이유를 기록한다.

## 관련 작업

기존 작업에서 넘어왔다면 해당 작업 기록을 가리킨다. 처음 발견한 후보라면 이 절은
생략한다.
```

관리 원칙:

- Codex와 Claude 모두 읽고 쓸 수 있다.
- 현재 진행 중인 작업의 수행 이력은 저장하지 않는다.
- 작업을 시작하거나 재개하면 해당 pending 파일을 제거한다.
- 이미 수행한 내용의 정본은 `work/`에 둔다.
- 보류된 작업의 남은 내용은 `pending/`에만 적고 `work/`에는 링크만 둔다.
- 일련번호나 날짜 접두어 같은 파일명 형식은 강제하지 않는다.

같은 파일의 동시 수정을 기계적으로 차단하는 방식은 아직 정하지 않았다.

## `work/`

실제로 착수한 작업의 수행 기록을 저장한다.

```text
work/
|-- codex/
|   `-- <작업>.md
`-- claude/
    `-- <작업>.md
```

관리 원칙:

- 작업 하나당 마크다운 파일 하나를 사용한다.
- Codex는 `work/codex/`만 수정한다.
- Claude는 `work/claude/`만 수정한다.
- 상대 에이전트의 작업 기록은 자유롭게 읽을 수 있다.
- 실제 산출물은 Aster 저장소에 두고 작업 기록에 복사하지 않는다.
- 상태별 하위 디렉토리는 만들지 않는다.
- 파일명 형식은 강제하지 않는다.

작업 상태의 유일한 정본은 파일 프론트매터의 `status` 필드다.

```yaml
---
status: active
---
```

허용 상태:

```text
active      현재 진행 중
paused      일시 보류
completed   완료
cancelled   영구 중단
```

현재 합의한 상태 전이:

```text
active -> paused
paused -> active
active -> completed
active -> cancelled
paused -> cancelled
```

작업 파일의 나머지 필수 항목은 아직 확정하지 않았다.

## `verifications/`

Codex가 만든 산출물을 Claude가 검증하거나 Claude가 만든 산출물을 Codex가 검증한
독립 교차 검증 이력만 저장한다. 자체 검토, 일반 기계 검사 및 작업 과정은 저장하지
않는다.

```text
verifications/
`-- <검증 대상>/
    `-- <회차>/
        |-- request.md
        |-- review.md
        `-- resolution.md
```

### `request.md`

검증을 요청한 쪽이 작성한다.

- 작성자
- 검증 대상과 대상 상태
- 검증 항목과 판정 기준
- 검증 범위와 제외 범위

### `review.md`

상대 검증자가 독립적으로 작성한다.

- 작성자
- 전체 판정과 항목별 결과
- 발견한 문제와 확인 가능한 근거
- 확인하지 못한 사항

### `resolution.md`

검증 지적의 수용, 반박 또는 재검증 판단이 필요할 때만 작성한다.

- 작성자
- 지적별 처리 결과
- 수용 또는 반박 근거
- 후속 조치와 재검증 필요 여부

관리 원칙:

- `request.md`와 `review.md`는 필수다.
- `resolution.md`는 후속 판단이 있을 때만 만든다.
- 한 회차에는 최대 세 파일이 생긴다.
- 각 파일은 실제 작성자만 수정한다.
- 요청자와 검증자 이름은 파일명이나 디렉토리가 아니라 파일 내용에 기록한다.
- 검증자를 기준으로 디렉토리를 나누지 않고 검증 대상을 기준으로 모은다.
- 이전 회차의 독립 검증 원문은 수정하지 않는다.

## SSOT 원칙

- 운영 행동의 정본은 저장소 `AGENTS.md`다.
- 상세 데이터 규격의 정본은 공유 데이터 명세다.
- `INDEX.md`는 정본의 위치만 가리킨다.
- 작업 상태의 정본은 작업 파일의 `status` 필드다.
- 보류된 남은 작업의 정본은 `pending/`이다.
- 수행 이력의 정본은 작성 에이전트의 `work/` 파일이다.
- 검증 요청, 독립 판정 및 후속 처리는 서로 다른 파일을 정본으로 삼는다.
- 다른 문서에는 내용을 복제하지 않고 정본을 참조한다.

## SDD 원칙

실제 공유 데이터를 만들기 전에 다음을 명세한다.

```text
용어와 상태
-> 기록 구조
-> 작성 및 수정 권한
-> 상태 전이
-> 기계 검사 항목
-> 실제 기록
```

검사 코드는 명세를 구현하며 검사 코드 자체를 규칙의 정본으로 삼지 않는다.

## 미결 사항

- 공유 데이터 명세를 한 파일로 둘지 주제별로 나눌지
- 공유 데이터 명세의 최종 저장소 경로
- 작업 파일의 필수 본문 항목
- pending 파일의 동시 수정 잠금 방식
- 검증 회차 디렉토리의 이름을 선택하는 방식
