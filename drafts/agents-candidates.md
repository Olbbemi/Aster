# Aster AGENTS.md 추가 후보

이 문서는 Aster의 `AGENTS.md`에 추가할 수 있으나 아직 공통 수칙으로 확정하지 않은
후보를 보관한다. 현재 `AGENTS.md`의 규칙을 보충하거나 대체하지 않는다.

## 정본과 참조

- 운영 행동, 개발 규격 및 작업 기록의 정본을 구분한다.
- 같은 규칙이나 상태를 여러 파일에 복제하지 않는다.
- 다른 문서에서는 정본을 링크하거나 경로로 참조한다.

## 설계 우선

- 규격과 구조를 합의하기 전에 실제 구성 요소를 만들지 않는다.
- 한 번에 전체 구조를 확정하지 않고 주제별로 논의하고 검증한다.
- 합의되지 않은 내용을 확정된 규칙처럼 사용하지 않는다.

## 초안 관리

- 확정되지 않은 설계는 `drafts/`에 둔다.
- 초안은 규칙의 정본으로 간주하지 않는다.
- 설계가 확정되면 정본 위치로 옮기고 중복된 초안을 정리한다.

## 개발 규격과 검사

- 개발 규격은 `standards/`에 둔다.
- 기계 검사는 `checks/`에 두고 `standards/`를 구현하도록 한다.
- 검사 코드 자체를 규칙의 정본으로 삼지 않는다.
- 기계 검사와 사람의 판단이 필요한 검증을 구분한다.

## 공유 작업 데이터

- 착수 전 후보와 보류 항목은 `pending/`의 규칙을 따른다.
- 착수한 작업은 작성 주체별 `work/`에 기록한다.
- 작업 상태는 작업 파일의 `status`를 정본으로 삼는다.
- 세부 기록 형식과 상태 전이는 공유 데이터 명세를 따른다.

## 작성 권한

- Codex는 Codex 작업 기록만 수정한다.
- Claude는 Claude 작업 기록만 수정한다.
- 상대 에이전트의 작업 기록은 읽을 수 있지만 수정하지 않는다.
- 공동 영역의 수정 권한은 해당 명세를 따른다.

## 플러그인 경계

- 개별 플러그인의 배포 경계는 `plugins/<plugin-name>/`이다.
- 개발용 문서와 검사는 플러그인 배포 영역에 넣지 않는다.
- 플러그인은 설치, 갱신, 인증, 장애 또는 배포 주기가 다를 때 분리한다.
- 구성 요소 종류만으로 플러그인을 분리하지 않는다.

## 공용 실행 자료

- 한 플러그인의 여러 스킬이 사용하는 자료는 해당 플러그인의 `shared/`에 둔다.
- 특정 스킬만 사용하는 자료는 해당 스킬 디렉토리에 둔다.
- 공용 내용은 복제하지 않고 각 `SKILL.md`에서 명시적으로 참조한다.

## 기존 Armarium 취급

- Armarium은 조사와 비교를 위한 참고 자료로만 사용한다.
- Armarium의 구조, 규격, 검사 또는 파일을 그대로 복사하지 않는다.
- 참고한 판단도 Aster의 요구와 현재 하네스에서 다시 검증한다.

## 시험용 구성 요소

- 저장소 뼈대와 검사 방식은 폐기 가능한 시험용 구성 요소로 먼저 검증한다.
- 시험이 끝나기 전에 실제 운영용 구성 요소로 간주하지 않는다.
- 시험 결과를 근거로 구조와 검사 방식을 확정한 뒤 실제 구성 요소를 만든다.

## 불필요한 구조 생성 금지

- 실제 필요가 확인된 파일과 디렉토리만 만든다.
- 빈 디렉토리와 자리 표시용 파일은 만들지 않는다.
