# 시나리오 기록 대조 형식

lifecycle의 동작/호환성 검증에서 요건, 사례와 현재 결과를 기계적으로 대조하는 형식이다.

시나리오 선정, 사용자 확정, 실행, 재시험과 완료 판단은
[시나리오 준비와 검증 절차](../../.agents/skills/skill-lifecycle/references/scenario-validation.md)를 따른다.

신규 작성하거나 현재 작업 범위에서 보완하는 기록에 적용한다.
다른 작업의 기존 기록을 일괄 변환하지 않는다.

## 정본과 표 식별

- 요건, 계획과 결과는 명세서 또는 연결된 Markdown 문서에 아래 표로 관리한다.
  - 표를 별도 검사 파일이나 JSON/YAML로 복제하지 않는다.
- 상세 입력, 환경과 판단 근거는 기존 기록을 연결하며 같은 내용을 반복하지 않는다.

- 각 표 바로 앞의 독립된 HTML 주석으로 표의 역할을 식별한다.
  - 주석과 표 사이에는 빈 줄만 허용하며, 표와 주석은 목록이나 인용문 밖에 둔다.
- 코드 예시와 인용문 안의 표는 실제 기록으로 세지 않는다.
- 검사할 파일은 명시적으로 전달하며 링크를 따라 검사 범위를 확장하지 않는다.

한 번의 검사는 하나의 시나리오 묶음이다.

- 요건과 계획 표는 각각 하나씩 필요하며 결과 검사에는 결과 표도 하나 필요하다.
  - 여러 파일에 나눌 수 있지만 같은 역할의 표를 중복하지 않는다.
- 필요한 표에는 한 개 이상의 행을 기록한다.
  - 검증 대상이 없으면 단계 규칙에 따라 적용 제외 근거를 남기며 빈 시험 표를 만들지 않는다.

## 열과 값

아래는 복사하여 실제 값으로 작성할 최소 형식이다.

```markdown
<!-- lifecycle-check:requirements -->
| 요건 ID | 필수 여부 | 범위 | 사유 |
| --- | --- | --- | --- |
| R1 | 필수 | 대상 | |

<!-- lifecycle-check:scenarios -->
| 사례 ID | 대응 요건 | 필수 여부 | 범위 | 기대 결과 | 사유 |
| --- | --- | --- | --- | --- | --- |
| S1 | R1 | 필수 | 대상 | 입력 조건에 맞는 결과를 반환한다. | |

<!-- lifecycle-check:results -->
| 사례 ID | 상태 | 근거/사유 |
| --- | --- | --- |
| S1 | 미실행 | 실행 전이다. |
```

- 열은 이름으로 식별하며 순서 변경과 추가 설명 열을 허용한다.
  - 열 이름의 누락/중복과 행의 열 수 불일치는 실패다.

- ID는 영문자/숫자로 시작하며 이후 영문자/숫자, `.`, `_`, `-`를 사용한다.
  - 대소문자를 구분하며 표 안에서 중복하지 않는다.
- 대응 요건은 요건 ID를 쉼표로 구분하며 한 셀 안에서도 중복하지 않는다.

- `필수 여부`는 `필수`, `선택`, `범위`는 `대상`, `제외`, `보류`를 사용한다.
  - 제외/보류에는 사유를 기록하며 범위 변경의 실제 사용자 합의는 별도로 확인한다.

- 모든 사례에 대응 요건과 기대 결과 또는 상세 링크를 기록한다.
- 대응 요건은 요건 표에 있어야 하며, 범위가 `대상`인 모든 요건은 `대상` 사례에 연결되어야 한다.

- 결과 상태는 `통과`, `실패`, `미실행`, `미판정`으로 구분하고 근거나 사유를 기록한다.
- 계획의 모든 사례에 결과를 한 행씩 남기며 제외/보류 사례도 기존 실행 상태를 유지한다.
  - 계획에 없는 사례의 결과는 실패다.

- 재시험 후에는 결과 표의 현재 판정을 갱신한다.
  - 이전 실패의 필요한 관찰/근거는 상세 기록에 유지하고 결과 표에 같은 ID를 누적하지 않는다.
- CLI/조건별로 독립 판정이 필요하면 계획에서 사례 ID를 구분한다.

## 검사 시점과 판정

| 모드 | 확인 범위 |
| --- | --- |
| `plan` | 요건/계획 표의 형식, ID와 요건 대응. 결과 표는 검사하지 않음 |
| `results` | 계획 검사와 함께 결과 표의 형식, 사례 대응과 누락 확인 |

실행 전 확정할 계획에 `plan`을, 실행 후 현재 결과를 대조할 때 `results`를 사용한다.

미정인 초안을 최종 계획 검사 통과로 간주하지 않는다.

기록 대조의 `PASS`는 표의 형식과 대응이 맞다는 뜻이다.

- 실제 사례의 상태별 수와 현재 범위의 필수 사례 중 미통과 목록을 별도로 출력한다.
- 사례의 실패/미실행/미판정이 기록되어 있어도 누락 없는 기록 자체는 `PASS`일 수 있다.
- 계획 검사에서는 실행 결과를 검사하지 않았다고 표시한다.

본문의 충분성, 요건/사례 선정의 타당성, 근거의 진위, 실제 승인과 단계 완료는 자동 판정하지 않는다.

링크 존재는 참조 검사로 확인하며, 파일 읽기/파싱 실패를 기록 대조 통과로 처리하지 않는다.
