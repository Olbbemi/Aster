# Aster 저장소 배치 규격

## 목적과 적용 범위

이 문서는 Aster 저장소의 개발 영역과 플러그인 배포 영역에 유지할 파일과 디렉토리의 역할, 배치 및 생성 조건을 정의한다.
경로는 별도 설명이 없으면 Aster 저장소 루트를 기준으로 한다.

작업 과정의 행동 규칙은 저장소 루트의 `AGENTS.md`와 그 문서에서 연결하는 상세 규칙을 따른다.
설계 초안, 작업용 명세서와 시험 결과 등 공유 작업 데이터의 배치와 관리 규칙은
[Aster 작업 규칙의 공유 작업 데이터 접근](../AGENTS.md#공유-작업-데이터-접근)에 따라 확인한다.

## 배치 기준과 안내

파일은 확장자나 실행 주체보다 사용 목적을 기준으로 배치한다.

- 공용 실행 파일, 사용 안내와 테스트는 `tools/`에 모은다.
- 호출하는 스킬이나 하네스, GitHub Actions 여부로 복제하거나 배치를 나누지 않는다.
- 개발 규격과 저장소 배치 기준은 `standards/`, Git과 GitHub 운영 규칙은 `.github/`에서 관리한다.
- 각 영역의 안내는 해당 규칙의 정본을 참조한다.

루트 `README.md`를 저장소의 종합 안내로 사용한다.
저장소의 목적, 최상위 디렉토리의 역할과 작업 목적별 문서 링크를 제공하며,
상세 규칙과 절차는 복제하지 않고 정본으로 연결한다.
세부 문서는 해당 안내 문서에서 연결한다.

- 디렉토리가 있다는 이유로 하위 `README.md`를 만들지 않는다.
- 링크나 기존 문서의 요약만 제공하는 안내는 루트 `README.md`에 통합한다.
- 하위 `README.md`는 별도 배포물의 진입 안내처럼
  루트 안내로 충족할 수 없는 독립적인 용도가 있을 때만 둔다.

- 새 내용은 기존 정본에 먼저 배치하고, 사용 목적과 읽어야 하는 상황이 분명히 다를 때만 별도 문서로 분리한다.
- 문서 이름은 해당 문서의 실제 목적을 드러내도록 정한다.
- 배치 기준의 정본은 이 문서이며, README에서 별도의 규칙으로 중복 정의하지 않는다.

## 작업 규칙 진입점

### `AGENTS.md`

Codex와 Claude가 함께 사용하는 Aster 작업 규칙의 정본이다.
저장소 루트에 둔다.

### `CLAUDE.md`

Claude가 공통 작업 규칙을 읽는 진입점이다.
저장소 루트에서 `AGENTS.md`를 가리키는 상대 심볼릭 링크로 관리한다.
작업 규칙은 `AGENTS.md` 또는 그 문서에서 연결하는 해당 정본에서 갱신한다.

두 파일은 개별 플러그인의 배포 경계 밖에 두며 플러그인 배포물에 포함하지 않는다.

## 개발 규격

### `standards/`

Aster의 구성 요소를 개발하고 검토할 때 적용하는 확정된 개발 규격을 둔다.
작업 명세서, 검토 초안, 시험 결과와 실제 실행 파일은 두지 않는다.

첫 번째 확정 규격을 저장할 때 `standards/`를 생성한다.
구성 요소별 하위 디렉토리는 해당 구성 요소에 적용할 규격 파일이 실제로 생길 때만 생성한다.

- `standards/skills/`에는 스킬 개발 규격을 둔다.

저장소 전체의 배치를 정의하는 이 문서는 `standards/repository-layout.md`에 둔다.

## GitHub 운영 파일

### `.github/`

Git과 GitHub의 운영 규칙, PR 양식과 Actions 워크플로를 둔다.
실제 사용할 운영 파일을 추가할 때 생성한다.

- Git 운영 규칙의 정본은 `.github/git-workflow.md`에 두고, `AGENTS.md`에서 적용 조건과 참조를 안내한다.
- PR 본문의 공용 템플릿은 `.github/pull_request_template.md`에 둔다.
- GitHub Actions 워크플로는 `.github/workflows/`에 둔다.
- 워크플로가 호출하는 스크립트, Git 훅과 해당 테스트는 아래 공용 실행 도구 배치를 따른다.

루트 `README.md`에서 Git 운영 규칙, PR 양식과 main 변경 전파 안내를 연결한다.
main 변경 전파의 실행 안내는 `tools/references/main-propagation.md`에 둔다.

작성 언어와 적용 절차는 [Git 운영 규칙](../.github/git-workflow.md)을 따르며, 실제 PR 초안은 이 디렉토리에 저장하지 않는다.

개별 플러그인의 배포 경계 밖에 두며 플러그인 배포물에 포함하지 않는다.

## 저장소 공용 실행 도구

### `tools/`

검사기, Git 자동화와 시나리오 실행기 등 Aster 저장소에서 사용하는 공용 실행 도구를 둔다.
내부 스킬, 에이전트와 GitHub Actions가 같은 도구를 사용할 수 있다.

배포 플러그인이 실행에 필요한 파일을 이 영역에 의존하도록 구성하지 않는다.

검사 기준은 `standards/`와 Git 운영 규칙을 정본으로 유지하고, 스크립트는 그 기준을 구현한다.

| 경로 | 역할 |
| --- | --- |
| `tools/scripts/validation/` | 스킬 구조, 참조, 배포 구성과 플러그인 버전 검사 |
| `tools/scripts/git/` | 브랜치 자동 전파와 Git 훅 진입점 |
| `tools/scripts/scenario/` | 승인된 시나리오 실행 |
| `tools/tests/<기능>/` | `scripts/`의 `validation`, `git`, `scenario`에 대응하는 테스트 |
| `tools/references/` | 용도별 파일로 관리하는 도구 사용 안내 |
| `tools/guidelines.md` | 내부 스킬의 공용 검사 실행 지침 |
| `tools/mappings.md` | 내부 스킬별로 사용할 검사기와 개별 안내의 연결 |
| `tools/requirements.txt` | 공용 도구의 외부 Python 의존성 |

- 기능별 디렉토리 아래에는 파일을 직접 두고 다시 `scripts/`, `tests/`, `references/`를 만들지 않는다.
- 호출 주체나 개별 스킬 이름으로 디렉토리를 세분화하지 않는다.
- 필요한 파일이 생길 때만 디렉토리를 만든다.

`mappings.md`에는 해당 내부 스킬이 사용하는 검사기만 등록한다.
같은 영역에 있다는 이유로 시나리오 실행기나 Git 자동화까지 스킬의 검사 대상으로 포함하지 않는다.

개별 안내에는 목적, 적용 범위, 입력과 실행 방법, 출력 해석, 실패 처리와 한계를 적고
규칙의 정본을 참조한다.
루트 `README.md`에서 필요한 안내로 연결한다.
시나리오 공통 실행기의 사용 계약은 `tools/references/scenario-runner.md`에 둔다.

일회성 하네스, 실제 시험 입력/결과와 작업 기록은 이 영역에 두지 않는다.
이러한 자료는 [공유 작업 데이터 접근](../AGENTS.md#공유-작업-데이터-접근)에 따라 확인한 규격에 맞게 저장한다.

개별 플러그인의 배포 경계 밖에 두며 플러그인 배포물에 포함하지 않는다.

### `.codex/rules/`

신뢰된 Aster 프로젝트에서 사용할 Codex 실행 허용 규칙을 둔다.
공통 실행기의 지정 명령만 허용하고, 사용자 전역 실행 규칙과 구분한다.

## 스킬 배치

스킬의 사용 형태를 먼저 결정하고, 사용 형태에 따라 다음 경로에 둔다.

- 내부용 스킬은 `.agents/skills/<skill-name>/`에 둔다.
- 플러그인 배포용 스킬은 `plugins/<plugin-name>/skills/<skill-name>/`에 둔다.

## 플러그인 경계

- 개별 플러그인의 배포 경계는 `plugins/<plugin-name>/`이다.
- 플러그인은 설치, 갱신, 인증, 장애 또는 배포 주기가 다를 때 분리한다.
- 구성 요소 종류만으로 플러그인을 분리하지 않는다.

## 스킬 자료 배치

이 절은 스킬을 사용하는 데 필요한 자료의 배치를 정의한다.
해당 스킬 자체를 개발하고 검증하는 데만 사용하는 규격과 검사 코드는 앞의 "개발 규격"과 "저장소 공용 실행 도구"를 따르고,
작업용 명세서와 시험 결과 등 공유 작업 데이터는 "목적과 적용 범위"에서 안내한 규격을 따른다.

### 스킬 전용 자료

특정 스킬만 사용하는 자료는 해당 스킬 디렉토리에 둔다.
스킬 디렉토리 내부의 파일과 하위 디렉토리 역할, 배치 및 생성 조건은 [스킬 내부 배치 규격](skills/skill-layout.md)을 따른다.

### 내부 스킬 공용 자료

- 여러 내부용 스킬이 사용하는 자료는 `.agents/shared/`에 둔다.
- 내부 스킬 공용 내용은 복제하지 않고 각 `SKILL.md`에서 명시적으로 참조한다.
- 플러그인 배포용 스킬은 `.agents/shared/`의 자료를 참조하지 않는다.

### 플러그인 내부 공용 자료

- 같은 플러그인의 여러 스킬이 사용하는 자료는 `plugins/<plugin-name>/shared/`에 둔다.
- 플러그인 내부 공용 내용은 복제하지 않고 각 `SKILL.md`에서 명시적으로 참조한다.

내부 스킬 공용 자료 또는 플러그인 내부 공용 자료를 변경할 때는 해당 자료를 참조하는 스킬을 확인한다.
변경이 각 스킬의 사용 방식과 참조 경로에 미치는 영향을 확인하고, 필요한 수정과 검증을 함께 수행한다.
