# Aster 저장소 배치 규격

## 목적과 적용 범위

이 문서는 Aster 저장소의 개발 영역과 플러그인 배포 영역에 유지할 파일과 디렉토리의 역할, 배치 및 생성 조건을 정의한다.
경로는 별도 설명이 없으면 Aster 저장소 루트를 기준으로 한다.

작업 과정의 행동 규칙은 저장소 루트의 `AGENTS.md`와 그 문서에서 연결하는 상세 규칙을 따른다.
명세서, 설계 및 검증 문서와 로컬 시험 자료의 배치 및 관리 규칙은
[Aster 작업 규칙의 공유 작업 데이터 접근](../AGENTS.md#공유-작업-데이터-접근)에 따라 확인한다.

## 배치 기준과 안내

파일은 확장자나 실행 주체보다 사용 목적을 기준으로 배치한다.

- 공용 실행 파일, 사용 안내와 테스트는 `tools/`에 모은다.
- 호출하는 스킬이나 하네스, GitHub Actions 여부로 복제하거나 배치를 나누지 않는다.
- 개발 규격과 저장소 배치 기준은 `standards/`, Git과 GitHub 운영 규칙은 `.github/`에서 관리한다.
- 각 영역의 안내는 해당 규칙의 정본을 참조한다.

루트 `README.md`를 저장소의 종합 안내로 사용한다.
저장소의 목적, 최상위 디렉토리의 역할과 작업 목적별 문서 링크를 제공하며,
상세 규칙과 절차는 복제하지 않고 정본으로 연결한다.
세부 문서는 해당 안내 문서에서 연결한다.

- 디렉토리가 있다는 이유로 하위 `README.md`를 만들지 않는다.
- 링크나 기존 문서의 요약만 제공하는 안내는 루트 `README.md`에 통합한다.
- 하위 `README.md`는 별도 배포물의 진입 안내처럼
  루트 안내로 충족할 수 없는 독립적인 용도가 있을 때만 둔다.

- 새 내용은 기존 정본에 먼저 배치하고, 사용 목적과 읽어야 하는 상황이 분명히 다를 때만 별도 문서로 분리한다.
- 문서 이름은 해당 문서의 실제 목적을 드러내도록 정한다.
- 배치 기준의 정본은 이 문서이며, README에서 별도의 규칙으로 중복 정의하지 않는다.

## 작업 규칙 진입점

### `AGENTS.md`

Codex와 Claude가 함께 사용하는 Aster 작업 규칙의 정본이다.
저장소 루트에 둔다.

### `CLAUDE.md`

Claude가 공통 작업 규칙을 읽는 진입점이다.
저장소 루트에서 `AGENTS.md`를 가리키는 상대 심볼릭 링크로 관리한다.
작업 규칙은 `AGENTS.md` 또는 그 문서에서 연결하는 해당 정본에서 갱신한다.

두 파일은 개별 플러그인의 배포 경계 밖에 두며 플러그인 배포물에 포함하지 않는다.

## 개발 규격

### `standards/`

Aster의 구성 요소를 개발하고 검토할 때 적용하는 확정된 개발 규격을 둔다.
작업 명세서, 검토 초안, 시험 결과와 실제 실행 파일은 두지 않는다.

첫 번째 확정 규격을 저장할 때 `standards/`를 생성한다.
구성 요소별 하위 디렉토리는 해당 구성 요소에 적용할 규격 파일이 실제로 생길 때만 생성한다.

- `standards/skills/`에는 스킬 개발 규격을 둔다.

저장소 전체의 배치를 정의하는 이 문서는 `standards/repository-layout.md`에 둔다.

## 공용 기록 양식과 실제 데이터

### `assets/work-records/`

일반 Aster 작업과 여러 내부 스킬이 선택해서 사용하는 기록 템플릿을 둔다.
필요한 정보와 생성 조건은 [작업 데이터 규격](work-data.md)을 따른다.
특정 스킬의 전용 템플릿은 이 영역으로 옮기지 않고 해당 스킬 안에 유지한다.

실제 기록이나 시험 결과를 템플릿 원본에 저장하지 않는다.
플러그인 배포물에 포함하거나 독립 실행 의존성으로 사용하지 않는다.

### `data/`

대표 작업 트리의 실제 로컬 기록을 보관하며 `/data/`를 Git 추적에서 제외한다.
공용 경로, 하위 구조와 초기 준비 조건은 [작업 데이터 규격](work-data.md)을 따른다.
규격과 템플릿은 Git 관리 영역에 유지하고 이 경로에 복제하지 않는다.
추가 worktree에는 별도 데이터를 준비하지 않는다.

### `records/`

명세서와 설계, 판단 및 검증 근거 등 Git에 보존할 작업 기록을 둔다.
`skill-lifecycle`의 새 기록은 경로를 확정한 뒤 초안부터 이 영역에서 작성하고 완료 시 같은 위치에서 정리한다.
다른 작업의 기록 생성 시점과 형식은 해당 작업의 규격을 따른다.
원시 로그, 시험용 복제본과 일회성 시험 자료는 로컬 작업 데이터에 둔다.
이 영역의 파일이 존재한다는 사실은 작업 완료나 실제 커밋을 뜻하지 않으며 Git 반영은 기존 운영 규칙을 따른다.

첫 기록을 작성하거나 기존 기록을 이관할 때 필요한 디렉토리만 생성한다.
자료의 적용 조건과 공용 보존 원칙은 [작업 데이터 규격](work-data.md#완료-기록의-git-보존)을,
스킬 전용 하위 경로와 선별 절차는 해당 스킬의 규격을 따른다.

일반 저장소 작업에서 완료 기록을 남기기로 한 경우에는 `records/repository/<작업명>/`을 사용한다.
배포 플러그인에 포함하지 않으며 스킬의 실행 의존성으로 사용하지 않는다.

## GitHub 운영 파일

### `.github/`

Git과 GitHub의 운영 규칙, PR 양식과 Actions 워크플로를 둔다.
실제 사용할 운영 파일을 추가할 때 생성한다.

- Git 운영 규칙의 정본은 `.github/git-workflow.md`에 두고, `AGENTS.md`에서 적용 조건과 참조를 안내한다.
- PR 본문의 공용 템플릿은 `.github/pull_request_template.md`에 둔다.
- GitHub Actions 워크플로는 `.github/workflows/`에 둔다.
- 워크플로가 호출하는 스크립트, Git 훅과 해당 테스트는 아래 공용 실행 도구 배치를 따른다.

루트 `README.md`에서 Git 운영 규칙, PR 양식과 main 변경 전파 안내를 연결한다.
main 변경 전파의 실행 안내는 `tools/references/main-propagation.md`에 둔다.

작성 언어와 적용 절차는 [Git 운영 규칙](../.github/git-workflow.md)을 따르며, 실제 PR 초안은 이 디렉토리에 저장하지 않는다.

개별 플러그인의 배포 경계 밖에 두며 플러그인 배포물에 포함하지 않는다.

## 저장소 공용 실행 도구

### `tools/`

Git 자동화 등 Aster 저장소의 운영 도구와 개발용 테스트를 둔다.
내부 스킬, 에이전트와 GitHub Actions가 같은 도구를 사용할 수 있다.

배포 플러그인이 실행에 필요한 파일을 이 영역에 의존하도록 구성하지 않는다.

검사 기준은 `standards/`와 Git 운영 규칙을 정본으로 유지하고, 스크립트는 그 기준을 구현한다.
Git 운영 도구의 공통 배치는 전역 공통 지침의 "Git 훅 진입점과 운영 스크립트의 배치를 통일한다" 절을 따른다.
아래 표는 Aster에서 사용하는 도구와 실제 배치를 안내한다.

| 경로 | 역할 |
| --- | --- |
| `tools/scripts/git/` | `post-checkout`, `pre-push` 훅 진입점 |
| `tools/scripts/git/operations/` | 공유 작업 데이터 준비, 플러그인 버전 검사와 브랜치 자동 전파 구현 |
| `tools/tests/git/` | Git 운영 도구의 개발용 테스트 |
| `tools/tests/skills/<스킬명>/` | 해당 스킬의 개발용 테스트 |
| `tools/references/` | 용도별 파일로 관리하는 도구 사용 안내와 개발용 테스트 안내 |
| `tools/requirements.txt` | 저장소 도구와 개발용 테스트의 외부 Python 의존성 |

- Git 운영 구현은 위 `operations/` 배치를 따른다.
- Git 운영 테스트는 `tools/tests/git/` 바로 아래에 파일을 둔다.
- 스킬 개발용 테스트는 내부용과 플러그인 배포용을 구분하지 않고 `tools/tests/skills/<스킬명>/`에 모은다.
  플러그인 이름으로 중간 디렉토리를 나누지 않는다.
- 스킬명 디렉토리 바로 아래에 테스트 파일을 두며, 그 아래에 추가 디렉토리를 만들지 않는다.
- 테스트 스크립트의 파일명은 검증 대상 기능을 명확하게 나타내도록 정한다.
- 필요한 파일이 생길 때만 디렉토리를 만든다.

스킬 실행에 필요한 스크립트와 안내는 [스킬 구조 규격](skills/skill-layout.md)에 따라 해당 스킬 안에 둔다.
skill-lifecycle의 검사기와 시나리오 실행기도 이 배치를 따르며,
skill-lifecycle 자체의 개발용 검사는 `tools/tests/skills/skill-lifecycle/`에 둔다.

개별 안내에는 목적, 적용 범위, 입력과 실행 방법, 출력 해석, 실패 처리와 한계를 적고
규칙의 정본을 참조한다.
루트 `README.md`에서 필요한 안내로 연결한다.

일회성 하네스, 실제 시험 입력/결과와 작업 기록은 이 영역에 두지 않는다.
이러한 자료는 [공유 작업 데이터 접근](../AGENTS.md#공유-작업-데이터-접근)에 따라 확인한 규격에 맞게 저장한다.

개별 플러그인의 배포 경계 밖에 두며 플러그인 배포물에 포함하지 않는다.

### `.codex/rules/`

신뢰된 Aster 프로젝트에서 사용할 Codex 실행 허용 규칙을 둔다.
공통 실행기의 지정 명령만 허용하고, 사용자 전역 실행 규칙과 구분한다.

## 스킬 배치

스킬의 사용 형태를 논의할 때 저장 경로를 함께 확정하고, 사용 형태에 따라 다음 경로에 둔다.

- 내부용 스킬은 `.agents/skills/<skill-name>/`에 둔다.
- 플러그인 배포용 스킬은 `plugins/<plugin-name>/skills/<skill-name>/`에 둔다.

실제 스킬 파일은 초안부터 확정한 소스 경로에 작성하고 같은 파일을 갱신한다.
설계 문서와 명세서 및 검증 기록은 소스와 구분하여 해당 작업의 기록 규격에 따른 위치에 둔다.
이름이나 경로가 미정이면 먼저 확정하며, 경로 확정만으로 빈 디렉토리나 자리 표시용 파일을 만들지 않는다.

## 플러그인 경계

- 개별 플러그인의 배포 경계는 `plugins/<plugin-name>/`이다.
- 플러그인은 설치, 갱신, 인증, 장애 또는 배포 주기가 다를 때 분리한다.
- 구성 요소 종류만으로 플러그인을 분리하지 않는다.

### 플러그인별 배포 소스

하나의 `aster` marketplace에서 플러그인별 배포 참조를 분리한다.
두 catalog인 `.agents/plugins/marketplace.json`과 `.claude-plugin/marketplace.json`은
각 플러그인의 `source`를 `git-subdir`로 정의한다.
`url`은 Aster 저장소, `path`는 해당 플러그인 경계,
`ref`는 등록 식별자에 대응하는 `integrate/<관리 대상>` 브랜치다.
두 catalog에서 같은 플러그인의 URL, 경로와 참조는 일치해야 한다.

marketplace 목록을 읽는 참조와 개별 플러그인 코드를 읽는 참조는 별개다.
목록 checkout의 상대 경로로 배포 소스를 대신하지 않는다.
한 플러그인의 배포를 위해 다른 플러그인의 통합 브랜치를 병합하거나 배포 참조를 바꾸지 않는다.

목록 변경은 공용 Git 흐름에서 검토하고, 플러그인 코드는 각 관리 대상의 흐름을 따른다.
일반적인 main 변경 전파는 [Git 운영 규칙](../.github/git-workflow.md)에 따라 별도로 유지한다.

배포 검증에서는 명세에서 정한 기대 소스와 파일 목록을 실제 catalog 및 지정한 원격 branch 커밋과 대조한다.
원격 확인을 생략하거나 필요한 Git 객체/접근 권한이 없으면 해당 검사는 미완료다.

Git 자료의 일치와 CLI 설치/업데이트 성공을 구분한다.
실제 개별 업데이트 검증에는 대상 외 플러그인의 소스, 버전, 활성화 및 설치 파일 보존을 포함한다.

설치 및 갱신은 [플러그인 배포 안내](../tools/references/plugin-distribution.md)를 따른다.

## 스킬 자료 배치

이 절은 스킬을 사용하는 데 필요한 자료의 배치를 정의한다.
해당 스킬 자체를 개발하고 검증하는 데만 사용하는 규격과 검사 코드는 앞의 "개발 규격"과 "저장소 공용 실행 도구"를 따르고,
작업용 명세서와 시험 결과 등 공유 작업 데이터는 "목적과 적용 범위"에서 안내한 규격을 따른다.

### 스킬 전용 자료

특정 스킬만 사용하는 자료는 해당 스킬 디렉토리에 둔다.
스킬 디렉토리 내부의 파일과 하위 디렉토리 역할, 배치 및 생성 조건은 [스킬 내부 배치 규격](skills/skill-layout.md)을 따른다.

### 내부 스킬 공용 자료

- 여러 내부용 스킬이 사용하는 자료는 `.agents/shared/`에 둔다.
- 내부 스킬 공용 내용은 복제하지 않고 각 `SKILL.md`에서 명시적으로 참조한다.
- 플러그인 배포용 스킬은 `.agents/shared/`의 자료를 참조하지 않는다.

### 플러그인 내부 공용 자료

- 같은 플러그인의 여러 스킬이 사용하는 자료는 `plugins/<plugin-name>/shared/`에 둔다.
- 플러그인 내부 공용 내용은 복제하지 않고 각 `SKILL.md`에서 명시적으로 참조한다.

내부 스킬 공용 자료 또는 플러그인 내부 공용 자료를 변경할 때는 해당 자료를 참조하는 스킬을 확인한다.
변경이 각 스킬의 사용 방식과 참조 경로에 미치는 영향을 확인하고, 필요한 수정과 검증을 함께 수행한다.

### 내부 스킬과 플러그인이 함께 참조하는 자료

`shared/`에는 내부 스킬과 설치된 플러그인에서 공통으로 참고하는 자료를 둔다.
첫 자료는 [공용 모델 선택 기준](../shared/model-selection.md)이며,
개발 규격, 실행 도구와 작업 기록은 각 기존 영역에 둔다.
루트 README는 용도와 정본 링크만 안내한다.

- 내부 스킬은 저장소의 정본을 상대 경로로 참조한다.
- 설치된 플러그인은 Aster GitHub 저장소의 `main`에 있는 해당 문서 URL을 직접 참조한다.
  모델 선택 기준의 주소는 `https://github.com/Olbbemi/Aster/blob/main/shared/model-selection.md`다.
- 호출 스킬에 읽을 시점과 접근하지 못했을 때의 대응을 명시한다.
  모델표를 읽지 못하면 그 사실을 알리고 사용자에게 모델을 지정받을 수 있다.
- 개별 스킬이나 플러그인에 같은 표를 복제해 독립적으로 관리하지 않는다.

이 영역은 개별 플러그인의 배포 경계 밖에 있다.
원격으로 조회할 참고표의 배치이며, 플러그인의 실행 파일과 독립 수행에 필요한 절차를
배포 경계 밖으로 옮기는 근거로 사용하지 않는다.
