# check_references.py

[공통 가이드라인](../guidelines.md)에 따라 참조 연결 검사 스크립트를 실행할 때 읽는 개별 안내다.
[검사 코드](../scripts/validation/check_references.py)는 로컬 링크 대상과 Markdown 문서의 절 존재 여부를 검사한다.

## 적용 대상

- 생성하거나 유지하는 내부용/플러그인용 스킬의 Markdown을 대상으로 하며, 스킬별로 실행한다.
- 제거할 스킬을 입력으로 사용하지 않는다.
  - 다른 문서에 남은 참조의 정리 여부는 호출 스킬이 정한 영향 범위에서 별도로 확인한다.
- 완료 기록은 아래 [완료 보고서 모드](#완료-보고서-모드)로 현재 보존 묶음을 검사한다.

## 입력과 실행

`skill_directory`에 검사할 스킬 최상위 디렉토리의 절대 경로를 설정한다.
markdown-it-py가 필요하며 준비 방법과 허용 버전은 [공통 가이드라인](../guidelines.md)을 따른다.

```bash
python3 tools/scripts/validation/check_references.py "$skill_directory" --json
```

## 추출 범위와 경로 해석

- 입력 디렉토리 아래의 `.md` 파일을 확장자 대소문자와 숨김 여부에 관계없이 읽는다.
- 상대 링크는 링크가 작성된 문서의 디렉토리를 기준으로 해석한다.
- 링크 대상의 다른 문서도 절 확인에 필요하면 읽지만, 그 문서의 링크를 따라 검사 범위를 추가 확장하지는 않는다.
- 파싱 결과는 한 실행 안에서 재사용한다.
- 하위 심볼릭 링크 디렉토리는 재귀 탐색하지 않고 `UNCHECKED`로 표시한다.
- 파일 링크는 실제 대상을 확인하며, 깨진 파일 링크는 실패한다.

[markdown-it-py](https://markdown-it-py.readthedocs.io/en/latest/using.html)의
CommonMark 파서에 표 문법을 활성화하여 인라인 링크, 참조형 링크와 이미지 경로를 추출한다.

- URL 인코딩은 경로와 fragment에서 각각 한 번 해제한다.
- 환경 변수나 `~`를 셸 경로처럼 확장하지 않는다.
- 실제 Markdown 로컬 링크로 표기한 생성 예정 경로도 존재 검사 대상이다.

| 표기/상황 | 처리 |
| --- | --- |
| 로컬 파일/디렉토리 링크 | 존재 여부 판정. 실패 위치와 해석한 경로 출력 |
| Markdown 파일 경로와 `#절` | 파일 존재 후 지정한 절의 존재 판정 |
| `#절`만 있는 링크 | 같은 문서의 절 존재 판정 |
| 빈 fragment (`파일.md#`, `#`) | 문서 자체를 가리키므로 파일 존재만 판정 |
| 비Markdown 파일/디렉토리의 nonempty fragment | 대상 존재 확인 후 `UNCHECKED` |
| 쿼리가 있는 링크 | 로컬 경로/절만 판정. 쿼리의 동적 의미는 미검사 |
| 외부 URL, 별도 URI 스킴, `//` 네트워크 주소 | `SKIP`. 네트워크 요청이나 URI 실행 없음 |
| 코드 블록/인라인 코드, YAML 프론트매터, HTML 주석/태그의 경로 | Markdown 링크 추출 범위에서 제외 |
| 일반 문장의 파일명, 잘못된 Markdown 또는 미정의 참조 | 의미 추론이나 별도 문자열 탐지 없음 |
| 읽기/파싱/디렉토리 탐색 오류 | `ERROR`. 미실행을 통과로 처리하지 않음 |

- `SKIP`은 범위 밖이라는 뜻이며 유효성을 확인했다는 뜻이 아니다.
- 종료 코드 규칙은 [공통 가이드라인](../guidelines.md)을 따른다.
- Markdown 0개이면 실행 오류이고, 문서는 있지만 링크가 0개이면 추출 0건을 명시한다.
- JSON에는 스캔한 모든 문서와 추출 링크 수, 항목별 판정/근거/해석 경로를 담는다.
- 줄 번호는 링크를 포함한 Markdown 블록의 시작 줄이며 정확한 링크 문자 위치를 뜻하지 않는다.

## 절 링크 판정

제목과 명시 HTML 앵커의 수집, 문자 변환과 중복 번호, fragment 해석은
[검증 규격의 절 링크 판정](../../standards/skills/skill-validation.md#로컬-markdown-절-링크의-기계-판정)을 따른다.
정책 이름은 `aster-markdown-headings-v1`이며 결과의 `anchor_policy`에 기록한다.

파일 확인, 제목/앵커 수집과 절 대조는 같은 스크립트의 별도 함수에서 처리한다.

- 존재하지 않는 절은 `reference.fragment`의 `FAIL`이다.
- `fragment_checked: true`는 대조를 수행했다는 뜻이며 통과 여부는 `status`로 확인한다.
  - 파일 누락/읽기 오류나 지원하지 않는 대상 형식은 절을 확인한 것으로 표시하지 않는다.
- `fragment_decoded`에는 한 번 해제한 값, `matched_anchor`에는 실제 일치한 값을 기록한다.
- 앵커를 읽기 위해 참조한 문서의 접근/파싱 실패는 `ERROR`, 지원하지 않는 대상은 `UNCHECKED`다.
- 오류/미판정이 있으면 기존 규칙에 따라 종료 코드 `2`를 반환한다.

## 완료 보고서 모드

완료 기록을 이관한 뒤 원본 자료를 정리하기 전에 실행한다.

`report_directory`에는 검사할 현재 보존 묶음 디렉토리의 절대 경로를 지정한다.
일반 참조 검사에 [완료 보고서의 로컬 참조 기준](../../standards/skills/skill-validation.md#완료-보고서의-로컬-참조)을 추가한다.

```bash
python3 -B tools/scripts/validation/check_references.py "$report_directory" --completion-report --json
```

- Git 저장소의 작업 트리 안에서 실행하며 저장소 루트는 검사 대상 위치에서 확인한다.
- 일반 모드는 Git을 요구하지 않는다.
- 이 모드는 로컬 절대 경로와 `file:` URI, 저장소 밖의 대상, Git 내부 메타데이터와
  Git에서 제외된 미추적 자료를 거부한다.
- 상대 심볼릭 링크는 연결 파일과 실제 대상의 보존 조건을 확인한다.
- 디렉토리에는 Git으로 보존할 수 있는 파일이 있어야 한다.

- 출력의 `preservation.untracked_files`는 보고서와 참조 대상에서 발견한 커밋 필요 파일 목록이다.
  - 보고서와 함께 커밋할 자료의 누락 여부를 확인하는 데 사용한다.
  - 이 목록은 작업 전체의 변경 파일 목록이나 실제 커밋 승인을 대신하지 않는다.
- 새 파일의 경로가 유효하면 `PASS`일 수 있으므로 실제 커밋 여부는 별도로 확인한다.
- 파일 참조에는 `repository_target`, `git_state`, `needs_commit`도 출력한다.
- Git 조회 실패는 `ERROR`이며, 기존 종료 코드와 결과 해석 규칙을 유지한다.

- 검사는 지정한 묶음의 Markdown 링크와 이미지 참조에 한정한다.
  - 일반 문장과 코드/주석의 과거 경로, 외부 URL과 그 밖의 URI는 자동 판정하지 않는다.
- 링크된 다른 문서의 링크까지 재귀 검사하거나 파일과 Git 상태를 변경하지 않는다.

## 결과 해석과 한계

- 생성 예정 경로에 대해 로컬 대상이 없다는 `FAIL`이 나오면, 호출 스킬은 문서에 정의된
  생성 시점과 조건을 [검증 규격](../../standards/skills/skill-validation.md#구조-검증)에 대조하여
  현재 존재해야 할 대상인지 판단한다.
  - 아직 생성할 시점이 아닌 경로의 부재만으로 규격 위반을 확정하지 않으며,
    생성 예정이라는 추정만으로 실패를 제외하지도 않는다.

- 문서에 다른 상대 경로 기준이 명시되어 있어도 검사기는 이를 해석하지 않는다.
  - 호출 스킬은 명시된 기준과 검사기가 해석한 경로를 대조하고, 필요한 경우 해당 기준에서 실제 대상의 존재를 확인한다.
  - 이 판단은 검사기의 출력과 구분하여 근거와 함께 기록한다.

- 통과는 파서가 인식한 로컬 링크 대상과 위 정책에 따른 Markdown 절의 존재를 뜻한다.
  - 필요한 참조의 누락, 문서의 자연어 경로 기준, 내용상 적절성, 다른 렌더러의 앵커 처리,
    설치 후 경로와 하네스 실행은 별도 검증한다.
- HTML의 `href`는 링크 추출 대상에 추가하지 않는다.
