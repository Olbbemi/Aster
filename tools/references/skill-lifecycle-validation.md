# skill-lifecycle 푸시 전 검사 기준

## 목적과 현재 상태

skill-lifecycle 변경을 푸시하기 전에 실제 스킬 파일의 필수 조건을 기계적으로 검사한다.
적용한 검사 중 하나라도 실패하면 푸시를 차단하는 데 사용한다.

검사 스크립트는 [check_skill_lifecycle.py](../tests/skills/skill-lifecycle/check_skill_lifecycle.py)다.
아래 여섯 항목을 실행하고 전체 판정을 반환한다.
[checks.json](../tests/skills/skill-lifecycle/checks.json)에 등록되어 있으며,
스킬 경로의 변경이 감지되면 `pre-push`에서 푸시할 커밋을 검사한다.
검사 호출과 푸시 차단은 [스킬 푸시 전 검사](skill-pre-push.md)를 따른다.

## 검사 대상과 범위

검사 대상은 푸시할 커밋에 포함된 `.agents/skills/skill-lifecycle/`의 파일이다.
다른 수정이나 미추적 파일이 섞인 작업 트리의 상태로 푸시할 커밋의 검사를 대신하지 않는다.
해당 스킬의 변경이 감지되면 변경된 파일만이 아니라 스킬 전체에서 아래 조건을 확인한다.

- `SKILL.md`, `references/`의 지침, `assets/`의 템플릿 원본과 스킬에 포함된 Python 파일을 검사한다.
- 실제 작업 명세서, 작업 기록, 시험 결과와 lifecycle로 생성하거나 수정하는 다른 스킬은 검사하지 않는다.
  스킬 내부의 `references/records/`는 기록 관리 지침이므로 검사 대상에 포함한다.
- 로컬 링크가 스킬 밖을 가리키면 그 대상의 존재와 지정한 절만 확인한다.
  연결된 문서의 링크를 따라가며 검사 범위를 확대하지 않는다.
- 외부 URL의 접속 가능 여부, 실제 모델 호출과 스킬 사용 시나리오는 검사하지 않는다.
- 검사 과정에서 대상 파일, Git 인덱스나 커밋을 수정하지 않는다.

## 검사 항목과 판정 기준

아래 표는 기존 규격에서 기계적으로 판정할 범위를 선택한 것이다.
세부 규칙은 연결한 정본을 따르며, 현재 파일 개수나 문구 전체를 고정된 기대값으로 복제하지 않는다.

| 항목 | 통과 조건 | 실패 조건 | 기준의 정본 |
| --- | --- | --- | --- |
| 스킬 기본 형식 | `SKILL.md`의 YAML을 파싱할 수 있고, `name`과 `description`이 비어 있지 않은 문자열이며 이름이 디렉토리명과 허용 문자 규칙에 맞음 | 필수 파일이나 필드 누락, YAML 구문 오류와 중복 키, 필수 값의 타입 오류나 이름 불일치 | [스킬 frontmatter](../../standards/skills/skill-content.md#skillmd-frontmatter), [구조 검증](../../standards/skills/skill-validation.md#구조-검증) |
| 로컬 참조 연결 | 스킬의 Markdown에서 추출한 로컬 링크 대상이 존재하며, 지정한 Markdown 절을 확인할 수 있음 | 대상 파일이나 절 누락, 잘못된 경로, 접근 또는 해석 오류 | [로컬 Markdown 절 링크](../../standards/skills/skill-validation.md#로컬-markdown-절-링크의-기계-판정) |
| 단계 목록과 파일 대응 | `lifecycle.md`의 단계 목록이 중복 없이 해석되며 `references/stages/`의 Markdown 파일 목록과 일치함 | 단계 목록의 누락이나 중복, 단계 파일 누락, 목록에 없는 단계 파일 | [단계 정의 공통 항목](../../.agents/skills/skill-lifecycle/references/lifecycle.md#단계-정의-공통-항목) |
| 단계 문서 구조 | 단계별 문서 제목, 필수 구역과 운영 항목의 제목 단계, 순서와 개수가 정본에 맞음 | 제목 불일치, 필수 구역이나 운영 항목의 누락, 중복, 순서 또는 제목 단계 오류 | [단계 정의 공통 항목](../../.agents/skills/skill-lifecycle/references/lifecycle.md#단계-정의-공통-항목) |
| 템플릿과 지침 대응 | 템플릿 원본의 단계 순서와 단계별 기록 항목이 지침에 대응하고, 프론트매터가 템플릿의 필드 및 초기값 기준에 맞음 | 단계나 기록 항목의 누락, 중복, 순서 불일치, 필드 누락이나 잘못된 타입 및 초기값 | [명세서 템플릿](../../.agents/skills/skill-lifecycle/references/records/specification.md#명세서-템플릿), [프론트매터](../../.agents/skills/skill-lifecycle/references/records/specification.md#프론트매터) |
| Python 문법 | 스킬에 포함된 Python 소스를 실행하지 않고 구문 분석할 수 있음 | 구문 오류 또는 소스 읽기 실패 | [구조 검증](../../standards/skills/skill-validation.md#구조-검증) |

기본 형식 검사에서는 선택 필드가 있다는 이유만으로 실패시키지 않는다.
하네스별 길이 제한이나 설명의 의미를 임의의 규칙으로 추가하지 않는다.

링크는 정본의 Markdown 추출 범위와 앵커 규칙을 따른다.
예시 코드, 일반 문장과 주석에 적힌 경로를 실행 대상이나 필수 파일로 추정하지 않는다.
로컬 링크 중 정본에서 미판정으로 구분하는 대상은 통과로 처리하지 않고 검사 오류로 보고한다.

단계 목록과 운영 항목은 해당 정본에서 읽어 대조한다.
단계를 추가하면서 목록, 단계 문서와 템플릿을 함께 갱신했다면 기존 단계 수를 이유로 실패시키지 않는다.
코드 예시, 주석과 인용문 안의 제목은 실제 단계 구조로 세지 않는다.

템플릿은 완성된 작업 명세서로 취급하지 않는다.
작성용 이름, 경로, 작업 유형과 문서 제목의 자리표시자를 허용하며 빈 기록란이나 작성 안내 주석을 실패로 처리하지 않는다.
실제 명세서 작성 여부, 승인 상태와 단계 완료 여부를 검사하지 않는다.

Python 문법 검사는 구문 분석에 한정한다.
스킬의 코드를 import하거나 실행해 작업을 시작하지 않으며 바이트코드 파일도 생성하지 않는다.

## 실행 방법

Aster 저장소 루트에서 Python 3으로 실행한다.
필요한 의존성은 `PyYAML`과 `markdown-it-py`이며 버전 범위는 [tools/requirements.txt](../requirements.txt)를 따른다.
의존성이 없는 실행 환경에서는 검사를 실행할 Python의 가상 환경 등을 준비한 뒤 다음 명령으로 설치한다.
훅의 격리 모드에서 접근할 수 있는 환경 기준은 [스킬 검사 입력](skill-pre-push.md#스킬-검사-등록과-입력)을 따른다.

```sh
python3 -m pip install -r tools/requirements.txt
```

개발 중인 파일은 작업 트리 입력을 명시하여 검사한다.

```sh
python3 -B tools/tests/skills/skill-lifecycle/check_skill_lifecycle.py --working-tree
```

커밋에 포함된 파일은 `--revision`으로 검사한다.
예를 들어 현재 `HEAD`의 스킬 파일을 검사하려면 다음 명령을 사용한다.

```sh
python3 -B tools/tests/skills/skill-lifecycle/check_skill_lifecycle.py --revision HEAD
```

`--working-tree`와 `--revision` 중 하나를 반드시 지정하며 함께 사용하지 않는다.
`--revision`은 커밋으로 해석할 수 있는 SHA, 브랜치 또는 태그를 받는다.
이 모드에서는 스킬 파일과 로컬 참조 대상을 모두 같은 커밋에서 읽는다.
작업 트리와 인덱스의 변경이나 미추적 파일을 검사 결과에 섞지 않으며 checkout도 수행하지 않는다.
훅에서는 Git이 전달한 실제 푸시 대상 커밋을 지정한다.

기본 저장소 경로는 스크립트가 놓인 Aster 저장소 루트다.
시험용 사본이나 다른 체크아웃은 `--repository-root <저장소 경로>`로 지정할 수 있다.

`--json`을 추가하면 전체 boolean 판정인 `passed`, 입력 모드와 해석한 커밋,
항목별 판정 및 실패 원인, 제외한 외부 링크 목록을 JSON으로 출력한다.
일반 출력은 첫 줄에 전체 `true` 또는 `false`, 이후 각 항목의 판정과 실패 위치 및 이유를 출력한다.

커밋 밖으로 나가는 참조와 절대 심볼릭 링크는 커밋 입력에서 확인할 수 없으므로 검사 오류다.
스킬 하위의 심볼릭 링크 디렉토리와 하위 저장소도 전체 파일 검사를 보장할 수 없어 검사 오류로 처리한다.
이런 오류를 검사 생략이나 통과로 처리하지 않는다.

## 결과와 실패 처리

각 검사의 판정은 `true` 또는 `false`다.
프로세스 종료 코드는 통과가 `0`, 실패가 비정상 종료 코드이며, 호출 측은 `0` 이외를 모두 차단으로 처리한다.

- 적용한 모든 항목을 판정하고 통과한 경우에만 `true`를 반환한다.
- 규칙 위반, 필수 입력 누락, 의존성 누락, 파일 읽기 실패와 검사 실행 오류는 모두 `false`다.
- 규칙 위반과 검사 실행 오류는 출력에서 구분한다.
  실패 항목, 대상 파일과 확인 가능한 위치 및 이유를 제공한다.
- 외부 URL은 검사 범위에서 제외하며 선택 자료가 없다는 사실만으로 실패시키지 않는다.
  다만 문서의 로컬 링크가 존재하지 않는 자료를 가리키면 참조 연결 검사에서 실패한다.
  제외한 범위를 알리고, 적용한 검사를 수행하지 못한 경우와 구분한다.
- 지침의 충분성, 단계 이동 조건의 타당성, 사용자 승인과 실제 시나리오 성공 여부는 판정하지 않는다.

## 배치와 훅 연결

검사는 `tools/tests/skills/skill-lifecycle/` 바로 아래에 둔다.
추가 하위 디렉토리를 만들지 않으며 파일명은 검사 기능을 명확하게 나타내도록 정한다.
배치 기준은 [저장소 공용 실행 도구](../../standards/repository-layout.md#저장소-공용-실행-도구)를 따른다.

`pre-push`에서는 푸시할 변경 파일이 속한 스킬 디렉토리 이름과
`tools/tests/skills/<스킬명>/`의 등록을 대응시켜 검사 대상을 선택한다.
여러 스킬이 바뀌면 각각 검사하며, 루트 `README.md`처럼 대응하는 스킬이 없는 변경은 스킬 검사를 생략한다.
호출 관계와 자동 적용 조건은 [스킬 푸시 전 검사](skill-pre-push.md)를 따른다.
