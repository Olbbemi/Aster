## pre-push 연결과 차단

실제 프로젝트 훅과 운영 코드 2개, 검사 코드/등록을 fixture 저장소에 복사했다.
시험용 `.git/hooks/pre-push`가 fixture의 프로젝트 훅만 호출하게 연결했다.
Camellia fixture manifest의 버전을 0.0.1부터 변경에 맞게 증가시켜 기존 버전 관문도 함께 통과시켰다.
이 버전과 커밋은 시험용이며 실제 Aster의 manifest/버전/커밋은 바꾸지 않았다.

| 사례 | 실제 관찰 |
| --- | --- |
| 정상 code-development 변경 | 실제 `git push` 성공. 등록된 5개 검사 모두 호출/통과, bare 원격 반영 |
| 잘못된 스킬 커밋과 수정된 인덱스 | 실제 `git push` 거부. 5개 모두 호출, 커밋의 메타데이터 실패를 검출, 원격 유지 |
| 등록된 검사 파일 부재 | 등록 오류로 푸시 거부, 원격 유지 |
| 첫 검사 실행 오류 | 오류로 푸시 거부하며 나머지 4개 검사도 호출, 원격 유지 |
| 시간 초과 | 공용 설정 60초를 확인. 시험에서만 0.05초로 단축하고 sleep(2) 자식의 실제 만료를 재현. 공용 실행 경로가 오류 2 반환 |
| 복원한 정상 소스 | 5개 모두 통과하고 실제 `git push` 성공 |
| 다른 스킬만 변경 | 푸시 성공, code-development는 호출하지 않음 |
| 개발용 테스트 경로만 변경 | 푸시 성공, code-development는 호출하지 않음 |

정상 전체 푸시는 16.640초, 커밋 위반 푸시는 16.800초, 실행 오류 푸시는 16.469초,
복원한 정상 전체 푸시는 16.833초였다.
각 커밋 검사도 최대 9.946초였으며 개별 파일의 60초 제한을 충족했다.
60초 동안 실제로 기다린 시험은 아니며 설정값 확인과 단축한 실제 시간 초과의 검출을 구분한다.
제한 시간이나 푸시 선택 규칙을 운영 코드에서 변경하지 않았다.

위 pre-push 8개와 앞 절 24개를 합한 추가 검증 32개가 최종 통과했다.
원시 결과는 `integration.json`이다.
모든 Git fixture와 시간 초과 fixture의 임시 디렉토리가 종료 후 제거된 것을 확인했다.
실제 16개 검사 대상 Python 소스의 SHA-256도 검증 전후 일치했다.

### 시험 하네스의 문제와 처리

첫 시험 준비에서 빈 Git 템플릿을 사용하여 hooks 디렉토리가 없었다.
fixture의 hooks 부모를 명시적으로 생성한 뒤 묶음을 다시 실행했다.
이 실패는 검사 대상 제품의 결함이 아니며 준비 실패를 통과로 기록하지 않았다.

다음 실행의 시간 초과 사례는 대상이 올바르게 오류 2와 stderr를 반환했지만,
시험 코드가 stdout만 검사하여 실패했다.
시험 코드의 출력 채널 확인을 수정하고 시간 초과 사례만 재실행했다.
다른 31개 통과는 대상과 조건이 바뀌지 않아 재사용했다.
초기 결과는 `integration-initial.json`, 단독 재검증은 `timeout-recheck.json`에 보존했다.

## 검증 범위와 후속 기록

두 개발용 종료 코드는 1이었다. 정상 제품의 통과와 변이 사본의 의도된 실패를 구분한다.

Python 16개 구문, 명세서 형식과 보존 참조 및 git diff --check도 확인했다.
원시 실행 JSON/stderr와 변이 결과는 공용 로컬 자료 루트의 validation/cross-review-fixes에 보존한다.

Git 운영 구현과 등록 파일은 변경하지 않았으며 기존 로컬 pre-push 연결 검증 결과를 보존한다.
