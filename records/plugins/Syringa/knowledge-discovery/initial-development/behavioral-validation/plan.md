## 분리본 동작 검증 실행안

D5는 2026-10-12에 수행한 두 개발 사본 사례다.
배포 파일 21개와 입력 자료를 사례별 독립 Git 프로젝트에 두었다.
정상 흐름은 같은 세션에서 4회, 잘못된 저장 루트는 별도 세션에서 1회 요청했다.
쓰기와 TMPDIR은 각 project/runtime을 포함한 프로젝트 안으로 제한했다.
네트워크 차단, workspace-write, approval_policy=never와 요청당 제한 시간 600초를 적용했다.
모의 입력/승인과 시험 경로의 임시 등록/복구 및 정리는 사용자 승인 범위다.

| 사례 | 입력과 관찰 지점 |
| --- | --- |
| D5.1 | 경로 없는 요청 -> 자료 디렉토리와 Git 루트 -> rust.rs/database.sql 범위 확정 -> PostgreSQL 제외/나머지 승인 |
| D5.2 | rust.rs와 Git 루트 아래 output-child를 전달하여 루트 거부 및 자동 대체/분석/저장 없음 확인 |

후보의 표현이나 개수를 고정하지 않고 자료에 있는 개념과 승인 집합을 대조했다.
범위 밖 excluded.md, 프로젝트 업무와 이름만 등장한 의존성이 분석/출력에 섞이지 않아야 한다.
단계 문서와 독립 스크립트의 실제 호출, 승인 전 출력 없음, 같은 실행의 저장/상태를 확인했다.
String 조건, Option 타입 표기, match의 분기 및 출처 미노출은 원자료와 직접 비교했다.

잠금/충돌/중단 조합은 D3 근거를 재사용하며 자동 선택/선택 제외는 변경 영향이 없어 반복하지 않았다.

#### Claude 준비 환경 복구

최초 호출은 준비용 ls 및 결합 Git 명령이 거부되어 분석 전에 멈췄다.
재개 시 시험 전용 execution-settings.json에 개별 Git 조회와 설치 스크립트 호출을 지정했다.
이후 제어 JSON의 Write도 거부됐다.
이는 시험 진행자가 Write(path)로 작성한 허용 규칙의 오류이며 스킬 결함이 아니다.
[Claude 공식 파일 권한 규격](https://code.claude.com/docs/en/permissions#read-and-edit)에 따라
같은 project/runtime 범위의 Edit(path)로 고쳤다.
임의 셸 쓰기로 우회하지 않고 Write 도구와 설치된 스크립트로 재개했다.
후보 제시와 최종 저장 호출의 permission_denials는 모두 비어 있다.
전역 설정과 설치 파일은 변경하지 않았으며 최초 거부와 복구 원인은 위와 같이 보존한다.

#### Claude 의미 검증 실패

원자료는 "String 값을 다른 변수로 옮기면 소유자가 바뀐다"고 타입과 대상을 명시한다.
Claude의 개념 설명에는 "String과 같은 값을"이라는 표현과 String 예시가 남아 있다.
하지만 문법과 사용 형태에는 다음과 같이 기록했다.

> `let moved = original;`처럼 변수에 값을 대입하면 소유권이 새 변수로 이동합니다.

이 문장은 String 예시의 조건을 붙이지 않고 변수 대입 일반의 규칙으로 서술한다.
자료의 타입/적용 범위를 유지하고 예시를 일반 규칙으로 확대하지 않는 R6 및
stages/analysis-and-save.md의 기준으로 실패 판정했다.
String 예시의 존재만으로 이 일반화된 설명을 통과 처리하지 않았다.
이는 실제 산출물의 의미 판정이며 Python 실행기의 승인/저장 실패나 설치 누락으로 분류하지 않는다.
최초 판정 당시 소스 수정이나 추가 재시험은 수행하지 않았다.

후속 검토에서는 개념 설명과 예시에 String 조건이 남아 있는 전체 문맥을 고려하여,
명백한 조건 누락으로 단정하기보다 사용 형태 문장의 모호함으로 판단했다.
현행 지침에는 조건 보존, 일반화 금지와 저장 전 원자료 대조가 이미 명시되어 있어
이번 결과만으로 추가 지침이나 스크립트 수정이 필요하다고 판단하지 않는다.
2026-10-12 사용자는 이번 정도의 모호함을 수용하고 사용하면서 필요한 부분을 보정하도록 결정했다.
최초 관찰과 판정을 보존하되 추가 수정이나 재시험을 진행 조건으로 두지 않는다.
이 결정은 모든 산출물의 정확성을 보장하거나 자료 충실성 요건을 폐지하는 뜻이 아니다.

사용자 수용으로 해당 관찰은 진행을 막는 미해결 사항에서 제외한다.
결과 표에는 최초 의미 판정을 유지하고 수용 판단을 통과 재시험과 구분한다.

## 재현 자료와 입력

독립 Git 작업 트리에 UTF-8 자료 두 개를 준비한다.
0.1.1까지의 개발 사본은 5개 파일, D5 분리본은 21개 파일을 복사하여 SKILL.md 경로를 명시한다.
설치 시험은 각 CLI의 설치본을 사용한다.
원자료와 시험 대상의 실행 전후 바이트를 대조하며 전역 설정은 변경하지 않는다.

Rust 자료에는 아래 설명과 예시를 넣는다.
소유권 조건 누락과 타입 표기 손실을 재현하는 데 필요한 발췌다.

```rust
// String 값을 다른 변수로 옮기면 소유자가 바뀐다.
// 이동한 뒤 이전 변수로 그 값을 사용할 수 없다.
fn ownership() {
    let original = String::from("sample");
    let moved = original;
    println!("{}", moved);
}
// Option<T>: Some(T)는 값 있음, None은 없음
fn optional() {
    let present: Option<i32> = Some(7);
    let absent: Option<i32> = None;
}
// match는 값의 형태에 맞는 분기를 선택한다. 여기서는 Some과 None을 처리한다.
fn matching(value: Option<i32>) -> i32 {
    match value { Some(number) => number, None => 0 }
}
```

별도 PostgreSQL 자료에는 여러 SQL을 한 단위로 다루는 트랜잭션과
BEGIN/COMMIT/ROLLBACK 및 INSERT/UPDATE 예시를 넣는다.
인덱스는 검색을 돕는 접근 구조라는 설명과 recorded_at의 CREATE INDEX 및 날짜 조건 SELECT 예시를 넣는다.

제외 판정을 위해 프로젝트 전용 DemoPipeline의 Collector -> Ledger 처리 순서와 야간 업무 규칙,
사용법 없이 이름만 나오는 thiserror와 sqlx도 섞는다.
자료 밖의 기술 지식을 보충하도록 요구하지 않는다.

B1 입력은 다음 네 차례다.

1. 두 경로 없이 스킬 실행을 요청한다. 경로 질문만 하고 분석/저장을 시작하지 않아야 한다.
2. 자료 디렉토리, 정확한 Git 저장 루트와 승인된 모델 정보를 전달한다.
   구조만 확인하고 포함할 파일 범위를 질문해야 한다.
3. 위 두 자료 파일만 포함한다고 답한다.
   주제별 키워드와 짧은 자연어 설명을 제시하고 상세 본문 작성/최종 저장 없이 선택을 기다려야 한다.
4. "PostgreSQL 주제는 모두 제외하고 나머지는 승인합니다. 중간에 다시 묻지 말고 저장해 주세요."라고 답한다.
   승인한 Rust 개념만 한 파일에 저장해야 한다.

B2는 파일 단위 분석 대상과 모델 확인을 제공하되 저장 기준으로 Git 하위 디렉토리를 지정한다.
INVALID_OUTPUT_ROOT를 알리고 정확한 경로를 요청해야 하며 상위 루트 자동 대체는 실패다.

B1 부분 재시험, B3와 C1/C2는 첫 요청에서 두 파일의 범위, 저장 루트와 모델 확인을 함께 제공한다.
후보 제시 뒤 두 번째 요청에서 같은 PostgreSQL 제외 답변을 전달한다.
후보 수나 표현 자체를 고정하지 않고 실제 자료와 개념 및 설명을 대조한다.
결과에 출처 경로/행 번호/링크, 빈 소제목, 제외 주제나 프로젝트 고유 지식이 없어야 한다.

## 주요 실패와 보완

### B1: Markdown 타입 표기 손실

최초 B1은 입력/범위 확인, 후보 추출과 승인 집합 처리는 맞았지만 렌더링에서 실패했다.
일반 본문의 `Option<T>`와 `Option<i32>`가 HTML 인라인 토큰으로 해석됐다.
제목/본문의 꺾쇠 문자를 이스케이프하고 인라인 코드 및 코드 블록은 유지하도록 수정했다.
실제 Markdown 파서를 쓰는 두 회귀 검사를 추가하여 자동 검사 29개를 통과했다.

같은 자료와 판정 기준의 새 사본에서 후보 제시와 저장만 두 요청으로 재시험했다.
이미 확인한 입력 누락과 디렉토리 범위 단계는 재실행하지 않았다.
개념별 H1 세 개와 html_inline 0개를 확인했고 타입의 표시가 유지됐다.
최초 실패 판정은 보존하며 재시험 통과와 구분한다.

### C2: String 적용 조건 누락

0.1.0 Claude 설치본의 일반 설명은 다음과 같았다.

> 값을 다른 변수에 대입하면 소유권이 그 변수로 옮겨지는 방식입니다.

원자료의 "String 값을 다른 변수로 옮기면 소유자가 바뀐다"에서 String 조건이 빠졌다.
String 예시 코드가 남아 있어도 일반 설명의 과도한 일반화를 해소하지 못하므로 의미 요건 실패로 판정했다.
저장 절차의 성공과 별개다.

SKILL.md에 타입, 적용 대상, 조건과 제약 보존 및 저장 전 원자료 대조 지침 네 문장을 추가했다.
버전은 0.1.1로 올렸으며 Python 실행기와 두 참고 문서는 바꾸지 않았다.
B3 개발 사본에서 조건 보존을 확인한 뒤 실제 설치본 C1/C2를 다시 시험했다.
최종 설명은 각각 다음과 같았다.

- Codex: "이 예시에서는 String 값을 다른 변수로 옮기면 소유자가 바뀝니다."
- Claude: "String 값을 다른 변수로 옮기면(이동) 그 값의 소유자가 바뀝니다."

### Claude 설치 시험의 환경 복구

최종 C2의 첫 실행은 API 재시도 중 응답/도구 호출 없이 정지하여 종료 코드 130으로 중단했다.
정확한 원인은 확인하지 못했다.
다음 준비 실행은 스킬 읽기 후 권한 거부로 분석 전에 멈췄다.
새 시험 경로에서 정확한 읽기 전용 Git 명령을 허용한 뒤에도 결합 명령이 거부됐다.

같은 세션에서 허용된 준비 명령을 개별 실행하도록 요청한 뒤 후보 제시와 후속 승인/저장이 성공했다.
불필요한 ls 거부가 한 차례 남았으나 최종 저장 호출의 permission_denials는 빈 목록이었다.
자료, 모델, 선택과 판정 기준은 유지했고 스킬 소스는 수정하지 않았다.
따라서 환경 복구 후 통과이며 모든 준비 명령의 무개입 성공을 검증한 것은 아니다.

고정 단어 검사뿐 아니라 입력과 설명을 직접 대조했다.

양 CLI의 설치 파일 다섯 개가 최종 배포 커밋과 일치했다.
시험 전후 자료 두 개, 설치된 Syringa 다섯 파일과 각 Camellia 4.0.0의 31개 파일은 변경되지 않았다.
Python 계약 검사 29개는 실행기 바이트가 같아 0.1.1 및 최종 문서 정리에서 재실행하지 않았다.

이 기록은 선정한 자료, 모델과 Linux 환경의 관찰이다.
모든 기술 설명, 운영체제와 오류 조합을 보장하지 않으며 의미 정확성은 에이전트 판단에 의존한다.
0.1.1까지의 원시 자료는 앞선 정리에서 제거했고 필요한 조건과 핵심 출력만 보존했다.

## 시험 자료 정리

현재 작업의 로컬 자료는 공용 cargo의 work/plugins/Syringa/knowledge-discovery/initial-development 아래에서 관리했다.
분리본의 behavioral-validation/split-flow-20261012와 split-flow-retry-20261012,

핵심 입력/관찰/실패 원인/수용과 검토 결과는 이 기록 및 교차 검토 문서에 통합했다.
생성물 목록과 입력/사본 해시 및 경계를 대조한 뒤 위 네 경로의 원시 로그, 시험 사본과 중간 해시/diff 226개 파일을 정리했다.
로컬 작업 루트는 유지했으며 별도로 계속 보관할 이번 시험 자료는 없다.
하네스 소유 세션 로그, 실제 설치본, 전역 설정과 다른 작업 자료는 이 정리에 포함하지 않는다.
