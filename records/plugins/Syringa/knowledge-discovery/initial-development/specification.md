# 자료에서 위키 후보를 추출하는 knowledge-discovery

## problem-definition (문제 정의)

### 진입 조건 확인

자료 기반 후보 추출의 목적과 제외 범위를 사용자와 확정했다.

### 스킬을 통해 해결해야 할 문제

코드와 명세서에 등장하는 일반 기술 지식을 위키 작성 전에 검토할 후보로 추출한다.
사용자가 후보를 선택한 뒤 필요한 내용만 상세 정리한다.

### 스킬을 사용하는 주체와 스킬이 사용되는 상황

Codex 또는 Claude Code 사용자와 에이전트가 지정 자료에서 위키 작성 재료를 준비할 때 사용한다.

### 문제가 해결되었을 때 기대하는 결과

주제별 키워드와 짧은 설명을 먼저 제시하고, 일괄 승인한 개념만 주제별 Markdown 파일에 저장한다.

### 요청한 스킬의 생성, 변경, 통합 또는 폐기가 필요한지에 대한 판단과 근거

knowledge-discovery를 새로 만들었다.
사용자는 기존 knowledge-collection 설계를 폐기하고 Syringa 플러그인 위치만 유지하도록 지정했다.
기존 점수표, 대화 수집, 백그라운드 저장과 훅 정책은 승계하지 않았다.

### 스킬이 수행할 범위와 제외할 범위

자료에서 확인되는 개념, 원리, 문법과 사용법을 다룬다.
프로젝트 고유 구조와 업무 규칙, 자료 밖 연관 지식 확장, 완성 위키 작성,
사이트 UI, GitHub Pages 게시와 Actions 연동은 제외한다.

### 후속 단계에서 확인할 사항

기능별 분리와 지속 검사 구현 후 기계 검사, 실제 동작 시험, 독립 검토와 1.0.0 설치본 시험을 수행했다.
Claude 설명의 모호함은 사용자 수용으로 진행을 막지 않는다.
최종 판정과 한계는 호환성 검증 및 완료 절에 연결한다.

### 완료 조건 확인

일반 지식 후보 추출과 후속 위키 작성의 책임 경계를 확정했고 요건 및 구현에 반영했다.

### 단계 이동 기록

기존 대화의 합의와 구성 확인을 대조하여 최초 기록을 구조 설계 단계에서 시작했다.
이전 단계의 실행 이력을 소급하여 만들지 않았다.

## requirements-definition (요건 정의)

### 진입 조건 확인

기존 동작 요건 R1-R8을 유지하고 문서 및 실행기 분리 요건 R9-R10을 추가했다.

### 스킬의 사용 형태(내부용 또는 플러그인 배포용)

Syringa 플러그인 배포용 스킬이다. 소스 경로는 프론트매터의 target_path다.
사용자가 승인한 작업명은 initial-development이며 기록 루트는 이 명세서의 디렉토리다.
기존 two-stage-extraction은 미승인 이름이어서 변경했다.
기록 간 참조는 현재 작업명으로 통일했다.

### 지원 대상 CLI와 각 CLI에 적용할 호환성 요건

Linux의 Codex CLI와 Claude Code에서 같은 Markdown/YAML 지침, 상대 참조 및 Python/Git 실행기를 사용한다.
설치된 스킬의 호출, 자료 접근, 승인과 저장을 CLI별로 확인한다.
검증 환경과 지원 한계는 호환성 검증 절을 따른다.

### 스킬 호출 조건과 호출 제외 조건

사용자가 지정한 코드 또는 명세에서 위키 후보를 추출하고 저장하는 요청에 사용한다.
일반 질의응답, 대화 학습 기록, 프로젝트 구조 분석과 완성 위키 제작에는 적용하지 않는다.
폐기한 설계의 명시적 호출 전용 정책을 승계하지 않았다.

### 스킬 실행에 필요한 입력과 기대 결과

분석 대상 경로와 저장 기준 경로를 모두 사용자가 지정해야 한다.
누락값을 추정하지 않으며 디렉토리 범위가 불명확하면 내용을 읽기 전에 확인한다.
저장 기준은 기존의 쓰기 가능한 Git 작업 트리 루트다.
분석 대상과 출력 루트가 같은 저장소여야 한다는 제약은 없다.

산출물은 `<root>/knowledge-candidate/YYYY-MM-DD/knowledge-YYYYMMDD-HHMMSS-<topic>.md`다.
파일을 생성하는 시각을 사용하고 충돌하면 구분자를 추가한다.
주제별 한 파일 안에서 개념별 H1과 자료가 뒷받침하는 설명, 문법, 동작 및 최소 예시를 작성한다.
자료에 없는 항목과 원본 출처 구역은 만들지 않는다.

### 반드시 수행해야 하는 동작과 에이전트가 재량으로 판단할 수 있는 동작

에이전트는 일반 지식 선별, 주제와 개념 구성, 자연어 승인 해석과 자료 충실성을 판단한다.
실행기는 명시 경로, 파일 집합, 후보와 승인 ID, 문서 형식 및 저장 충돌을 검사한다.
실행기가 실제 사용자 동의나 의미 정확성을 독립적으로 증명하지는 않는다.

### 스킬 실행에 적용되는 제약, 실패 조건과 대응

입력 누락, 잘못된 Git 루트, 읽기 실패, 범위 밖 파일과 승인 ID 불일치에서는 진행을 막는다.
하위 디렉토리를 상위 Git 루트로 자동 교정하거나 없는 저장 루트를 만들지 않는다.
자료가 바뀌면 기존 후보와 승인을 재사용하지 않는다.
정상적인 빈 결과와 실패를 구분하고 일부 저장 뒤 실패하면 완료 파일을 보존한다.
복구가 불명확하면 RECOVERY_REQUIRED를 보고하며 저장 완료로 처리하지 않는다.

### 사용자 확인 및 승인 조건

스킬 사용자는 두 경로, 불명확한 디렉토리 범위, 후보 선택과 필요한 모델 범위를 확인한다.
명확한 제외 요청은 나머지 후보의 승인으로 해석하되 대상이 모호하면 다시 확인한다.
승인한 주제마다 재승인을 요구하지 않는다.

- [x] 자료 기반 일반 지식 후보 추출, 필수 두 경로, 정확한 Git 루트와 주제별 파일/개념별 제목을 확정했다.
  기존 수집 설계를 폐기하고 완성 위키 작성 및 프로젝트 고유 지식을 제외한다는 사용자 합의가 근거다.
- [x] 간결한 SKILL.md와 참고 문서의 단계 관리, 기능별 독립 스크립트와 공통 진입점 제거를 승인받았다.
  다른 스킬과 유사한 문서 구조 및 기능별 분리 요청을 반영했다.
- [x] 스킬 자체의 지속 검사를 기능별로 나누고 pre-push에 등록하도록 승인받았다.
  검사 결과는 boolean JSON/종료 코드이며 실제 작업 기록이나 AI 의미 판단은 검사 대상에서 제외한다.
- [x] 지침/검토는 GPT-6 Astra / high, 코드 구현은 GPT-6.1 Sol / medium으로 진행하도록 승인받았다.
  부모 세션의 모델은 사용자 변경 확인이며 독립 런타임 측정으로 표현하지 않는다.
- [x] 실제 Codex 시험은 GPT-6.1 Sol / medium, Claude 시험과 독립 검토는 Claude Sonnet / high로 승인받았다.
  모의 경로/범위 입력과 PostgreSQL 제외/나머지 승인, 시험 경로의 임시 등록/복구와 생성물 정리를 포함한다.
  모델 불일치 후에는 동작 시험만 재요청받아 직접 CLI 인자로 재시험했고 공용 실행기를 수정하지 않았다.
- [x] 작업명 initial-development와 lifecycle 기준 최종 기록 정리를 승인받았다.
  기록 커밋은 설치 검증 뒤로 미뤘다가 최종 정리와 커밋을 순서대로 진행하라는 요청으로 재개했다.

교차 검토 및 Git 반영 범위와 실제 커밋은 [커밋 검토](commit-review.md)에서 관리한다.
1.0.0 설명의 모호함에 대한 사용자 수용 범위는 호환성 검증 절에 기록한다.

### 각 파일과 자료가 담당할 역할

| 파일 | 역할 |
| --- | --- |
| SKILL.md | 목적, 적용 범위, 필수 입력과 시작/재개 안내 |

| references/execution.md | 명령, 데이터 스키마, 오류와 저장 계약 |
| references/model-selection.md | 모델 승인 범위와 설정 확인 방식 |
| scripts/*.py | 기능별 직접 실행과 필요한 공통 보조 기능. 세부 배치는 스크립트 설계 참조 |
| 플러그인 manifest | Syringa 식별자와 배포 버전 |

개발 자료의 역할은 완료 절의 보존 목록에 정리한다.

### 스킬을 구성하는 파일과 자료 사이의 참조 방향 및 의존 관계

model-selection.md는 공개 Aster 모델 선택 기준을 연결하며 사본을 유지하지 않는다.
런타임은 records나 tools의 개발 자료를 요구하지 않는다.

### 작업 대상 스킬 전용 자료

지침과 참고 문서는 knowledge-discovery의 SKILL.md 및 references/에,

실행별 잠금과 상태는 임시 디렉토리에 두고 배포물이나 최종 후보 문서와 분리한다.

## implementation (구현)

### 진입 조건 확인

문서 및 기능별 호출 설계를 확정하고 사용자 승인 모델로 구현했다.

### 새로 만들거나 수정, 이동 또는 제거한 파일과 디렉토리

SKILL.md를 진입 안내로 줄이고 workflow.md와 단계 문서 5개로 상세 절차를 옮겼다.
execution.md는 독립 호출 계약으로 갱신했다.
직접 호출 스크립트 7개와 공통 모듈 4개를 작성하고 discovery.py를 제거했다.
기존 본체 35개의 AST 동일성과 상태 재개를 구현 시점에 대조했으며 지속 검사로 고정하지 않았다.

기존 계약 29개에 독립 호출 흐름 1개를 추가했다.
이를 기능별 검사 5개로 나누고 구조 검사 1개를 더하여 총 6개 파일/33개 항목을 checks.json에 등록했다.
커밋 읽기와 실행 자료/결과 출력을 보조 모듈 2개에서 공유한다.
검사 안내, README와 배포 기대 목록을 갱신했으며 공용 훅은 변경하지 않았다.

문서화된 discovery.py 호출 폐지에 major 기준을 적용하여 manifest를 1.0.0으로 변경했다.
자료 충실성 및 모델 선택 규칙의 의미는 유지했다.
이전 B1의 Markdown 타입 표기와 0.1.0 C2의 조건 누락 보완은
[주요 실패와 보완](behavioral-validation/plan.md#주요-실패와-보완)에 보존한다.

## mechanical-validation (기계 검사)

### 진입 조건 확인

### 작업 대상 스킬의 기계 검사 항목과 적용 여부

스킬 구조, 로컬 참조, 배포 파일, 실행기 정상/오류 계약과 기록 형식을 검사했다.
자료의 의미와 실제 하네스 호출은 기계 검사의 통과 범위에 포함하지 않는다.

| 항목 | 적용과 필수 여부 | 판정 기준과 현재 근거 |
| --- | --- | --- |
| 기본 구조 | 필수 | skill-content.md의 frontmatter 및 skill-validation.md의 구조 검증. 이번 check_structure.py 실행 결과 |
| 로컬 참조 | 필수 | skill-validation.md의 구조/절 링크 검증. 이번 check_references.py 실행 결과 |

이후 스킬, 검사 코드, 입력 계약과 의존성에 변경이 없고 당시 사용한 명시 작업 트리/커밋 입력과 종료 코드를 확인하여 재사용한다.
실행기 30개 계약과 기본 형식/참조/구문 3개, 지정 커밋 격리 및 실패 차단 결과를 이번 새 실행과 구분한다.

소스 커밋 90932e8에서도 통과했고 실제 3d4960d 푸시의 pre-push에서 버전과 6개 등록 검사가 모두 통과했다.

| 경계 | 실제 관찰 |
| --- | --- |
| Git 루트/링크/자료 | Git 하위/bare/일반 디렉토리 거부, 링크 거부와 소스 변경 탐지 |
| 승인/출력 | 승인 ID 대조, 승인 전 저장 차단, 빈 결과/전체 제외, 타입 렌더링 |
| 저장 | 충돌 보존, 독립 프로세스 경쟁, 실행 잠금과 공개 전후 중단/복구 |
| 커밋 격리 | 미커밋 이름 오류/미추적 구문 오류는 커밋 검사에 섞이지 않고 작업 트리 검사만 실패. 대상 Git 상태 보존 |
| 훅 차단 | 커밋된 이름 오류와 승인 보호 제거는 false/1로 차단 |
| 검사 오류 | 잘못된 revision, 필수 모드/실행 모듈 누락은 false/2 |
| 환경 격리 | 잘못된 GIT_DIR/GIT_WORK_TREE에도 명시 저장소와 독립 Git fixture 검사 |

기존 9fbdd8f의 실행기로 만든 승인 상태를 새 read_source/save_topic/run_status에서 이어 처리했다.
이 AST/상태 호환 대조는 이번 분리의 일회성 근거이며 지속 검사에는 포함하지 않는다.

배포 전 원격 9fbdd8f는 이전 5개 파일 구성으로 현재 21개와 달라 FAIL/1이었다.
이후 소스 반영 뒤 원격 일치는 D6에서 별도 확인했으며 과거 실패를 통과로 바꾸지 않는다.

### 검사 실패가 발생한 위치와 위반한 개발 규격

B1의 타입 표기 손실은 기존 검사가 놓친 결함으로 실제 Markdown 파서의 회귀 검사를 추가했다.
배포 전 원격 비교 실패는 소스 결함이 아니라 아직 게시하지 않은 구성과의 차이였다.
원격 일치까지 기계 검사 완료 조건으로 요구한 명세의 순서 오류를 사용자 요청에 따라 정정하여,
로컬 배포 구성은 이 단계에서, 게시 후 원격 일치는 호환성 검증에서 확인했다.

### 실행하지 못한 검사와 실행했지만 결과를 판정하지 못한 항목

선정한 기계 검사에는 남은 미판정 항목이 없다.
외부 URL의 가용성은 로컬 참조 검사에서 다루지 않는다.
AI 의미 판단과 실제 설치 실행은 D5/D6의 별도 근거를 따른다.

### 의미 판단이 필요한 항목과 그 이유 및 확인할 후속 단계

일반 지식 선별, 자연어 승인과 설명의 적용 조건은 정규식이나 ID 검사로 보장할 수 없다.
D5/D6에서 입력과 설명을 대조했으며 수용한 표현의 한계는 호환성 검증 절에 기록한다.

### 완료 조건 확인

기본 구조, 로컬 참조/배포 구성과 33개 지속 검사 및 훅 차단 근거를 확인했다.
원격 일치는 게시 후 확인하는 것으로 정정하여 단계의 필수 항목에 미해결 사항이 없다.

### 단계 이동 기록

기계 검사 후 승인된 D5의 시나리오, 모델과 격리 환경으로 동작 검증에 진입했다.

## behavioral-validation (동작 검증)

### 진입 조건 확인

분리본의 기계 검사와 D5 두 사례/모델 승인을 확인하고 개발 사본을 준비했다.
0.1.1의 B1-B3 근거를 새 분리본의 통과로 승계하지 않았다.

### 확정한 시나리오와 실행 조건

[D5 실행 조건](behavioral-validation/plan.md#분리본-동작-검증-실행안)에 따라 정상 흐름 4회와 잘못된 저장 루트 1회를 수행했다.
독립 Git 프로젝트에 21개 배포 파일 사본과 자료를 두고 쓰기/임시 상태를 프로젝트로 제한했다.
모의 범위 및 후보 선택은 승인 범위에 한정했고 요청당 제한 시간은 600초였다.

### 동작 검증을 수행한 사용 사례와 입력

D5.1은 입력 누락 질문, 구조 확인 후 범위 질문, 두 파일에서 후보 제시 및 승인 대기,
PostgreSQL 제외 후 같은 실행의 Rust 저장을 확인했다.
D5.2는 Git 하위 디렉토리를 저장 루트로 제시하여 자동 대체 없이 거부하는지 확인했다.
입력 발췌와 기대 결과는 검증 기록의 재현 자료에 보존한다.

### 동작 검증에 사용한 CLI와 실행 환경

Codex CLI 0.162.1에서 수행했다.
최초 요청은 설정의 Sol / medium과 실제 turn_context의 Astra / high가 달라 중단했다.
이후 exec/exec resume에 모델과 강도를 직접 지정한 5회 요청에서 모두 gpt-6.1-sol / medium을 확인했다.
공용 실행기는 수정하지 않았고 임시 TOML 경로 등록은 복구했다.
환경과 모델의 관찰 근거는 [재시험 결과](behavioral-validation/plan.md#분리본-재시험-결과)를 따른다.

### 작업 대상 스킬의 인식 여부와 호출 결과

지정한 스킬 사본과 참고 문서 및 실행기에 접근하여 후보/승인/저장을 수행했다.
시험 중 사본 파일과 입력을 변경하지 않았다.

### 요건별 동작 검증 결과와 판정 근거

D5.1/D5.2는 통과했다.
단계 문서와 7개 독립 스크립트를 사용하여 승인 전 저장 없이 대기하고,
PostgreSQL 제외 뒤 Rust 후보 3개만 한 파일로 저장하여 completed를 확인했다.
String 조건, Option 타입 표기와 match 의미를 원자료에 대조했으며 범위 밖 분석/출력은 없었다.
잘못된 루트는 INVALID_OUTPUT_ROOT로 거부하고 자동 대체나 상세 분석/저장을 하지 않았다.

### 이전 단계에서 넘긴 미확인 사항과 의미 판단 항목의 확인 결과 및 근거

프로젝트 고유 지식과 이름만 등장한 의존성은 제외됐고 승인 전 저장이 없었다.
일괄 선택과 결과의 자료 충실성을 원자료에 대조하여 판단했다.

### 동작 검증에서 발견한 실패와 재현 조건

최초 D5의 모델 불일치는 미판정으로 보존하며 원인은 확정하지 않았다.
지정 모델에서의 재시험으로 현재 요구 범위는 확인했다.
기존 B1 렌더링 및 C2 조건 누락 보완 이력은 검증 기록의 주요 실패 절을 따른다.

### 실행하지 못한 사용 사례와 결과를 판정하지 못한 동작

확정한 D5 두 사례에 남은 미판정 항목은 없다.
최초 설정 적용 차이의 원인은 미확정이나 공용 실행기 수정은 이번 범위에 포함하지 않았다.

### 완료 조건 확인

D5의 선정 사례가 지정 모델에서 통과했고 입력/사본/원본 해시 보존을 확인했다.
최초 미판정과 재시험을 구분했으며 설치 검증은 D6의 별도 근거를 사용한다.
