## 지적 1: 충돌 이름에서 중단하면 RECOVERY_REQUIRED로 정지

최종 판단은 반박이다.
관찰된 동작은 재현되지만 확정한 계약을 위반하는 결함은 아니다.
[실행 계약](../../../../../../../plugins/Syringa/skills/knowledge-discovery/references/execution.md)과
[설계](../../structure-design/script-design.md)는 상태와 파일의 일치 여부가 불명확하면 자동 저장을 멈추도록 정한다.
항상 다음 접미사로 복구한다는 요건은 없다.

재현은 독립 시험 Git 저장소에서 첫 이름과 -2 이름을 기존 파일로 점유하고,
-2 공개 의도를 상태에 저장한 직후 os.link 전에 하위 프로세스를 os._exit(73)으로 종료하는 방식이다.
finally가 수행되지 않아 publishing 상태와 임시 파일이 남았다.
이후 status의 실제 결과는 다음과 같다.

| 관찰 항목 | 결과 |
| --- | --- |
| 하위 프로세스 종료 코드 | 73 |
| phase / saved / failed | processing / 빈 목록 / 빈 목록 |
| pending | Rust 주제 1개 |
| recovery_required | RECOVERY_REQUIRED |
| 임시 파일 | status 전후 1개 유지 |
| 기존 두 파일 | 변경 없음 |

저장 완료로 오판하지 않았고 모호한 증거를 보존했다.
이 영속 상태는 공개 성공 후 외부 프로세스가 결과 파일을 교체한 경우와 구별할 수 없다.
다음 접미사로 자동 진행하면 교체 사실을 놓치고 중복 저장할 수 있으므로 현재 동작을 유지한다.
이 상태에서는 같은 실행의 추가 저장에 사용자 개입이 필요하다는 제약을 남긴다.

## 부수 관찰: 공개 전 중단의 임시 파일 잔존

최종 판단은 반박이다.
reconcile의 정리는 최종 파일 부재와 정상 파일 판정 뒤의 공통 경로에 있다.
성공 분기에서만 정리한다는 원 검토자의 설명은 코드와 일치하지 않는다.

충돌 없는 경로에서 공개 의도를 저장한 직후 os.link 전에 os._exit(73)으로 종료했다.
status는 saved를 빈 목록으로 유지하고 해당 주제를 IO_ERROR의 미저장 실패로 보고했다.
pending은 빈 목록, recovery_required는 null이었다.
이번 실행 inode와 같은 임시 파일은 status 전 1개에서 이후 0개가 됐다.
판정할 수 없는 불일치 상태의 보존과 구분한다.

## 참고 관찰과 최종 영향

H3 허용은 계약에 부합한다.
Git 환경변수로 잘못된 저장이 발생한다는 근거는 제시되지 않았으므로 확정 결함이나 변경 사유로 삼지 않았다.

수용하여 코드를 수정할 지적은 없었고 추가 독립 검토는 수행하지 않았다.
이 판단의 회차는 round-001이며 실제 설치/호출은 이후 [C1/C2](../../behavioral-validation/plan.md)에서 확인했다.
0.1.1은 후속 C2 조건 누락을 보완한 것으로 이 교차 검토의 수정 결과가 아니다.

재현 입력과 핵심 상태를 본문에 통합했다.
사용자 요청에 따라 원시 대화, 실행 로그와 일회성 재현 자료를 정리했으며,
원 검토자의 독립 실행이나 해시 검증이 있었던 것으로 확대하지 않는다.
