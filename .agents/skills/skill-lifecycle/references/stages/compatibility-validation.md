# compatibility-validation (호환성 검증)

이 문서는 `skill-lifecycle` 생명 주기의 `compatibility-validation` (호환성 검증) 단계에 적용할 운영 규칙과 단일 명세서 기록 기준을 정의한다.

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `compatibility-validation`이다.
- `cross-validation` (교차 검증)의 완료 조건과 근거가 확인되었다.
- 명세서에 지원 대상으로 정의된 CLI와 각 CLI에 적용할 호환성 요건 및 각 요건의 검증 기준이 확인되었다.
- 지원 CLI별 실행 환경의 준비 상태와 필요한 설치/업데이트 또는 사용자 이관 사항이 확인되었다.
- CLI별 검증 결과를 비교할 공통 요건과 CLI별로 허용되는 차이가 명세서에서 확인되었다.

### 수행 작업

공용/전용 구성과 필수 요건의 수행 및 완료 판단은 아래에서 선정한 호환성 범위에 적용한다.

- 명세서의 작업 유형, 호환성 요건과 검증 기준을
  [하네스 및 배포 검증](../../../../../standards/skills/skill-validation.md#하네스-및-배포-검증)에 대조하여
  CLI별 항목과 사례 및 종료 지점을 선정한다. 공용 자료를 사용하는 다른 스킬과 외부 구성의 영향도 포함한다.
- 같은 규격의 기존 근거 재사용 기준에 따라 유효한 근거와 추가 실행할 항목을 구분한다.
- [시나리오 절차](../scenario-validation.md)에 따라 실행 부담과 정리 범위를 포함한 묶음을 확정하고 결과를 대조한다.
- 이전 단계에서 현재 단계에 확인하도록 지정한 미확인 사항과 의미 판단 항목을 확인하고, 관련 규격과 명세서의 기준에 따라 검토하거나 검증한 결과와 판단 근거를 기록한다.
- [사용 형태별 확인](../../../../../standards/skills/skill-validation.md#사용-형태별-확인)에 맞는 실제 환경을 준비한다.
- 필요한 권한과 자동 실행 수단이 있으면 설치 또는 업데이트한다.
  수행할 수 없으면 이유, 대상 커밋/버전과 사용자 작업을 안내해 이관하고 실제 반영 상태를 확인한 뒤 시험을 재개한다.
  설치 준비 중에는 단계를 완료하지 않으며 Git 승인 및 전역 설정의 작업 경계를 유지한다.
- 호환성 검증 과정에서 파일, 설정 또는 외부 상태가 변경될 수 있으면 격리된 임시 작업 환경을 사용한다.
- 지원 CLI별로 현재 범위에 선정한 인식 및 호출 항목이 기대 상태와 일치하는지 확인한다.
- 공통 또는 CLI별로 적용되는 필수 호환성 요건과 해당 시험의 안전 조건을 각 대상 CLI에서 확인한다.
  전체 동작 요건으로 범위를 확대하지 않는다.
- 공용 파일, 설정과 지원 자료는 신규 요건 또는 변경 영향에 해당하는 접근과 실행 역할을 각 지원 CLI에서 확인한다.
- CLI 전용 파일이나 설정은 실제 비호환 사항과 공용 구성만으로 요건을 충족할 수 없는 근거를 확인한다.
  해당 구성의 동작과 적용 범위도 명세서 및 구조 설계와 대조한다.
- CLI별 검증 결과를 비교하여 공통으로 동작하는 범위, 명세서에서 허용한 차이 및 호환되지 않는 사항을 구분한다.
- 명세서에서 지원 대상으로 정의하지 않은 CLI나 실행 환경의 동작을 작업 대상 스킬이 지원하는 기능으로 판정하지 않는다.
- 각 CLI에서 사용한 실행 환경, 사용 사례와 입력, 검증한 요건, 실제로 관찰한 동작과 결과 및 판정 근거를 CLI별로 구분하여 기록한다. 한 CLI의 성공을 다른 CLI의 통과 근거로 사용하지 않는다.
- 실행하지 못한 호환성 검증 항목과 실행했지만 결과를 판정하지 못한 항목을 CLI별로 구분하고, 그 이유와 해결에 필요한 사항을 기록한다.
- 호환성 검증에서 수정이나 새로운 사실이 확인되면 이전 검증 결과에 미치는 영향을 확인한다.
  [단계 전이](../lifecycle.md#단계-전이)와 [검증 단계 순서](../lifecycle.md#검증-단계-순서)에 따라
  필요한 단계로 돌아가 영향받는 검증을 다시 수행하고,
  교차 검증의 수행 여부 판단과 기존 검토 결과가 현재 작업 결과에도 유효한지 확인한다.
  필요한 교차 검토를 마치고 플러그인은 변경분을 재배포한 뒤 완료 조건을 재확인한다.
- 환경/권한/사용량 문제와 스킬 결함을 구분하고
  [결과 대조와 재시험](../scenario-validation.md#결과-대조와-완료-판단)에 따라 미확인 범위만 재시험한다.
- 시험 자료의 보관과 삭제는 [시험 정리](../scenario-validation.md#시험-생성물과-임시-기록-정리)를 따른다.

### 완료 조건

- 지원 대상으로 정의한 모든 CLI에서 현재 범위의 필수 호환성 요건이 검증 기준을 통과했다.
- 현재 범위의 인식 및 호출 항목이 각 지원 CLI에서 기대 상태와 일치했다.
- 현재 호환성 범위에 해당하는 공용 구성의 역할이 각 CLI의 실제 실행 또는 현재도 유효한 기존 실행 근거로 확인되었다.
- 특정 지원 CLI에서만 사용하는 전용 파일이나 설정이 있다면, 실제로 호환되지 않는 사항과 공용 구성만으로 해당 CLI의 요건을 충족할 수 없는 근거에 따라 사용되었다.
- 특정 지원 CLI에서만 사용하는 전용 파일이나 설정이 있다면, 실제 동작과 적용 범위가 명세서 및 구조 설계에 정의된 내용과 일치했다.
- CLI별 동작과 구성의 차이를 구분했으며 명세서의 허용 범위를 벗어난 차이가 없다.
- 이전 단계에서 현재 단계에 확인하도록 지정한 미확인 사항과 의미 판단 항목의 검토 또는 검증 결과와 근거가 기록되었으며, 현재 단계의 완료를 막는 미해결 사항이 없다.
- 각 지원 CLI에서 사용 형태에 맞는 실제 환경의 근거가 확인되었다. 플러그인은 대상 커밋/버전의 실제 설치 또는 업데이트 반영과 설치본 호출이 확인되었다.
- 호환성 검증 과정에서 파일, 설정 또는 외부 상태가 변경될 수 있는 시험은 격리된 임시 작업 환경에서 수행되었으며, 검증 범위 밖의 실제 운영 파일, 사용자 데이터 또는 외부 상태를 변경하지 않았다.
- 각 CLI의 실행 환경, 검증한 사용 사례와 요건, 사용한 입력, 실제로 관찰한 동작과 결과 및 판정 근거가 기록되었다.
- 각 호환성 판정의 근거를 해당 CLI의 실제 실행 결과와 명세서의 관련 요건 및 검증 기준까지 추적할 수 있으며, 다른 CLI의 성공만으로 통과를 판정하지 않았다.
- 현재 범위의 필수 항목에 유효한 근거가 있으며, 추가 실행으로 확정한 사례가 모두 실행되었다.
- 실행하지 못한 호환성 검증 항목과 실행했지만 결과를 판정하지 못한 항목이 있다면, 해당 CLI와 항목, 이유 및 해결에 필요한 사항이 기록되었으며, 명세서의 검증 기준과 현재 단계의 완료 조건에 따라 완료를 막지 않는다는 근거가 확인되었다.
- 호환성 검증에서 확인한 수정이나 새로운 사실이 이전 검증에 미치는 영향과 필요한 재검증 결과가 기록되었다.
  교차 검증의 수행 여부 판단이 현재 작업 결과에도 유효하고, 수행한 검토가 있다면 그 결과도 유효하며,
  필요한 재검증이나 교차 검토가 남아 있지 않다.

### 허용 전이

- 모든 완료 조건과 그 근거가 확인되면 `completed` (완료)로 이동한다.
- 이전 검증의 근거나 교차 검증의 수행 여부 판단 및 검토 결과를 보완해야 한다면 해당 검증 단계로 돌아간다.
  여러 단계의 보완이 필요하면 생명 주기 순서에서 가장 먼저 위치한 단계로 돌아간다.
- 명세서의 요건과 구조 설계를 변경할 필요 없이 구현 결과를 수정하여 해결할 수 있으면 `implementation` (구현)으로 돌아간다.
- 공용 구성이나 CLI 전용 구성을 포함한 파일과 자료의 구조, 역할과 배치, 참조 방향 또는 의존 관계를 다시 설계해야 하면 `structure-design` (구조 설계)으로 돌아간다.
- 명세서에 정의된 지원 대상 CLI, CLI별 호환성 요건이나 허용할 차이의 범위 또는 검증 기준이 불명확하거나 변경이 필요하면 `requirements-definition` (요건 정의)으로 돌아간다.
- 해결할 문제, 대상 사용자와 사용 상황 또는 작업 대상 스킬이 수행할 범위와 제외 범위를 변경해야 하면 `problem-definition` (문제 정의)으로 돌아간다.
- 이전 단계로 돌아갈 사유가 없고 완료 조건을 충족하지 못하면, 부족한 내용과 원인 및 해결에 필요한 사항을 기록하고 `compatibility-validation` (호환성 검증)에 머문다.
- 전이 기록과 단계 갱신, 복귀 후 변경 영향 확인 및 필요한 재검증은 [생명 주기 운영 규칙의 단계 전이](../lifecycle.md#단계-전이)를 따른다.

### 산출물

- 지원 대상 CLI와 호환성 요건 및 검증 기준의 명세서 위치
- 각 CLI의 실행 환경과 호환성 검증 결과
- 지원 CLI의 공용 구성과 동작 확인 결과
- 명세서에서 허용한 CLI별 차이와 각 차이의 근거
- 명세서의 허용 범위를 벗어난 CLI별 동작 또는 구성의 차이와 그 영향
- 이전 단계에서 넘긴 미확인 사항과 의미 판단 항목의 확인 결과 및 근거
- 지원 대상 CLI별로 실행하지 못한 호환성 검증 항목과 결과를 판정하지 못한 항목 및 그 이유

## 명세서 기록 항목

공통 기록 형식과 시험 자료 정리 후의 기록은 [작업 내용과 결과](../specification.md#작업-내용과-결과)를 따른다.

### 지원 대상 CLI와 호환성 요건 및 검증 기준의 명세서 위치

- 대상 스킬 명세서에서 지원 대상으로 정의한 CLI와 해당 목록이 기록된 위치를 적고, 지원 범위를 제한하는 버전이나 실행 환경 조건이 있으면 함께 적는다.
- 지원 대상으로 정의한 각 CLI에 적용되는 호환성 요건이 정의된 명세서 항목과 그 위치를 적는다.
- 각 호환성 요건에 대응하는 검증 기준이 기록된 대상 스킬 명세서의 항목과 위치를 연결하여 적는다.
- 지원 대상으로 정의한 모든 CLI에 공통으로 적용되는 요건과 특정 CLI에만 적용되는 요건을 구분하여 적는다.
- 대상 스킬 명세서의 요건 정의에서 정한 구분에 따라 각 호환성 요건이 필수인지 선택인지 적는다.

### 각 CLI의 실행 환경과 호환성 검증 결과

- 각 CLI의 이름을 적고, 버전을 확인할 수 있으면 함께 적는다.
- 각 CLI에서 사용한 모델과 호환성 검증 결과에 영향을 줄 수 있는 설정을 확인할 수 있으면 적는다.
- 각 CLI의 작업 디렉토리와 스킬 설치 또는 등록 상태 및 실행에 필요한 의존 조건을 적는다.
- 플러그인은 대상 커밋/버전, 신규 설치 또는 업데이트 방식, 실제 반영 상태와 로드 위치를 적는다.
  설치를 사용자에게 이관했다면 이유, 요청한 작업과 재개 시 실제 확인 결과를 연결한다.
- 명세서에 정한 스킬의 사용 형태와 각 CLI에서 검증한 스킬의 실제 배치 또는 설치 경로를 적는다.
- 격리된 임시 작업 환경을 사용했다면 해당 환경의 위치와 실제 운영 환경으로부터 격리한 방법을 적는다.
- 같은 CLI에서도 사용 사례별 실행 환경이나 설정이 다르면, 각 사용 사례와 해당 환경 및 설정을 대응시켜 적는다.
- 각 CLI에서 검증한 사용 사례와 해당 사례로 검증한 호환성 요건 및 검증 기준을 대응시켜 적는다.
- 해당 사례의 확정 계획과 사용자 합의 근거, 변경 시 재확인 결과 및 실행 내역의 대조 위치를 연결한다.
- 신규 요건 또는 변경 내용과 영향 범위를 기준으로 해당 사례와 종료 지점을 선정한 근거를 적는다.
  기존 근거를 재사용한 항목은 CLI별 대상/환경/조건 및 변경 영향 대조 결과와 추가 실행 제외 이유를 적는다.
- 각 사용 사례에서 실제로 사용한 입력과 결과에 영향을 주는 사전 상태 및 실행 순서를 적는다.
- 각 CLI에서 실제로 검증하여 결과를 판정할 수 있는 호환성 요건의 결과를 `통과` 또는 `실패`로 적는다.
- 특정 요건이 해당 CLI에 적용되지 않으면 `해당 없음`으로 적고, 명세서의 적용 범위와 관련 규격에 따른 근거를 적는다.
- 실행하지 못했거나 결과를 판정하지 못한 경우에는 [지원 대상 CLI별로 실행하지 못한 호환성 검증 항목과 결과를 판정하지 못한 항목 및 그 이유](#지원-대상-cli별로-실행하지-못한-호환성-검증-항목과-결과를-판정하지-못한-항목-및-그-이유)의 작성 지침에 따라 대상 스킬 명세서의 해당 항목에 기록한다.
- 각 사용 사례에서 명세서의 작업 유형에 따라 기대한 스킬의 인식 상태와 실제 인식 결과를 구분하고, 명시 호출과 지원되는 자동 선택 중 검증한 방식 및 실제 호출 여부를 적는다.
- 명세서의 관련 요건과 검증 기준에 따른 기대 동작 및 결과를 실제로 관찰한 동작 및 결과와 구분하여 적는다.
- 각 판정이 해당 요건의 검증 기준을 충족하거나 위반한다고 판단한 이유를 적고, 해당 CLI의 실행 기록이나 결과물 등 확인 가능한 근거의 위치를 연결한다. 다른 CLI의 성공만으로 통과를 판정하지 않는다.

### 지원 CLI의 공용 구성과 동작 확인 결과

- 둘 이상의 지원 CLI에서 함께 사용하도록 설계한 스킬 파일, 설정, 참조 문서, 스크립트와 그 밖의 지원 자료를 적고, 각 구성의 경로와 해당 구성을 사용하는 CLI를 대응시켜 적는다.
- 각 공용 구성의 역할과 대응하는 요건이 정의된 대상 스킬 명세서의 구조 설계 항목과 위치를 연결한다.
- 해당 공용 구성을 사용하는 각 CLI에서 실제로 확인한 동작과 결과 및 설계한 역할과 관련 요건을 충족하는지 판단한 결과를 적고, 근거로 사용한 대상 스킬 명세서의 CLI별 호환성 검증 결과 위치를 연결한다.
- CLI별 확인 결과를 비교하여 공통 요건을 충족한 범위와 동작 또는 구성의 차이를 구분하여 적는다.
- 확인된 차이가 있으면 명세서의 허용 범위 안에 있는지 벗어나는지 구분하고, 대상 스킬 명세서에서 해당 차이와 근거를 기록한 항목의 위치를 연결한다.
- 공용 구성이 없으면 `없음`으로 적는다.

### 명세서에서 허용한 CLI별 차이와 각 차이의 근거

- 명세서에서 허용한 동작 또는 구성의 차이와 해당 CLI 및 허용 범위를 대응시켜 적는다.
- 각 차이의 허용 근거가 되는 명세서 항목과 그 위치를 적는다.
- CLI별 차이로 인해 전용 파일 또는 설정을 사용했다면, 실제로 호환되지 않는 사항과 공용 구성만으로 해당 CLI의 요건을 충족할 수 없는 이유 및 이를 뒷받침하는 근거를 적는다.
- CLI별 차이로 인해 전용 파일 또는 설정을 사용했다면 해당 경로와 적용 범위 및 역할이 정의된 대상 스킬 명세서의 구조 설계 항목과 위치를 연결한다.
- 각 차이에 대해 CLI별로 실제 확인한 동작 또는 구성이 명세서의 허용 범위와 일치하는지 판단한 결과를 적고, 근거로 사용한 대상 스킬 명세서의 CLI별 호환성 검증 결과 위치를 연결한다.
- 명세서에서 허용한 CLI별 차이가 없으면 `없음`으로 적는다.

### 명세서의 허용 범위를 벗어난 CLI별 동작 또는 구성의 차이와 그 영향

- 명세서의 허용 범위를 벗어난 차이가 확인된 CLI와 해당 사용 사례 또는 구성의 위치를 적는다.
- 명세서가 요구한 동작 또는 구성과 실제로 확인한 동작 또는 구성을 구분하고, 그 차이를 적는다.
- 허용 범위를 벗어났다고 판단한 근거가 되는 대상 스킬 명세서의 관련 요건, 허용 범위 및 검증 기준의 위치와 실제 확인 근거를 연결한다.
- 차이를 재현하는 데 필요한 입력, 실행 환경, 사전 상태 및 실행 순서를 적는다. 해당 조건이 대상 스킬 명세서의 CLI별 호환성 검증 결과에 기록되어 있으면 그 위치를 참조한다.
- 확인된 차이가 필수 요건, 안전 조건 및 지원 범위에 미치는 영향을 적는다.
- 확인된 차이를 해결하기 위해 필요한 보완 작업을 적고, 허용 전이를 기준으로 돌아갈 단계와 그 이유를 적는다.
- 명세서의 허용 범위를 벗어난 차이가 없으면 `없음`으로 적는다.

### 이전 단계에서 넘긴 미확인 사항과 의미 판단 항목의 확인 결과 및 근거

- 이전 단계에서 현재 단계에 확인하도록 지정한 미확인 사항과 의미 판단 항목을 적고, 각 항목이 기록된 대상 스킬 명세서의 단계와 위치를 연결한다.
- 각 항목에서 확인하거나 판단해야 할 내용, 관련 지원 CLI와 적용 범위, 적용할 개발 규격의 항목 및 명세서의 관련 요건과 검증 기준을 적는다.
- 각 항목을 확인한 방법과 검토 또는 검증한 대상을 적는다. CLI에서 실제로 실행하여 확인했다면 해당 CLI의 실행 환경과 사용 사례 및 결과가 기록된 대상 스킬 명세서의 위치를 연결한다.
- 실제로 확인한 사실, 판단 결과와 그 근거를 구분하여 적고, 근거 자료의 위치를 함께 적는다. 이전 단계에서 전달된 후보나 추정을 확인된 사실 또는 확정된 위반으로 간주하지 않는다.
- CLI별 확인 결과가 다르면 각 결과와 판단 근거를 구분하여 적는다. 한 CLI에서 확인한 결과만으로 다른 CLI에서도 해당 사항이 확인되었다고 판단하지 않는다.
- 같은 확인 결과가 대상 스킬 명세서의 다른 항목에 기록되어 있으면 해당 위치를 참조하고, 이 항목에서 판단할 사항과의 관계를 적는다.
- 확인하지 못했거나 판단을 마치지 못한 사항은 관련 CLI와 적용 범위, 그 이유와 해결에 필요한 정보, 작업 또는 사용자 판단을 적고, 현재 단계의 완료에 미치는 영향을 적는다.
- 확인 결과 보완이 필요하다면 필요한 작업과 보완할 단계를 허용 전이에 따라 판단하고 그 근거를 적는다.
- 이전 단계에서 현재 단계에 확인하도록 지정한 사항이 없으면 `없음`으로 적는다.

### 지원 대상 CLI별로 실행하지 못한 호환성 검증 항목과 결과를 판정하지 못한 항목 및 그 이유

- 각 지원 CLI에서 실행하지 못한 호환성 검증 항목과 관련 사용 사례 및 요건, 실행하지 못한 이유와 이를 확인한 근거를 대응시켜 적는다.
- 각 지원 CLI에서 실행했지만 결과를 판정하지 못한 항목과 관련 사용 사례 및 요건, 판정하지 못한 이유를 대응시켜 적는다.
- 결과를 판정하지 못한 경우에는 실제로 관찰한 동작과 결과 및 판정에 부족한 정보를 구분하여 적는다. 미실행이나 판정 불가를 임의로 `통과`, `실패` 또는 `해당 없음`으로 표시하지 않는다.
- 각 항목이 해당 CLI의 필수 호환성 요건과 관련되는지와 현재 단계의 완료에 미치는 영향을 적는다.
- 해당 항목이 현재 단계의 완료를 막지 않는다고 판단한다면, 명세서의 검증 기준과 현재 단계의 완료 조건에 따른 근거를 적는다.
- 검증을 실행하거나 결과를 판정하기 위해 필요한 작업, 입력, 실행 환경, 기능과 권한을 적고, 사용자 판단이 필요하면 해당 내용을 함께 적는다.
- 이전 단계에서 보완해야 한다면 허용 전이에 따라 돌아갈 단계와 그 근거를 적는다.
- 모든 지원 CLI에서 실행하지 못한 호환성 검증 항목과 결과를 판정하지 못한 항목이 모두 없으면 `없음`으로 적는다.
