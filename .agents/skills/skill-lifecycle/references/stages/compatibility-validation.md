# compatibility-validation (호환성 검증)

이 문서는 `skill-lifecycle` 생명 주기의 `compatibility-validation` (호환성 검증) 단계에 적용할
운영 규칙과 단일 명세서 기록 기준을 정의한다.

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `compatibility-validation`이다.
- `behavioral-validation` (동작 검증)의 완료 조건과 근거가 확인되었다.
- 명세서에 지원 대상으로 정의된 CLI와 각 CLI에 적용할 호환성 요건이 확인되었다.
- 지원 대상으로 정의된 각 CLI와 호환성 검증에 필요한 실행 환경의 사용 가능 여부가 확인되었다.
- CLI별 검증 결과를 비교할 공통 요건과 CLI별로 허용되는 차이가 명세서에서 확인되었다.

### 수행 작업

- 지원 대상으로 정의된 각 CLI가 작업 대상 스킬을 사용 가능한 대상으로 인식하는지와 실제 호출 결과를 확인한다.
- 지원 대상으로 정의된 모든 CLI에서 공통으로 적용되는 필수 요건과 안전 조건을 검증한다.
- 특정 CLI에만 적용되는 필수 요건이나 안전 조건이 있으면 해당 CLI에서 별도로 검증한다.
- 둘 이상의 지원 CLI에서 함께 사용하도록 설계한 스킬 파일, 설정, 참조 문서, 스크립트 및 그 밖의 지원 자료가 각 CLI에서 구조 설계에 정한 역할을 수행하는지 확인한다.
- Codex CLI 또는 Claude CLI 전용 파일이나 설정이 있으면, 공용 구성으로 처리할 수 없는 실제 차이와 그 근거가 있는지 확인한다.
- Codex CLI 또는 Claude CLI 전용 파일과 설정의 동작 및 적용 범위가 명세서와 구조 설계에 정의된 내용과 일치하는지 확인한다.
- CLI별 검증 결과를 비교하여 공통으로 동작하는 범위, 명세서에서 허용한 차이 및 호환되지 않는 사항을 구분한다.
- 명세서에서 지원 대상으로 정의하지 않은 CLI나 실행 환경의 동작을 작업 대상 스킬이 지원하는 기능으로 판정하지 않는다.
- 각 CLI에서 사용한 실행 환경, 사용 사례와 입력, 검증 결과 및 판정 근거를 CLI별로 구분하여 기록한다.

### 산출물

- 지원 대상 CLI와 호환성 요건의 명세서 위치
- 각 CLI의 실행 환경과 호환성 검증 결과
- 지원 CLI의 공용 구성과 동작 확인 결과
- 명세서에서 허용한 CLI별 차이와 각 차이의 근거
- 명세서의 허용 범위를 벗어난 CLI별 동작 또는 구성의 차이와 그 영향
- 지원 대상 CLI별로 호환성을 검증하지 못한 내역과 이유

### 완료 조건

- 명세서에서 지원 대상으로 정의한 모든 CLI에서 필수 호환성 요건이 검증되었다.
- 명세서에서 지원 대상으로 정의한 모든 CLI의 필수 호환성 요건이 통과했다.
- 둘 이상의 지원 CLI에서 사용하는 공용 구성이 있다면, 각 CLI에서 해당 구성이 동작하는 범위가 실제 실행 결과로 확인되었다.
- Codex CLI 또는 Claude CLI 전용 파일이나 설정이 있다면, 공용 구성으로 처리할 수 없는 실제 차이와 확인 가능한 근거에 따라 사용되었다.
- CLI별 동작과 구성의 차이가 명세서의 허용 범위 안에 있는지 벗어나는지 구분되었다.
- 명세서의 허용 범위를 벗어난 CLI별 동작 또는 구성의 차이가 없다.
- 각 CLI의 실행 환경, 검증한 사용 사례, 사용한 요청, 관찰한 결과 및 판정 근거가 기록되었다.
- 각 호환성 판정의 근거를 CLI별 실행 결과와 명세서의 요건까지 추적할 수 있다.
- 명세서에서 지원 대상으로 정의한 CLI 중 호환성 검증을 완료하지 못한 CLI가 없다.

### 허용 전이

- 완료 조건이 모두 충족되면 `cross-validation` (교차 검증)으로 이동한다.
- 이동할 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 `cross-validation`로 변경한다.
- 구현 결과가 명세서에 정의된 CLI별 호환성 요건과 일치하지 않으면 `implementation` (구현)으로 돌아간다.
- 공용 파일과 설정 및 지원 자료 또는 CLI 전용 파일과 설정의 역할이나 배치를 다시 설계해야 하면 `structure-design` (구조 설계)으로 돌아간다.
- 명세서에 정의된 지원 대상 CLI나 CLI별 호환성 요건을 변경해야 하면 `requirements-definition` (요건 정의)으로 돌아간다.
- 해결할 문제 또는 작업 대상 스킬이 수행할 범위와 제외 범위를 변경해야 하면 `problem-definition` (문제 정의)으로 돌아간다.
- 명세서에서 지원 대상으로 정의한 CLI나 호환성 검증에 필요한 실행 환경을 사용할 수 없으면 원인과 해결에 필요한 사항을 기록하고 현재 단계에 머문다.
- 이전 단계로 돌아갈 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 돌아갈 단계의 식별자로 변경한다.


## 명세서 기록 항목

### 지원 대상 CLI와 호환성 요건의 명세서 위치

- 작업 대상 스킬의 명세서에서 지원 대상으로 정의한 CLI를 적는다.
- 지원 대상으로 정의한 각 CLI에 적용되는 호환성 요건이 정의된 명세서 항목과 그 위치를 적는다.
- 지원 대상으로 정의한 모든 CLI에 공통으로 적용되는 요건과 특정 CLI에만 적용되는 요건을 구분하여 적는다.
- 각 호환성 요건을 필수 요건과 선택 요건으로 구분하여 적는다.

### 각 CLI의 실행 환경과 호환성 검증 결과

- 각 CLI의 이름을 적고, 버전을 확인할 수 있으면 함께 적는다.
- 각 CLI에서 사용한 모델과 호환성 검증 결과에 영향을 줄 수 있는 설정을 확인할 수 있으면 적는다.
- 각 CLI의 작업 디렉토리와 스킬 설치 또는 등록 상태 및 실행에 필요한 의존 조건을 적는다.
- 각 CLI에서 검증한 사용 사례와 해당 검증에 사용한 요청을 적는다.
- 각 CLI에서 확인한 호환성 요건의 판정 결과를 `통과`, `실패` 또는 `해당 없음`으로 적는다.
- 각 판정에 대해 실제로 관찰한 동작과 결과 및 판정 근거를 적는다.

### 지원 CLI의 공용 구성과 동작 확인 결과

- 둘 이상의 지원 CLI에서 공용으로 사용한 스킬 파일, 설정, 참조 문서, 스크립트와 그 밖의 지원 자료를 적는다.
- 각 공용 파일과 자료에 대해 구조 설계에서 정한 역할을 적는다.
- 각 지원 CLI에서 공용 구성을 사용하여 실제로 확인한 동작을 적는다.
- CLI별 확인 결과를 비교하여 공용 구성이 동일하게 동작한 범위와 그 근거가 된 실행 결과를 적는다.
- 공용 구성이 없으면 `없음`으로 적는다.

### 명세서에서 허용한 CLI별 차이와 각 차이의 근거

- 명세서에서 허용한 CLI별 동작 또는 구성의 차이를 적는다.
- 각 차이의 허용 근거가 되는 명세서 항목과 그 위치를 적는다.
- 각 차이를 공용 구성으로 처리할 수 없는 이유와 이를 뒷받침하는 근거를 적는다.
- CLI별 차이로 인해 전용 파일 또는 설정을 사용했다면 해당 경로와 적용 범위를 적는다.
- 명세서에서 허용한 CLI별 차이가 없으면 `없음`으로 적는다.

### 명세서의 허용 범위를 벗어난 CLI별 동작 또는 구성의 차이와 그 영향

- 명세서의 허용 범위를 벗어난 차이가 확인된 CLI와 해당 사용 사례를 적는다.
- 각 사용 사례에서 명세서가 요구한 동작 또는 구성과 실제로 확인한 차이를 적는다.
- 확인된 차이가 필수 요건, 안전 조건 및 지원 범위에 미치는 영향을 적는다.
- 확인된 차이를 해결하기 위해 돌아가야 하는 생명 주기 단계와 그 이유를 적는다.
- 명세서의 허용 범위를 벗어난 차이가 없으면 `없음`으로 적는다.

### 지원 대상 CLI별로 호환성을 검증하지 못한 내역과 이유

- 호환성을 검증하지 못한 CLI를 적는다.
- 호환성 검증에 필요했지만 사용할 수 없었던 실행 환경 또는 기능을 적는다.
- 호환성을 검증하지 못한 이유와 이를 확인한 근거를 적는다.
- 호환성 검증을 완료하는 데 필요한 환경, 기능 또는 작업을 적는다.
- 호환성을 검증하지 못한 CLI가 없으면 `없음`으로 적는다.
