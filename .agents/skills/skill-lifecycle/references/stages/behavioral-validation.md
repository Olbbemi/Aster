# behavioral-validation (동작 검증)

이 문서는 `skill-lifecycle` 생명 주기의 `behavioral-validation` (동작 검증) 단계에 적용할
운영 규칙과 단일 명세서 기록 기준을 정의한다.

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `behavioral-validation`이다.
- `mechanical-validation` (기계 검사)의 완료 조건과 근거가 확인되었다.
- 동작 검증 대상인 요건과 각 요건의 검증 가능한 완료 기준이 확인되었다.
- 동작 검증에 사용할 Codex CLI 또는 Claude CLI가 확인되었으며, 격리가 필요한 시험에는 사용할 임시 작업 환경이 준비되었다.

### 수행 작업

- 명세서의 요건을 기준으로 스킬이 호출되어야 하는 상황, 호출되지 않아야 하는 상황, 경계 조건 및 실패 상황을 검증할 사용 사례를 선정한다.
- 실제 사용 상황을 대표하는 입력으로 작업 대상 스킬이 사용 가능한 대상으로 인식되고 호출되는지 확인한다.
- 호출된 작업 대상 스킬이 명세서의 필수 동작을 수행하는지 확인한다.
- 사용자 확인 및 승인 조건과 중단 조건을 지키는지 확인한다.
- 작업 대상 스킬이 생성하거나 변경한 결과물이 명세서의 기대 결과와 스킬이 수행할 범위를 충족하는지 확인한다.
- 특정 문구나 제목이 일치하는지만 확인하지 않고, 실제로 관찰할 수 있는 동작과 결과를 검증한다.
- 동작 검증 과정에서 파일, 설정 또는 외부 상태가 변경될 수 있으면 격리된 임시 작업 환경을 사용한다.
- 작업 대상 스킬이 스크립트나 외부 구성 요소를 사용하면 해당 요소를 포함한 실제 실행 흐름을 검증한다.
- 각 사용 사례의 실행 환경, 입력, 관찰한 동작과 결과 및 요건별 판정을 기록한다.
- 실행 환경이나 조건의 문제로 검증하지 못한 사용 사례와 실행했지만 결과를 판정하지 못한 동작을 구분한다.

### 산출물

- 동작 검증을 수행한 사용 사례와 입력
- 동작 검증에 사용한 CLI와 실행 환경
- 작업 대상 스킬의 인식 여부와 호출 결과
- 요건별 동작 검증 결과와 판정 근거
- 동작 검증에서 발견한 실패와 재현 조건
- 실행하지 못한 사용 사례와 결과를 판정하지 못한 동작

### 완료 조건

- 작업 대상 스킬의 필수 요건마다 실제 사용 상황을 대표하는 사용 사례가 검증되었다.
- 스킬이 호출되어야 하는 사용 사례와 호출되지 않아야 하는 사용 사례에서 실제 호출 여부가 명세서의 호출 조건과 호출 제외 조건에 모두 일치했다.
- 명세서에 정의된 필수 요건의 동작과 기대 결과가 모두 동작 검증을 통과했다.
- 명세서에 사용자 확인 및 승인 조건이나 중단 조건이 있다면 작업 대상 스킬이 해당 조건을 모두 준수했다.
- 동작 검증에 사용한 CLI와 실행 환경이 기록되었으며, 결과에 영향을 줄 수 있는 조건을 확인했다면 함께 기록되었다.
- 동작 검증을 수행한 모든 사용 사례와 각 사례에 사용한 입력 및 기대 결과가 기록되었다.
- 작업 대상 스킬의 인식 여부와 각 사용 사례의 호출 결과가 기록되었다.
- 동작 검증에서 발견한 실패와 재현 조건이 누락되지 않았으며, 실패가 근거 없이 성공으로 판정되지 않았다.
- 각 요건의 통과 또는 실패 판정을 실제 실행에서 관찰한 동작과 결과로 추적할 수 있다.
- 필수 요건을 검증하기 위해 선정한 모든 사용 사례가 실행되었다.
- 실행하지 못한 사용 사례와 결과를 판정하지 못한 동작이 있다면 해당 항목과 이유가 기록되었다.
- 동작 검증 과정에서 실제 운영 파일, 사용자 데이터 또는 검증 범위 밖의 외부 상태를 변경하지 않았다.

### 허용 전이

- 완료 조건이 모두 충족되면 `compatibility-validation` (호환성 검증)으로 이동한다.
- 이동할 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 `compatibility-validation`로 변경한다.
- 구현 결과가 명세서에 정의된 동작 또는 기대 결과와 일치하지 않으면 `implementation` (구현)으로 돌아간다.
- 파일과 디렉토리의 구조, 구성 요소의 역할 또는 참조 관계 때문에 스킬이 의도한 대로 동작할 수 없으면 `structure-design` (구조 설계)으로 돌아간다.
- 동작 요건이나 검증 가능한 완료 기준이 불명확하거나 실제 사용 상황과 맞지 않으면 `requirements-definition` (요건 정의)으로 돌아간다.
- 해결할 문제, 대상 사용자와 사용 상황 또는 스킬이 수행할 범위와 제외 범위를 변경해야 하면 `problem-definition` (문제 정의)으로 돌아간다.
- 동작 검증에 필요한 실행 환경이나 기능을 사용할 수 없으면 원인과 해결에 필요한 사항을 기록하고 현재 단계에 머문다.
- 이전 단계로 돌아갈 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 돌아갈 단계의 식별자로 변경한다.


## 명세서 기록 항목

### 동작 검증을 수행한 사용 사례와 입력

- 각 사용 사례를 구분할 식별자와 해당 사례의 검증 목적을 적는다.
- 각 사용 사례와 해당 사례로 검증할 명세서의 요건을 대응시켜 적는다.
- 각 사용 사례를 스킬이 호출되어야 하는 상황, 호출되지 않아야 하는 상황, 경계 조건 또는 실패 상황으로 구분한다.
- 각 사용 사례에서 실제로 사용한 입력을 변경하거나 생략하지 않고 적는다.
- 명세서를 기준으로 각 입력에서 기대한 동작과 결과를 적는다.

### 동작 검증에 사용한 CLI와 실행 환경

- 동작 검증에 사용한 Codex CLI 또는 Claude CLI를 적고, 버전을 확인할 수 있으면 함께 적는다.
- 동작 검증에 사용한 모델과 결과에 영향을 줄 수 있는 모델 설정을 확인할 수 있으면 적는다.
- 동작 검증을 실행한 작업 디렉토리와 스킬의 설치 또는 등록 상태를 적는다.
- 격리된 임시 작업 환경을 사용했다면 해당 환경의 위치와 실제 운영 환경으로부터 격리한 방법을 적는다.
- 동작 검증에 사용한 외부 구성 요소와 설정 및 실행에 필요한 의존 조건을 적는다.
- 기록할 외부 구성 요소, 설정 또는 의존 조건이 없으면 `없음`으로 적는다.

### 작업 대상 스킬의 인식 여부와 호출 결과

- 동작 검증에 사용한 CLI가 작업 대상 스킬을 사용 가능한 대상으로 인식했는지 적는다.
- 작업 대상 스킬을 이름으로 명시하여 호출했는지, 사용자 요청에 따라 자동으로 선택되었는지 구분한다.
- 각 사용 사례에서 작업 대상 스킬이 명세서의 호출 조건과 호출 제외 조건에 따라 호출되거나 호출되지 않았는지 적는다.
- 인식 또는 호출 결과가 예상 결과와 다르면 실제로 관찰한 내용과 차이를 판정한 근거를 적는다.

### 요건별 동작 검증 결과와 판정 근거

- 검증한 각 요건과 해당 요건을 검증하는 데 사용한 사례를 대응시켜 적는다.
- 각 요건의 동작 검증 결과를 `통과` 또는 `실패`로 적는다.
- 명세서를 기준으로 기대한 동작과 실제로 관찰한 동작 및 결과를 구분하여 적는다.
- 동작 검증 결과를 판정하는 데 사용한 결과물의 경로, 실행 기록 또는 그 밖의 확인 가능한 근거를 적는다.
- 명세서에 사용자 확인 및 승인 조건이 있으면 작업 대상 스킬의 준수 결과를 적고, 없으면 `없음`으로 적는다.
- 명세서에 중단 조건이 있으면 작업 대상 스킬의 준수 결과를 적고, 없으면 `없음`으로 적는다.
- 재검증을 수행한 경우 이전 동작 검증 결과와 재검증 결과를 구분하여 적는다.

### 동작 검증에서 발견한 실패와 재현 조건

- 동작 검증에 실패한 사용 사례와 해당 사례가 검증한 요건을 대응시켜 적는다.
- 실제로 관찰한 동작 및 결과와 명세서를 기준으로 기대한 동작 및 결과의 차이를 적는다.
- 실패를 재현하는 데 필요한 입력, 실행 환경, 사전 조건 및 실행 순서를 적는다.
- 실패가 작업 대상 스킬의 동작, 결과 및 사용 범위에 미치는 영향을 적는다.
- 실패의 원인을 해결하기 위해 돌아가야 할 생명 주기 단계와 해당 단계를 선택한 이유를 적는다.
- 기록할 동작 검증 실패가 없으면 `없음`으로 적는다.

### 실행하지 못한 사용 사례와 결과를 판정하지 못한 동작

- 실행하지 못한 사용 사례와 해당 사례를 실행하지 못한 이유를 대응시켜 적는다.
- 실행했지만 결과를 판정하지 못한 동작과 해당 결과를 판정하지 못한 이유를 대응시켜 적는다.
- 실행하지 못한 사용 사례나 결과를 판정하지 못한 동작이 필수 요건과 관련되는지 적는다.
- 실행하지 못했거나 결과를 판정하지 못한 항목을 후속 검증하는 데 필요한 실행 환경, 기능 및 작업을 적는다.
- 실행하지 못한 사용 사례와 결과를 판정하지 못한 동작이 모두 없으면 `없음`으로 적는다.
