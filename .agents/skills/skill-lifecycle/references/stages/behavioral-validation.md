# behavioral-validation (동작 검증)

이 문서는 `skill-lifecycle` 생명 주기의 `behavioral-validation` (동작 검증) 단계에 적용할 운영 규칙과 단일 명세서 기록 기준을 정의한다.

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `behavioral-validation`이다.
- `mechanical-validation` (기계 검사)의 완료 조건과 근거가 확인되었다.
- 동작 검증 대상인 요건과 각 요건의 검증 가능한 완료 기준이 확인되었다.
- 명세서에 정의된 지원 대상 CLI 중 동작 검증에 사용할 CLI가 확인되었으며, 격리가 필요한 시험에는 사용할 임시 작업 환경이 준비되었다.

### 수행 작업

- [스킬 검증 규격](../../../../../standards/skills/skill-validation.md)과 명세서의 작업 유형 및 요건을 기준으로, 스킬이 호출되어야 하는 상황, 호출되지 않아야 하는 상황, 경계 조건 및 실패 상황을 검증할 사용 사례를 선정한다.
- 사용 사례를 선정할 때는 작업의 위험과 변경 영향 범위를 반영하고, 공용 자료를 사용하는 다른 스킬이나 외부 구성의 동작에 영향을 주었다면 필요한 검증 사례를 포함한다.
- 실행 전에 시험 입력이 실행 지시인지 처리할 시험 데이터인지와 실제 전달되는 역할, 적용 지침 및 실행 조건을 확인하고, 그 조건에서 기대 결과가 성립하는지 검토한다. 입력 작성자나 시험자의 의도만으로 시험 대상에 전달된 역할을 판단하지 않는다.
- 이전 단계에서 현재 단계에 확인하도록 지정한 미확인 사항과 의미 판단 항목을 확인하고, 관련 규격과 명세서의 기준에 따라 검토하거나 검증한 결과와 판단 근거를 기록한다.
- 실제 사용 상황을 대표하는 입력으로 작업 대상 스킬의 인식 여부와 호출 결과가 명세서에서 정한 기대 상태와 일치하는지 확인한다.
- 통합 또는 폐기로 더 이상 제공하지 않기로 한 스킬은 명세서에서 정한 인식 및 호출 상태가 실제 환경에 반영되었는지 확인한다.
- 스킬이 호출되어야 하는 사용 사례에서는 호출된 스킬이 명세서의 필수 동작을 수행하는지 확인한다.
- 사용자 확인 및 승인 조건과 중단 조건을 지키는지 확인한다.
- 각 사용 사례에서 관찰한 동작과 결과가 명세서의 기대 결과와 스킬이 수행할 범위 및 제외할 범위에 부합하는지 확인한다.
- 특정 문구나 제목이 일치하는지만 확인하지 않고, 실제로 관찰할 수 있는 동작과 결과를 검증한다.
- 명세서에 정의된 사용 형태에 따라 내부용 스킬은 저장소에서 직접 사용하는 환경에서, 플러그인 배포용 스킬은 설치된 플러그인 환경에서 동작을 검증한다.
- 동작 검증 과정에서 파일, 설정 또는 외부 상태가 변경될 수 있으면 격리된 임시 작업 환경을 사용한다.
- 작업 대상 스킬이 스크립트나 외부 구성 요소를 사용하면 해당 요소를 포함한 실제 실행 흐름을 검증한다.
- 각 사용 사례의 실행 환경, 입력, 관찰한 동작과 결과 및 요건별 판정을 기록한다.
- 동작 검증에서 실패가 발견되면 기대 결과와 실제 결과의 차이, 실패를 재현하는 데 필요한 조건과 영향을 기록한다.
- 기대와 다른 결과만으로 스킬 결함을 확정하지 않는다. 확인한 근거에 따라 스킬 결함, 시험 설계 문제와 환경 제약을 구분하고, 원인을 확인할 근거가 부족하면 미확정으로 남긴다. 원인이 미확정이라는 이유만으로 스킬 문구를 보강하거나 통과할 때까지 반복 실행하지 않는다.
- 실행 환경이나 조건의 문제로 검증하지 못한 사용 사례와 실행했지만 결과를 판정하지 못한 동작을 구분하고, 그 이유와 해결에 필요한 사항을 기록한다.

### 완료 조건

- 명세서의 작업 유형, 요건과 변경 영향 범위에 따라 선정한 실제 사용 사례로 현재 단계의 검증 대상인 필수 요건이 검증되었다.
- 각 사용 사례에서 스킬의 실제 인식 여부와 호출 결과가 명세서의 작업 유형에 따라 정의된 기대 상태, 호출 조건 및 호출 제외 조건에 일치했다.
- 현재 단계의 검증 대상인 필수 요건의 동작과 기대 결과가 모두 동작 검증을 통과했다.
- 이전 단계에서 현재 단계에 확인하도록 지정한 미확인 사항과 의미 판단 항목의 검토 또는 검증 결과와 근거가 기록되었으며, 현재 단계의 완료를 막는 미해결 사항이 없다.
- 명세서에 사용자 확인 및 승인 조건이나 중단 조건이 있다면 작업 대상 스킬이 해당 조건을 모두 준수했다.
- 동작 검증은 명세서에 정의된 지원 대상 CLI 중 선택한 CLI와 스킬의 사용 형태에 맞는 실행 환경에서 수행되었으며, 사용한 CLI, 실행 환경과 결과에 영향을 주는 조건이 기록되었다.
- 동작 검증을 수행한 모든 사용 사례와 각 사례에 사용한 입력, 기대 결과 및 시험 조건에서 그 기대 결과가 성립한다고 판단한 근거가 기록되었다.
- 작업 대상 스킬의 인식 여부와 각 사용 사례의 호출 결과가 기록되었다.
- 동작 검증에서 발견한 실패와 재현 조건이 누락되지 않았으며, 실패가 근거 없이 성공으로 판정되지 않았다.
- 각 요건의 통과 또는 실패 판정을 실제 실행에서 관찰한 동작과 결과로 추적할 수 있다.
- 필수 요건을 검증하기 위해 선정한 모든 사용 사례가 실행되었다.
- 실행하지 못한 사용 사례와 결과를 판정하지 못한 동작이 있다면 해당 항목, 이유와 해결에 필요한 사항이 기록되었으며, 해당 항목이 현재 단계의 완료를 막지 않는다는 근거가 확인되었다.
- 동작 검증 과정에서 실제 운영 파일, 사용자 데이터 또는 검증 범위 밖의 외부 상태를 변경하지 않았다.

### 허용 전이

- 모든 완료 조건과 그 근거가 확인되면 `compatibility-validation` (호환성 검증)으로 이동한다.
- 명세서의 요건과 구조 설계를 변경할 필요 없이 구현 결과를 수정하여 해결할 수 있으면 `implementation` (구현)으로 돌아간다.
- 파일과 디렉토리의 구조, 각 구성 요소의 역할과 배치, 참조 방향 또는 의존 관계를 다시 설계해야 하면 `structure-design` (구조 설계)으로 돌아간다.
- 동작 요건이나 검증 가능한 완료 기준이 불명확하거나 실제 사용 상황과 맞지 않으면 `requirements-definition` (요건 정의)으로 돌아간다.
- 해결할 문제, 대상 사용자와 사용 상황 또는 스킬이 수행할 범위와 제외 범위를 변경해야 하면 `problem-definition` (문제 정의)으로 돌아간다.
- 이전 단계로 돌아갈 사유가 없고 완료 조건을 충족하지 못하면, 부족한 내용과 원인 및 해결에 필요한 사항을 기록하고 `behavioral-validation` (동작 검증)에 머문다.
- 전이 기록과 단계 갱신, 복귀 후 변경 영향 확인 및 필요한 재검증은 [생명 주기 운영 규칙의 단계 전이](../lifecycle.md#단계-전이)를 따른다.

### 산출물

- 동작 검증을 수행한 사용 사례와 입력
- 동작 검증에 사용한 CLI와 실행 환경
- 작업 대상 스킬의 인식 여부와 호출 결과
- 요건별 동작 검증 결과와 판정 근거
- 이전 단계에서 넘긴 미확인 사항과 의미 판단 항목의 확인 결과 및 근거
- 동작 검증에서 발견한 실패와 재현 조건
- 실행하지 못한 사용 사례와 결과를 판정하지 못한 동작

## 명세서 기록 항목

### 동작 검증을 수행한 사용 사례와 입력

- 각 사용 사례를 구분할 식별자와 해당 사례의 검증 목적을 적는다.
- 명세서의 작업 유형, 작업의 위험과 변경 영향 범위를 기준으로 해당 사용 사례를 선정한 근거를 적는다.
- 각 사용 사례와 해당 사례로 검증할 명세서의 요건을 대응시켜 적는다.
- 각 사용 사례를 스킬이 호출되어야 하는 상황, 호출되지 않아야 하는 상황, 경계 조건 또는 실패 상황으로 구분한다.
- 각 사용 사례에서 실제로 사용한 입력을 변경하거나 생략하지 않고 적는다.
- 시험 입력이 실행 지시인지 시험 데이터인지와 실제 전달된 역할을 적고, 기대 결과에 영향을 주는 적용 지침과 실행 조건을 연결한다.
- 각 사용 사례의 결과에 영향을 주는 사전 상태와 실제 실행 순서를 적는다.
- 명세서를 기준으로 각 입력에서 기대한 동작과 결과를 적고, 위 시험 조건에서 그 기대가 성립한다고 판단한 근거를 적는다.

### 동작 검증에 사용한 CLI와 실행 환경

- 명세서에 정의된 지원 대상 CLI 중 실제로 동작 검증에 사용한 CLI를 적고, 버전을 확인할 수 있으면 함께 적는다.
- 동작 검증에 사용한 모델과 결과에 영향을 줄 수 있는 모델 설정을 확인할 수 있으면 적는다.
- 동작 검증을 실행한 작업 디렉토리와 스킬의 설치 또는 등록 상태를 적는다.
- 명세서에 정한 스킬의 사용 형태와 검증에 사용한 스킬의 실제 배치 또는 설치 경로를 적는다.
- 격리된 임시 작업 환경을 사용했다면 해당 환경의 위치와 실제 운영 환경으로부터 격리한 방법을 적는다.
- 동작 검증에 사용한 외부 구성 요소와 설정 및 실행에 필요한 의존 조건을 적는다.
- 사용 사례별로 사용한 CLI나 실행 환경이 다르다면, 각 사용 사례와 해당 CLI 및 실행 환경을 대응시켜 적는다.
- 기록할 외부 구성 요소, 설정 또는 의존 조건이 없으면 `없음`으로 적는다.

### 작업 대상 스킬의 인식 여부와 호출 결과

- 각 사용 사례에서 명세서의 작업 유형에 따라 기대한 스킬의 인식 상태와 실제 CLI가 해당 스킬을 인식한 결과를 구분하여 적는다.
- 각 사용 사례에서 명시 호출과 지원되는 자동 선택 중 어떤 방식을 검증했는지 적는다.
- 각 사용 사례에서 작업 대상 스킬이 명세서의 호출 조건과 호출 제외 조건에 따라 호출되거나 호출되지 않았는지 적는다.
- 인식 여부와 호출 결과가 기대 상태에 일치하는지 판단하고, 실제로 관찰한 내용과 판단 근거를 적는다. 차이가 있다면 기대 상태와 다른 내용을 명시한다.

### 요건별 동작 검증 결과와 판정 근거

- 검증한 각 요건과 해당 요건의 검증 기준 및 실제 검증에 사용한 사례를 대응시켜 적는다.
- 실제로 검증하여 결과를 판정할 수 있는 요건의 동작 검증 결과를 `통과` 또는 `실패`로 적는다.
- 실행하지 못했거나 결과를 판정하지 못한 경우에는 [실행하지 못한 사용 사례와 결과를 판정하지 못한 동작](#실행하지-못한-사용-사례와-결과를-판정하지-못한-동작)의 작성 지침에 따라 대상 스킬 명세서의 해당 항목에 기록한다.
- 명세서를 기준으로 기대한 동작과 실제로 관찰한 동작 및 결과를 구분하여 적는다.
- 관찰한 동작과 결과가 해당 요건의 검증 기준을 충족하거나 위반한다고 판단한 이유를 적고, 판단에 사용한 결과물의 경로, 실행 기록 또는 그 밖의 확인 가능한 근거를 연결한다.
- 명세서에 사용자 확인 및 승인 조건이 있으면 작업 대상 스킬의 준수 결과를 적고, 없으면 `없음`으로 적는다.
- 명세서에 중단 조건이 있으면 작업 대상 스킬의 준수 결과를 적고, 없으면 `없음`으로 적는다.
- 재검증을 수행했다면 대상과 이유, 기존 시험과 달라진 조건 및 결과를 적고 현재 유효한 판정과 근거를 갱신한다. 기존 관찰과 당시 판정은 근거 자료에 보존한다. 재검증 통과만으로 기존 실패의 원인이 밝혀졌거나 해결됐다고 판단하지 않으며, 확인된 범위와 미확정 사항을 구분한다.

### 이전 단계에서 넘긴 미확인 사항과 의미 판단 항목의 확인 결과 및 근거

- 이전 단계에서 현재 단계에 확인하도록 지정한 미확인 사항과 의미 판단 항목을 적고, 각 항목이 기록된 대상 스킬 명세서의 단계와 위치를 연결한다.
- 각 항목에서 확인하거나 판단해야 할 내용과 적용할 개발 규격의 항목 및 명세서의 관련 요건을 적는다.
- 각 항목을 확인한 방법과 검토 또는 검증한 대상을 적는다. 실제 사용 사례로 확인했다면 해당 사례를 연결한다.
- 실제로 확인한 사실, 판단 결과와 그 근거를 구분하여 적고, 근거 자료의 위치를 함께 적는다. 이전 단계에서 전달된 후보나 추정을 확인된 사실 또는 확정된 위반으로 간주하지 않는다.
- 같은 확인 결과가 대상 스킬 명세서의 다른 항목에 기록되어 있으면 해당 위치를 참조하고, 이 항목에서 판단할 사항과의 관계를 적는다.
- 확인하지 못했거나 판단을 마치지 못한 사항은 그 이유와 해결에 필요한 정보, 작업 또는 사용자 판단을 적고, 현재 단계의 완료에 미치는 영향을 적는다.
- 확인 결과 보완이 필요하다면 필요한 작업과 보완할 단계를 허용 전이에 따라 판단하고 그 근거를 적는다.
- 이전 단계에서 현재 단계에 확인하도록 지정한 사항이 없으면 `없음`으로 적는다.

### 동작 검증에서 발견한 실패와 재현 조건

- 동작 검증에 실패한 사용 사례와 해당 사례가 검증한 요건을 대응시켜 적는다.
- 실제로 관찰한 동작 및 결과와 명세서를 기준으로 기대한 동작 및 결과의 차이를 적는다.
- 실패를 재현하는 데 필요한 입력, 실행 환경, 사전 조건 및 실행 순서를 적는다.
- 실패가 작업 대상 스킬의 동작, 결과 및 사용 범위에 미치는 영향을 적는다.
- 실패 원인이 스킬 결함, 시험 설계 문제 또는 환경 제약에 해당하는지 확인한 근거와 함께 적는다. 여러 요인이 확인되면 함께 기록하고, 확인하지 못한 원인은 미확정으로 적는다. 관찰된 불일치와 스킬 결함 여부의 판단을 구분한다.
- 원인 판단에 따라 필요한 보완 작업이나 추가로 확인할 사항을 적고, 이전 단계의 보완이 필요하면 허용 전이를 기준으로 해당 단계와 이유를 적는다.
- 기록할 동작 검증 실패가 없으면 `없음`으로 적는다.

### 실행하지 못한 사용 사례와 결과를 판정하지 못한 동작

- 실행하지 못한 사용 사례와 해당 사례로 검증하려던 요건 및 실행하지 못한 이유를 대응시켜 적는다.
- 실행했지만 결과를 판정하지 못한 동작과 해당 사용 사례, 관련 요건 및 판정하지 못한 이유를 대응시켜 적는다.
- 결과를 판정하지 못한 경우에는 실제로 관찰한 동작과 결과 및 판정에 부족한 정보를 구분하여 적는다. 판정하지 못한 결과를 임의로 `통과` 또는 `실패`로 표시하지 않는다.
- 각 항목이 현재 단계의 검증 대상인 필수 요건과 관련되는지와 현재 단계의 완료에 미치는 영향을 적는다.
- 해당 항목이 현재 단계의 완료를 막지 않는다고 판단한다면, 완료 조건과 명세서의 검증 기준에 따른 근거를 적는다.
- 검증을 실행하거나 결과를 판정하기 위해 필요한 작업, 입력, 실행 환경, 기능과 권한을 적고, 사용자 판단이 필요하면 해당 내용을 함께 적는다.
- 이전 단계에서 보완해야 한다면 허용 전이에 따라 돌아갈 단계와 그 근거를 적는다.
- 실행하지 못한 사용 사례와 결과를 판정하지 못한 동작이 모두 없으면 `없음`으로 적는다.
