# mechanical-validation (기계 검사)

이 문서는 `skill-lifecycle` 생명 주기의 `mechanical-validation` (기계 검사) 단계에 적용할
운영 규칙과 단일 명세서 기록 기준을 정의한다.

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `mechanical-validation`이다.
- `implementation` (구현)의 완료 조건과 근거가 확인되었다.
- 기계 검사 대상인 파일, 디렉토리 및 설정과 적용할 개발 규격이 식별되었다.
- 명세서의 검증 대상이 기계적으로 판정할 항목과 사람 또는 AI 에이전트의 판단이 필요한 항목으로 구분되었다.
- 사용할 검사 도구와 검사 명령을 실행하는 데 필요한 조건이 확인되었다.

### 수행 작업

- 작업 대상 스킬에 적용할 기계 검사 항목을 개발 규격에서 확인한다.
- 파일과 디렉토리의 구조 및 이름, 프론트매터와 필수 파일의 존재 여부를 검사한다.
- 파일 간 참조 경로가 유효하고 참조 대상이 존재하는지 검사한다.
- 같은 정보를 중복하여 정의한 파일, 미완성 자리 표시자 및 어디에서도 사용하거나 참조하지 않는 파일이 있는지 검사한다.
- 스크립트가 있으면 구문 오류와 실행 가능 여부를 검사한다.
- 같은 입력에 일관된 결과가 요구되는 스크립트는 결과가 재현되는지도 검사한다.
- Codex CLI 또는 Claude CLI가 공식 검사 도구를 제공하면 해당 CLI에서 사용하는 파일과 설정에 적용한다.
- 실행한 검사 명령, 검사 대상, 검사 결과 및 실패한 경우의 판정 근거를 기록한다.
- 사람 또는 AI 에이전트의 의미 판단이 필요한 항목은 기계 검사 결과만으로 통과하거나 실패했다고 판정하지 않는다.

### 산출물

- 작업 대상 스킬의 기계 검사 항목과 적용 여부
- 기계 검사에 사용한 명령과 각 명령의 적용 대상
- 기계 검사별 통과 또는 실패 결과
- 검사 실패가 발생한 위치와 위반한 개발 규격
- 기계 검사로 판정할 수 없는 항목과 그 이유

### 완료 조건

- 작업 대상 스킬에 적용하기로 한 모든 기계 검사 항목이 실행되었다.
- 필수로 지정된 기계 검사가 모두 통과했다.
- 실행한 모든 검사 명령과 각 명령의 적용 대상 및 실행 조건이 기록되었다.
- 실행한 모든 기계 검사의 통과 또는 실패 결과와 판정 근거가 기록되었다.
- 검사 실패가 발생했다면 실패 위치와 위반한 개발 규격의 항목이 기록되었다.
- 발생한 검사 실패가 누락되지 않았으며, 근거와 승인 없이 예외로 처리되지 않았다.
- 각 검사 결과가 판정한 개발 규격의 항목을 추적할 수 있다.
- 기계 검사로 판정할 수 없는 항목과 그 이유가 기록되었으며, 해당 항목을 확인할 후속 검증 단계가 지정되었다.
- 검사 과정에서 검사 스크립트를 새로 작성하거나 수정했다면, 해당 스크립트가 의도한 대상을 검사하고 올바른 결과를 반환하는지 확인되었다.

### 허용 전이

- 완료 조건이 모두 충족되면 `behavioral-validation` (동작 검증)으로 이동한다.
- 이동할 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 `behavioral-validation`로 변경한다.
- 구현 결과가 명세서와 일치하지 않으면 `implementation` (구현)으로 돌아간다.
- 파일과 디렉토리의 구조 또는 각 구성 요소의 역할과 배치에 문제가 있으면 `structure-design` (구조 설계)으로 돌아간다.
- 검사 대상인 요건이 불명확하거나 검증 가능한 완료 기준에 문제가 있으면 `requirements-definition` (요건 정의)으로 돌아간다.
- 검사 도구를 실행할 수 없거나 검사 결과를 판정할 수 없으면 원인과 해결에 필요한 사항을 기록하고 현재 단계에 머문다.
- 이전 단계로 돌아갈 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 돌아갈 단계의 식별자로 변경한다.


## 명세서 기록 항목

### 작업 대상 스킬의 기계 검사 항목과 적용 여부

- 작업 대상 스킬에 해당하는 기계 검사 항목, 각 항목의 적용 여부 및 판정 기준을 적는다.
- 각 기계 검사 항목의 판정 기준이 근거로 삼은 개발 규격과 해당 규격의 위치를 적는다.
- 각 검사 항목이 필수인지 선택인지 구분한다.
- 선택 검사는 작업 대상 스킬에 적용했는지 여부와 적용하거나 적용하지 않은 이유를 적는다.

### 기계 검사에 사용한 명령과 각 명령의 적용 대상

- 기계 검사에 실제로 사용한 명령을 변경하거나 생략하지 않고 적는다.
- 각 명령을 적용한 파일, 디렉토리 및 설정을 명령별로 적는다.
- 각 명령을 실행한 작업 디렉토리와 명령 실행에 필요한 조건을 적는다.
- 명령에서 사용한 검사 도구의 이름을 적고, 버전을 확인할 수 있으면 함께 적는다.

### 기계 검사별 통과 또는 실패 결과

- 각 기계 검사 항목의 판정 결과를 `통과` 또는 `실패`로 적는다.
- 통과 또는 실패를 판정한 근거로 명령이 반환한 종료 코드와 주요 결과 내용을 적는다.
- 검사 과정에서 새로 작성하거나 수정한 검사 스크립트가 있으면 해당 스크립트의 동작을 확인한 방법과 결과를 적는다.
- 재검사를 수행한 경우 이전 검사 결과와 재검사 결과를 구분하여 적는다.
- 검사 실패를 예외로 처리한 경우 해당 검사, 예외 처리 근거, 승인 주체 및 승인 내용을 적는다.

### 검사 실패가 발생한 위치와 위반한 개발 규격

- 검사에 실패한 파일, 디렉토리 또는 설정의 위치를 적는다.
- 실패 위치를 세부적으로 확인할 수 있으면 해당 줄 번호나 설정 항목을 적는다.
- 검사 실패가 위반한 개발 규격의 항목과 해당 항목의 위치를 적는다.
- 검사 실패의 원인을 해결하기 위해 돌아가야 할 생명 주기 단계와 그 이유를 적는다.
- 기록할 검사 실패가 없으면 `없음`으로 적는다.

### 기계 검사로 판정할 수 없는 항목과 그 이유

- 기계 검사만으로 통과 또는 실패를 판정할 수 없는 검증 항목을 적는다.
- 검사 도구의 부재, 실행 조건의 미충족 또는 의미 판단의 필요 등 기계 검사로 판정할 수 없는 이유를 적는다.
- 기계 검사로 판정할 수 없는 항목을 확인할 후속 검증 단계와 해당 단계를 선택한 이유를 적는다.
- 기계 검사로 판정할 수 없는 항목이 없으면 `없음`으로 적는다.
