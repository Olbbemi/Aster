# mechanical-validation (기계 검사)

구현 결과가 동작 검증에 들어가기 위한 기계 판정 기준을 충족했는지 확인하는 단계다.
구현된 스킬과 변경 영향 범위에 필요한 검사를 선정하고, 현재 유효한 결과를 근거로 완료 여부를 판단한다.
다른 단계에서 수행한 자료 검사만으로 이 단계가 완료되지는 않는다.

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `mechanical-validation`이다.
- `implementation` (구현)의 완료 조건과 근거가 확인되었다.
- 기계 검사 대상인 파일, 디렉토리 및 설정과 적용할 개발 규격이 식별되었다.
- 명세서에 정의된 검증 대상 요건과 각 요건의 검증 기준이 확인되었다.

### 수행 작업

1. 명세서의 구현 결과와 변경 영향 범위를 바탕으로 검사 대상을 식별한다.
   아래 [검사 대상과 적용 조건](#검사-대상과-적용-조건),
   [스킬 검증 규격](../../../../../standards/skills/skill-validation.md)과 명세서의 검증 기준에 따라
   각 항목의 적용 여부, 필수 여부와 판정 기준을 정한다.
2. 적용할 항목별로 기존 결과를 확인하고 [기존 결과 재사용](#기존-결과-재사용) 조건에 대조한다.
   유효한 결과가 없거나 변경의 영향을 받은 항목은 실행 대상으로 정한다.
3. [검사 스크립트 사용 가이드라인](../../../../../tools/guidelines.md)에 따라 실행 대상의 검사기를 호출한다.
   입력, 명령, 종료 코드와 결과를 확보하며 실행하지 못한 항목과 이유를 구분한다.
4. 이번 실행 결과와 재사용한 근거를 현재 검사 대상 및 판정 기준에 대조하고 명세서에 기록한다.
   실패, 미실행과 미판정을 통과로 처리하지 않으며, 필수 항목이 충족되지 않으면 이 단계를 완료하지 않는다.
5. 검사에서 확인한 변경 영향과 동작 검증으로 넘길 사항을
   [초안 작성과 보완](../scenario-validation.md#초안-작성과-보완)에 따라 시나리오 초안에 반영한다.
6. 남은 사항이 완료를 막는지와 필요한 후속 작업을 정리하고 완료 조건 및 허용 전이에 따라 다음 행동을 판단한다.
   의미 판단이 필요한 항목은 확인할 후속 검증 단계에 연결한다.
   사용자 판단이나 승인이 필요한 사항은 기존 요청과 합의의 조건에 따라 근거를 제시하고 확인받는다.

#### 검사 대상과 적용 조건

이 표는 기계 검사 단계에서 아래 검사기를 적용할 조건을 정의한다.
스크립트 경로와 사용 안내는 [검사 매핑](../../../../../tools/mappings.md#skill-lifecycle)에서 찾고,
실제 입력과 명령, 판정 범위 및 한계는 개별 안내를 따른다.

| 검사기 | 대상과 적용 조건 |
| --- | --- |
| `check_structure.py` | 생성하거나 유지하는 대상 스킬의 최종 `SKILL.md`와 프론트매터. 통합 후 유지하는 스킬은 포함하고 제거한 스킬에는 파일 존재를 요구하지 않음 |
| `check_references.py` 일반 모드 | 생성하거나 유지하는 대상 스킬의 Markdown 참조. 공용 자료 변경이나 대상 제거가 다른 자료의 참조에 영향을 주면 남아 있는 해당 참조도 검사 범위에 포함 |
| `check_distribution.py` | 생성하거나 유지하는 대상 플러그인의 manifest, marketplace 등록과 합의한 기대 배포 구성. 일부 스킬만 제거하고 플러그인은 유지하는 경우 포함. 내부용 스킬에는 적용하지 않으며 동일 플러그인의 같은 구성은 한 번만 확인 |

명세서와 개발 규격에서 추가로 정한 기계 판정 항목이 있으면 함께 선정한다.
대상 스킬의 스크립트 구문이나 구현에 포함된 도식 등 변경 영향이 있는 항목은 해당 기준에 따라 확인한다.
기존 검사기로 판정할 수 없는 필수 항목이나 제거된 대상의 남은 등록 등 도구 범위 밖의 확인은
부족한 검사 수단과 후속 작업을 명시한다.
위 표의 검사 통과만으로 나머지 항목까지 통과했다고 판단하지 않는다.

작업 명세서 형식, 설계 도식, 시나리오 계획/결과와 완료 보고서의 검사는
매핑에서 연결한 각 자료의 지침이 정한 시점에 수행한다.
해당 자료가 이번 구현 또는 변경 영향 범위에 포함되면 필요한 결과를 함께 확인할 수 있다.
등록된 검사기 전부를 기계 검사 단계에서 일괄 실행하거나,
후속 단계에서 만들 결과 기록과 완료 보고서를 미리 작성하여 검사하지 않는다.

#### 기존 결과 재사용

다음 조건을 모두 확인한 항목은 기존 통과 결과를 재사용한다.

- 원래 검사한 대상과 범위, 입력/명령, 실행 환경과 결과 및 판정 근거를 확인할 수 있다.
- 대상의 내용/경로, 참조와 배포 구성, 입력/설정, 적용 규격과 검사기 및 실행 환경을 현재 상태와 대조했다.
  검사 결과에 영향을 주는 변경이 없고 현재 필요한 범위를 충족한다.
- 현재 필수 조건에 대응하는 판정이 통과이며, 실패/미실행/미판정을 통과 근거로 사용하지 않는다.

유효성을 확인할 수 없거나 범위가 부족하면 해당 항목을 실행한다.
일부만 변경되었으면 영향을 받는 검사 대상에 다시 적용하며,
검사기가 필요한 범위를 부분 실행할 수 없으면 지원하는 검사 단위로 실행한다.
명세서에는 기존 근거의 위치와 현재도 유효한 이유를 연결하고 이번에 실행한 결과와 구분한다.

### 완료 조건

- 검사 대상과 항목별 적용 여부, 필수 여부, 판정 기준 및 적용 제외의 근거가 정리되었다.
- 적용하기로 한 모든 기계 검사에 이번 실행 또는 위 재사용 조건을 충족하는 결과가 확보되었다.
  필수 검사가 모두 판정 기준을 충족했으며 필수 항목에 실패, 미실행과 미판정이 남아 있지 않다.
- 실행 정보와 항목별 결과 및 근거가 아래 명세서 기록 항목에 따라 명세서에 기록되어 해당 개발 규격과 요건을 추적할 수 있으며,
  실패, 미실행과 미판정이 누락되거나 근거 없이 통과 또는 적용 제외로 처리되지 않았다.
- 남은 확인 사항이 현재 단계 완료를 막지 않는 근거와 필요한 후속 작업이 정리되었으며, 의미 판단이 필요한 항목은 확인할 후속 검증 단계에 연결되었다.
- 검사에서 확인한 영향이 시나리오 초안에 반영되었고 사용자와 검토할 미정 사항이 정리되었다.

### 허용 전이

- 모든 완료 조건과 그 근거가 확인되면 [사용자 검토와 확정](../scenario-validation.md#사용자-검토와-확정)을 진행한다.
  `current_stage` 값을 제외한 동작 검증의 진입 조건이 확인되면 `behavioral-validation`으로 이동한다.
  사용자 확정이나 환경 준비를 기다리는 동안에는 기계 검사 완료와 실제 시험 미실행 상태를 구분하여 기록한다.
- 명세서의 요건과 구조 설계를 변경할 필요 없이 구현 결과를 수정하여 해결할 수 있으면 `implementation` (구현)으로 돌아간다.
- 파일과 디렉토리의 구조, 각 구성 요소의 역할과 배치, 참조 방향 또는 의존 관계를 다시 설계해야 하면 `structure-design` (구조 설계)으로 돌아간다.
- 검사 대상인 요건이 불명확하거나 검증 가능한 완료 기준에 문제가 있으면 `requirements-definition` (요건 정의)으로 돌아간다.
- 이전 단계로 돌아갈 사유가 없고 완료 조건을 충족하지 못하면, 부족한 내용과 원인 및 해결에 필요한 사항을 기록하고 `mechanical-validation` (기계 검사)에 머문다.
- 전이 기록과 단계 갱신, 복귀 후 변경 영향 확인 및 필요한 재검증은 [생명 주기 운영 규칙의 단계 전이](../lifecycle.md#단계-전이)를 따른다.

### 산출물

명세서에 검사별 핵심 결과, 판정과 한계를 유지한다.
상세 명령/환경, 실패와 재시험 근거가 필요할 때만 [검증 문서](../work-data.md#기록-루트-안의-배치)로 분리한다.
원시 출력은 로컬 자료로 구분하고 판정의 필수 근거를 원시 로그에만 남기지 않는다.

- 작업 대상 스킬의 기계 검사 항목과 적용 여부
- 기계 검사에 사용한 명령과 각 명령의 적용 대상
- 기계 검사별 통과 또는 실패 결과
- 검사 실패가 발생한 위치와 위반한 개발 규격
- 실행하지 못한 검사와 실행했지만 결과를 판정하지 못한 항목
- 의미 판단이 필요한 항목과 그 이유 및 확인할 후속 단계

## 명세서 기록 항목

### 작업 대상 스킬의 기계 검사 항목과 적용 여부

- 검토한 기계 검사 항목과 각 항목의 검사 대상, 적용 여부 및 판정 기준을 적는다.
- 명세서의 작업 유형과 구현 단계에 기록된 변경 대상 및 영향 범위를 바탕으로, 각 검사 항목과 대상을 선정하거나 적용에서 제외한 이유를 적는다.
- 각 기계 검사 항목의 판정 기준에 적용한 개발 규격의 항목과 위치 및 명세서의 관련 요건을 적는다.
- 각 검사 항목이 필수인지 선택인지 구분하고, 그 판단의 근거가 되는 개발 규격 또는 명세서의 내용을 적는다.
- 적용 대상으로 정했지만 도구나 실행 조건의 문제로 실행하지 못한 검사는 적용 제외와 구분한다.

### 기계 검사에 사용한 명령과 각 명령의 적용 대상

- 기계 검사에 실제로 사용한 명령은 변경하거나 생략하지 않고 보존한다.
  별도 근거 자료에 보존했다면 [작업 내용과 결과](../specification.md#작업-내용과-결과)에 따라 명세서에서 원문 위치를 연결하고 중복해서 복사하지 않는다.
- 각 명령으로 수행한 기계 검사 항목과 해당 명령을 적용한 파일, 디렉토리 및 설정을 명령별로 적는다.
- 각 명령을 실행한 작업 디렉토리와 실제로 사용한 입력, 설정 및 실행 환경을 적는다.
  결과에 영향을 주는 실행 조건이 있다면 함께 적는다.
- 기존 결과를 재사용했다면 원래 실행 시점과 근거 위치, 이번 검사에 대응하는 범위와 재사용 이유를 적는다.
  기존 명령과 결과를 중복 복사하지 않으며 이번에 다시 실행한 것으로 기록하지 않는다.
- 명령에서 사용한 검사 도구의 이름을 적고, 버전을 확인할 수 있으면 함께 적는다.

### 기계 검사별 통과 또는 실패 결과

- 실제로 실행하여 결과를 판정할 수 있는 기계 검사 항목의 판정 결과를 `통과` 또는 `실패`로 적는다.
- 각 검사 항목에 사용한 명령을 연결하고, 해당 명령이 반환한 종료 코드와 주요 결과 내용을 적는다.
  그 결과가 해당 항목의 판정 기준을 충족하거나 위반한다고 판단한 근거를 함께 적는다.
- 이번 실행과 기존 결과 재사용을 구분하고, 재사용한 결과도 현재의 대상과 기준을 충족하는 근거에 연결한다.
- 재검사를 수행했다면 재검사 대상과 이유 및 결과를 적고, 현재 유효한 판정 결과와 근거를 갱신한다.
- 검사 실패를 통과 또는 적용 제외로 변경했다면, 해당 검사와 변경 전후의 판단 및 개발 규격과 명세서의 판정 기준에 따른 변경 근거를 적는다.

### 검사 실패가 발생한 위치와 위반한 개발 규격

- 실패한 검사 항목과 해당 파일, 디렉토리 또는 설정의 위치를 적고, 확인할 수 있으면 줄 번호나 설정 항목을 함께 적는다.
- 검사 실패를 판정할 때 적용한 개발 규격의 항목이나 명세서의 판정 기준을 적고, 해당 내용을 확인할 수 있는 문서 위치를 함께 적는다.
  실제 검사 결과가 그 기준을 어떻게 위반했는지 설명한다.
- 검사 실패의 원인과 필요한 보완 작업을 적고, 허용 전이를 기준으로 보완할 단계와 그 이유를 적는다.
- 기록할 검사 실패가 없으면 `없음`으로 적는다.

### 실행하지 못한 검사와 실행했지만 결과를 판정하지 못한 항목

- 기계 검사 대상으로 정한 항목 중 실행하지 못한 검사와 실행했지만 결과를 판정하지 못한 항목을 구분하고, 각 항목의 검사 대상을 적는다.
- 검사 도구의 부재, 실행 조건의 미충족 또는 판정에 필요한 결과와 근거의 부족 등 각 항목을 실행하거나 판정하지 못한 이유를 적는다.
- 실행했지만 결과를 판정하지 못한 경우에는 실제로 관찰한 결과와 판정에 부족한 정보를 구분하여 적는다.
  판정하지 못한 결과를 임의로 `통과` 또는 `실패`로 표시하지 않는다.
- 해당 항목이 현재 단계의 완료를 막는지 판단하고, 관련 완료 조건과 판단 근거를 적는다.
  완료를 막지 않는다고 판단한 경우에도 그 근거를 명시한다.
- 실행 또는 판정에 필요한 작업, 입력, 도구, 실행 환경과 권한을 적고, 사용자 판단이 필요하면 해당 내용을 함께 적는다.
  이전 단계에서 보완해야 한다면 허용 전이에 따라 돌아갈 단계와 그 근거를 적는다.
- 실행하지 못한 검사와 실행했지만 결과를 판정하지 못한 항목이 없으면 `없음`으로 적는다.

### 의미 판단이 필요한 항목과 그 이유 및 확인할 후속 단계

- 기계 검사만으로 통과 또는 실패를 확정할 수 없어 사람 또는 AI 에이전트의 의미 판단이 필요한 항목을 적는다.
- 각 항목에서 판단해야 할 내용과 기계 검사만으로 판단할 수 없는 이유를 적는다.
- 에이전트가 검사 결과를 검토하면서 의미 판단이 필요하다고 본 사항이 있으면, 해당 위치와 실제로 관찰한 사실을 적는다.
  추가 판단이 필요한 사항과 이미 확정된 위반을 구분한다.
- 각 항목을 확인할 후속 검증 단계와 해당 단계를 선택한 이유를 적고, 판단에 필요한 자료와 근거의 위치를 함께 적는다.
- 동작 검증으로 넘기는 항목은 해당 항목을 반영한 시나리오 초안의 사례와 위치를 연결한다.
- 각 항목의 판단을 후속 단계에서 수행해도 현재 단계의 완료 조건을 충족할 수 있는 근거를 적는다.
  검사 도구나 실행 조건의 문제로 실행 또는 판정하지 못한 기계 검사를 의미 판단 항목으로 바꾸어 넘기지 않는다.
- 의미 판단이 필요한 항목이 없으면 `없음`으로 적는다.
