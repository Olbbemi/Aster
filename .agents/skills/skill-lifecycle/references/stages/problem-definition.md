# problem-definition (문제 정의)

이 문서는 `skill-lifecycle` 생명 주기의 `problem-definition` (문제 정의) 단계에 적용할 운영 규칙과 단일 명세서 기록 기준을 정의한다.

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `problem-definition`이다.
- 스킬을 생성, 변경, 통합 또는 폐기할 필요가 제기되었다.

### 수행 작업

- 스킬을 통해 해결해야 할 문제를 확인한다.
- 스킬을 사용하는 주체와 스킬이 사용되는 상황을 확인한다.
- 문제가 해결되었을 때 기대하는 결과를 확인한다.
- 요청한 스킬의 생성, 변경, 통합 또는 폐기가 문제 해결에 필요한지 판단한다.
- 스킬이 수행할 범위와 제외할 범위를 구분한다.
- 문제 정의 단계에서 확인할 수 없는 사항이 있다면 확인할 내용과 후속 단계를 구분한다.

### 완료 조건

- 스킬을 통해 해결해야 할 문제가 요건을 정의할 수 있을 정도로 구체화되었다.
- 스킬을 사용하는 주체와 스킬이 사용되는 상황 및 기대하는 결과가 확인되었다.
- 요청한 작업 유형이 문제 해결에 필요한지 판단되었고 그 근거가 기록되었다.
- 스킬이 수행할 범위와 제외할 범위가 요건을 정의할 수 있을 정도로 구분되었다.
- 문제 정의의 완료를 막는 미확인 사항이 없다.
- 만약 후속 단계에서 확인할 사항이 남아 있다면 그 내용과 확인할 단계가 명시되었다.

### 허용 전이

- 요청한 작업 유형이 문제 해결에 필요하고 완료 조건을 모두 충족하면 `requirements-definition` (요건 정의)으로 이동한다.
- 이동할 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 `requirements-definition`로 변경한다.
- 요청한 작업 유형이 문제 해결에 필요하지 않다고 판단되면 그 근거를 기록하고 작업을 종료한다.
- 요청한 작업 유형의 필요성이 아직 판단되지 않았거나, 필요한 작업이지만 완료 조건을 충족하지 못하면 `problem-definition` (문제 정의)에 머물며 부족한 내용을 확인하거나 보완한다.

### 산출물

- 스킬을 통해 해결해야 할 문제
- 스킬을 사용하는 주체와 스킬이 사용되는 상황
- 문제가 해결되었을 때 기대하는 결과
- 요청한 스킬의 생성, 변경, 통합 또는 폐기가 필요한지에 대한 판단과 근거
- 스킬이 수행할 범위와 제외할 범위
- 후속 단계에서 확인할 사항

## 명세서 기록 항목

### 스킬을 통해 해결해야 할 문제

- 현재 존재하는 불편이나 결함 또는 필요한 기능의 부족을 적는다.
- 해당 문제가 대상 주체와 관련 작업에 미치는 영향을 적는다.
- 근거를 확인한 내용과 아직 근거를 확인하지 못한 내용을 구분하여 적는다.
- 구체적인 구조, 구현 방식 또는 해결 방법은 이 항목에 적지 않는다.
- 구체적인 해결 방법을 정하지 않은 상태에서도 필요한 요건을 정의할 수 있도록 문제가 설명되어야 한다.

### 스킬을 사용하는 주체와 스킬이 사용되는 상황

- 스킬 사용을 요청하는 주체와 스킬의 지침을 수행하는 주체를 구분하여 적는다.
- 스킬이 사용되는 작업과 상황을 적는다.
- 만약 요청 주체나 수행 주체에 따라 스킬이 사용되는 상황이 다르면 그 차이를 적는다.
- 구체적인 호출 방법, 사용할 도구와 모델 또는 파일 구조는 이 항목에 적지 않는다.
- 요청 주체와 수행 주체 및 스킬이 사용되는 작업과 상황이 요건을 정의할 수 있을 정도로 구체적으로 설명되어야 한다.

### 문제가 해결되었을 때 기대하는 결과

- 문제가 해결되었을 때 현재 상태가 어떻게 달라져야 하는지 적는다.
- 그 변화가 대상 주체와 관련 작업에 미칠 기대 효과를 적는다.
- 기대 결과가 여러 개라면 각 내용을 구분하여 적는다.
- 세부 기능 요건, 구현 방법 또는 검증 절차는 이 항목에 적지 않는다.
- 후속 요건을 정의하고 이후에 문제가 해결되었는지 판단할 수 있을 정도로 기대 결과가 구체적으로 설명되어야 한다.

### 요청한 스킬의 생성, 변경, 통합 또는 폐기가 필요한지에 대한 판단과 근거

- 프론트매터에 지정된 작업이 문제 해결에 필요한지 판단한 결과를 적는다.
- 판단의 근거가 된 요청 내용과 확인한 사실을 적는다.
- 만약 다른 작업 유형과 구분해야 한다면 해당 유형을 선택하지 않은 이유를 적는다.
- 구체적인 구현 방법이나 세부 작업 절차는 이 항목에 적지 않는다.
- 요청한 작업의 진행 또는 종료를 결정할 수 있을 정도로 판단과 근거가 설명되어야 한다.

### 스킬이 수행할 범위와 제외할 범위

- 문제를 해결하기 위해 스킬의 수행 범위에 포함해야 할 작업을 적는다.
- 스킬의 수행 범위에서 제외해야 할 작업을 적는다.
- 만약 다른 스킬, 도구, AI 에이전트 또는 사람이 수행할 작업이 있다면 스킬의 수행 범위와 구분하여 적는다.
- 구체적인 구현 방법, 파일 구조 또는 도구 선택은 이 항목에 적지 않는다.
- 후속 단계에서 개별 요건의 포함 여부를 판단할 수 있을 정도로 수행 범위와 제외 범위가 구체적으로 설명되어야 한다.

### 후속 단계에서 확인할 사항

- 문제 정의의 완료를 막지는 않지만 후속 단계에서 확인해야 할 사항을 적는다.
- 각 사항을 확인하지 못한 이유와 확인할 후속 단계를 함께 적는다.
- 각 사항과 관련하여 현재까지 확인한 사실과 근거가 있다면 함께 적는다.
- 문제 정의를 완료하는 데 반드시 필요한 사항은 후속 단계로 넘기지 않고 현재 단계에서 확인한다.
- 후속 단계에서 확인할 사항이 없다면 `없음`이라고 적는다.
- 이 항목의 전체 내용은 후속 단계에서 확인 작업을 이어갈 수 있을 정도로 구체적으로 설명되어야 한다.
