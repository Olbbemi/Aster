# implementation (구현)

이 문서는 `skill-lifecycle` 생명 주기의 `implementation` (구현) 단계에 적용할
운영 규칙과 단일 명세서 기록 기준을 정의한다.

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `implementation`이다.
- `structure-design` (구조 설계)의 완료 조건과 근거가 확인되었다.
- 새로 만들거나 수정, 이동 또는 제거할 파일과 디렉토리가 식별되었고, 각 대상이 담당할 역할이 정해졌다.
- 구현할 각 요건과 이를 담당할 파일 또는 구성 요소의 대응 관계가 확인되었다.
- 구현에 필요한 파일 변경이 사용자와 합의한 작업 범위에 포함된다.

### 수행 작업

- 명세에 기록된 요건과 구조 설계에 따라 `SKILL.md`와 지원 파일 및 디렉토리를 새로 만들거나 수정, 이동 또는 제거한다.
- 핵심 지침과 조건부 상세 지침을 구조 설계에서 정한 역할과 위치에 맞게 배치한다.
- 반복해서 수행해야 하거나 동일한 입력에 일관된 처리가 필요한 작업은 스크립트로 구현한다.
- 공용 자료는 구조 설계에서 정한 Aster 저장소 전체 또는 플러그인 단위의 관리 위치에 한 번만 정의하고, 이를 사용하는 구성 요소에서 참조한다.
- Codex CLI와 Claude CLI에서 공용 구성을 사용할 수 없다는 차이와 근거가 확인된 경우에만, 해당 차이를 처리하는 CLI 전용 파일이나 설정을 작성한다.
- 작업 대상 스킬을 등록하거나 실행하기 위해 플러그인 매니페스트와 같은 스킬 외부 구성을 변경해야 한다면, 필요한 범위만 변경한다.
- 구현 과정에서 명세 또는 구조 설계와 실제 구현이 맞지 않는 사항을 식별하고, 해당 문제를 보완해야 할 이전 단계를 구분한다.
- 구현 중 발견한 문제를 해결하기 위해 이전 단계에서 확정한 명세 내용을 임의로 변경하지 않는다.
- 변경이 필요하면 돌아갈 단계와 그 근거를 명세서에 기록한다.

### 산출물

- 새로 만들거나 수정, 이동 또는 제거한 파일과 디렉토리
- 구현하지 못한 요건과 구현하지 못한 이유 및 보완할 단계

### 완료 조건

- 명세에서 구현 대상으로 정한 모든 요건이 구현 결과에 반영되었다.
- 각 변경 대상이 구조 설계에서 정한 역할, 위치와 처리 방법에 따라 변경되었다.
- 같은 규칙이나 정보가 여러 파일에 중복하여 정의되지 않았으며, 해당 내용을 변경할 기준 위치가 하나로 유지되었다.
- 미완성 자리 표시자, 사용되지 않는 파일 및 빈 디렉토리가 남아 있지 않다.
- 반복해서 수행해야 하거나 동일한 입력에 일관된 처리가 필요한 작업이 있다면 해당 작업이 스크립트로 구현되었다.
- Codex CLI 또는 Claude CLI 전용 구성은 구조 설계에 기록된 원인과 판단 근거에 따라 작성되었다.
- 스킬 외부 구성의 변경은 작업 대상 스킬을 등록하거나 실행하는 데 필요한 범위로 제한되었다.
- 구현하지 못한 필수 요건이 남아 있지 않다.
- 구현 과정에서 새로 만들거나 수정, 이동 또는 제거한 파일과 디렉토리가 식별되었다.
- 각 파일 및 디렉토리의 변경 내용이 그 변경으로 구현한 명세 항목과 대응하는지 확인되었다.

### 허용 전이

- `implementation` (구현)의 모든 완료 조건과 근거가 확인되면 `mechanical-validation` (기계 검사)으로 이동한다.
- 이동할 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 `mechanical-validation`로 변경한다.
- 파일이나 자료의 역할 또는 배치를 다시 설계해야 하면 `structure-design` (구조 설계)으로 돌아간다.
- 정의된 요건을 변경하거나 보완해야 하면 `requirements-definition` (요건 정의)으로 돌아간다.
- 해결할 문제나 스킬이 수행할 범위와 제외 범위를 변경해야 하면 `problem-definition` (문제 정의)으로 돌아간다.
- 필요한 변경 권한이나 입력이 없거나 다른 완료 조건을 충족하지 못하면 `implementation` (구현)에 머물며 부족한 내용을 확인하고 보완한다.
- 이전 단계로 돌아갈 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 돌아갈 단계의 식별자로 변경한다.


## 명세서 기록 항목

### 새로 만들거나 수정, 이동 또는 제거한 파일과 디렉토리

- 새로 만들거나 수정, 이동 또는 제거한 파일과 디렉토리의 경로를 적는다.
- 각 파일과 디렉토리에 수행한 작업을 생성, 수정, 이동 또는 제거로 구분한다.
- 각 파일 및 디렉토리의 변경 내용이 어떤 명세 항목을 구현했는지 적는다.
- 각 변경 대상이 구조 설계에서 정한 어떤 자료 종류와 역할에 해당하는지 적는다.
- 각 변경 대상이 구조 설계에서 정한 작업 대상 스킬, Aster 저장소 전체 또는 플러그인 단위의 관리 범위 중 어디에 해당하는지 적는다.
- 각 변경 대상의 CLI 적용 범위를 구조 설계에 따라 적는다.
- 적용 범위는 공용, Codex CLI 전용, Claude CLI 전용 또는 구분 없음으로 표시한다.
- 스크립트를 새로 만들거나 수정했다면 구조 설계에서 정한 사용 조건과 수행 작업대로 작성되었는지 적는다.
- 결과물용 자료를 새로 만들거나 수정했다면 구조 설계에서 정한 사용 대상과 사용 방법에 맞게 작성되었는지 적는다.
- 공용 자료를 새로 만들거나 수정했다면 이를 사용하는 구성 요소와 해당 내용을 변경할 기준 위치가 구조 설계와 일치하는지 적는다.
- CLI 전용 구성을 새로 만들거나 수정했다면 구조 설계에 기록된 원인과 판단 근거에 따라 작성되었는지 적는다.
- 스킬 외부 구성을 변경했다면 변경 대상과 내용을 적고, 해당 변경이 구조 설계에서 정한 스킬 등록에 필요한 범위 또는 실행에 필요한 범위에 포함되는지 적는다.
- 파일이나 디렉토리를 이동했다면 이동 전 경로와 이동 후 경로를 적는다.
- 파일이나 디렉토리를 제거했다면 제거한 이유를 적는다.

### 구현하지 못한 요건과 구현하지 못한 이유 및 보완할 단계

- 구현하지 못한 요건을 적는다.
- 각 요건을 구현하지 못한 이유를 적는다.
- 구현하지 못한 각 요건이 필수 요건인지 구분한다.
- 구현하지 못한 각 요건이 현재 단계의 완료를 막는지 적는다.
- 구현하지 못한 각 요건을 보완할 단계와 해당 단계에서 필요한 작업을 적는다.
- 구현하지 못한 요건이 없으면 `없음`으로 적는다.
