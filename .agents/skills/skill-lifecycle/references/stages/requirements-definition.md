# requirements-definition (요건 정의)

이 문서는 `skill-lifecycle` 생명 주기의 `requirements-definition` (요건 정의) 단계에 적용할 운영 규칙과 단일 명세서 기록 기준을 정의한다.

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `requirements-definition`이다.
- `problem-definition` (문제 정의)의 완료 조건과 근거가 확인되었다.
- 요청한 작업의 필요성과 스킬이 수행할 범위 및 제외할 범위가 확인되었다.
- 요건을 정의하는 데 필요한 스킬 사용 주체, 스킬이 필요한 상황과 기대 결과가 확인되었다.

### 수행 작업

- 스킬의 사용 형태를 내부용 또는 플러그인 배포용으로 정한다.
- 지원 대상 CLI를 정하고, [스킬 검증 규격의 하네스 및 배포 검증](../../../../../standards/skills/skill-validation.md#하네스-및-배포-검증)에서 대상 스킬에 해당하는 항목을 확인하여 각 CLI에 적용할 호환성 요건을 정의한다.
- 스킬을 호출해야 하는 조건과 호출하지 않아야 하는 조건을 정의한다.
- 스킬 실행에 필요한 입력과 기대 결과를 정의한다.
- 반드시 수행해야 하는 동작과 에이전트가 재량으로 판단할 수 있는 동작을 구분한다.
- 스킬 실행에 적용되는 제약과 실패 조건을 정의한다.
- 사용자 확인 또는 승인이 필요한 조건을 정의한다.
- [스킬 검증 규격](../../../../../standards/skills/skill-validation.md)을 확인하여 각 요건의 충족 여부를 검증할 수 있는 기준을 정의한다.
- 확인하지 못한 사항과 사용자의 판단이 필요한 사항을 식별하고, 현재 단계에서 해결할 사항과 후속 단계에서 확인할 사항을 구분한다.

### 완료 조건

- 스킬의 사용 형태가 내부용 또는 플러그인 배포용으로 정해졌다.
- 지원 대상 CLI와 각 CLI에 적용할 호환성 요건이 정의되었다.
- 스킬 호출 조건과 호출 제외 조건이 실제 요청에서 판단할 수 있을 정도로 구체적으로 정의되었다.
- 스킬 실행에 필요한 입력, 각 입력의 필수 여부와 입력값이 충족해야 할 조건이 정의되었다.
- 필요한 입력이 없거나 불충분할 때의 대응과 기대 결과의 제공 형태 및 충족 기준이 정의되었다.
- 스킬 실행 중 지켜야 하는 제약과 스킬이 작업을 수행할 수 없는 조건이 정의되었다.
- 실패 조건이 발생했을 때 스킬이 취할 대응과 사용자에게 알릴 내용이 정의되었으며, 대체 방식이 있다면 그 사용 조건과 사용자 승인 조건이 정의되었다.
- 사용자 확인 및 승인이 필요한 작업과 조건, 요청 시점 및 사용자가 응답하지 않거나 승인을 거부했을 때의 처리 방식이 정의되었다.
- 각 요건이 `problem-definition` (문제 정의)에서 확인한 스킬의 수행 범위와 기대 결과에 연결되었다.
- 반드시 수행해야 하는 동작과 에이전트가 재량으로 판단할 수 있는 동작이 구분되었다.
- 정의된 요건 사이에 충돌이 없다.
- [스킬 검증 규격](../../../../../standards/skills/skill-validation.md)에서 대상 스킬에 해당하는 항목을 반영하여 각 요건의 충족 여부를 검증할 기준이 정의되었다.
- 요건 정의의 완료를 막는 미확인 사항이나 사용자 판단이 필요한 사항이 없다.
- 만약 후속 단계에서 확인할 사항이 남아 있다면 그 내용, 현재 단계에서 확인하지 못한 이유와 확인할 단계가 명시되었다.

### 허용 전이

- 모든 완료 조건과 그 근거가 확인되면 `existing-configuration-review` (기존 구성 확인)로 이동한다.
- 이동할 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 `existing-configuration-review`로 변경한다.
- 요건이 `problem-definition` (문제 정의)에서 확인한 문제, 스킬의 수행 범위 또는 기대 결과와 맞지 않으면 `problem-definition`으로 돌아간다.
- `problem-definition` (문제 정의)으로 돌아갈 사유가 없고 완료 조건을 충족하지 못하면 `requirements-definition` (요건 정의)에 머물며 부족한 내용을 확인하고 보완한다.
- 이전 단계로 돌아갈 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 돌아갈 단계의 식별자로 변경한다.

### 산출물

- 스킬의 사용 형태(내부용 또는 플러그인 배포용)
- 지원 대상 CLI와 각 CLI에 적용할 호환성 요건
- 스킬 호출 조건과 호출 제외 조건
- 스킬 실행에 필요한 입력과 기대 결과
- 반드시 수행해야 하는 동작과 에이전트가 재량으로 판단할 수 있는 동작
- 스킬 실행에 적용되는 제약, 실패 조건과 대응
- 사용자 확인 및 승인 조건
- 각 요건의 충족 여부를 검증할 수 있는 기준
- 확인하지 못한 사항과 사용자의 판단이 필요한 사항

## 명세서 기록 항목

### 스킬의 사용 형태(내부용 또는 플러그인 배포용)

- 내부용 또는 플러그인 배포용 중 선택한 사용 형태를 적는다.
- 문제 정의에서 확인한 사용 주체와 사용 상황을 근거로 해당 형태를 선택한 이유를 적는다.
- [저장소 배치 규격](../../../../../standards/repository-layout.md)의 "스킬 배치"를 기준으로 선택한 사용 형태와 프론트매터의 `target_path`가 일치하는지 적는다. 일치하지 않으면 조정이 필요한 내용과 이유를 적는다.

### 지원 대상 CLI와 각 CLI에 적용할 호환성 요건

- 지원할 CLI를 적고, 지원 범위를 제한하는 버전이나 실행 환경 조건이 있다면 함께 적는다.
- [스킬 검증 규격의 하네스 및 배포 검증](../../../../../standards/skills/skill-validation.md#하네스-및-배포-검증)에서 대상 스킬에 해당하는 항목을 기준으로, 각 CLI에서 충족해야 하는 동작 조건을 적는다.
- 모든 지원 CLI에 공통으로 적용할 요건과 특정 CLI에만 적용할 요건을 구분한다.
- 각 호환성 요건이 필수인지 선택인지 구분한다.
- CLI별로 다른 동작을 허용한다면 허용할 차이의 범위와 근거를 적는다. 허용할 차이가 없으면 `없음`으로 적는다.
- 이 문서의 [각 요건의 충족 여부를 검증할 수 있는 기준](#각-요건의-충족-여부를-검증할-수-있는-기준)에 있는 작성 지침에 따라, 대상 스킬 명세서의 "각 요건의 충족 여부를 검증할 수 있는 기준" 항목에 각 호환성 요건의 검증 기준을 적고 해당 요건과 대응시킨다.

### 스킬 호출 조건과 호출 제외 조건

- 스킬을 호출해야 하는 요청과 상황을 적는다.
- 스킬을 호출하지 않아야 하는 요청과 상황을 적는다.
- 호출 여부가 혼동될 수 있는 인접 스킬이나 작업이 있다면 구분 기준을 적는다.
- 각 조건을 실제 요청에서 판단할 수 있을 정도로 구체적으로 설명한다.

### 스킬 실행에 필요한 입력과 기대 결과

- 스킬 실행에 필요한 입력을 적는다.
- 스킬 실행에 필요한 각 입력이 필수인지 선택 사항인지 구분하고, 입력값이 충족해야 할 조건을 적는다.
- 스킬 실행에 필요한 입력이 없거나 불충분할 때의 대응을 적는다.
- 스킬 실행을 통해 얻어야 하는 기대 결과를 적는다.
- 기대 결과가 어떤 형태로 제공되어야 하는지와 결과가 충족되었는지 판단할 기준을 적는다.

### 반드시 수행해야 하는 동작과 에이전트가 재량으로 판단할 수 있는 동작

- 스킬이 반드시 수행해야 하는 동작을 적는다.
- 반드시 수행해야 하는 각 동작이 어떤 조건에서 필요한지 적는다.
- 스킬을 실행하는 AI 에이전트가 상황에 따라 수행 여부나 방법을 판단할 수 있는 동작을 적는다.
- 스킬을 실행하는 AI 에이전트가 재량으로 판단할 때 적용해야 하는 기준과 허용 범위를 적는다.
- 사용자가 명시적으로 요청한 경우에만 수행할 수 있는 동작을 적는다.
- 확인 가능한 근거가 있을 때만 수행할 수 있는 동작을 적는다.

### 스킬 실행에 적용되는 제약, 실패 조건과 대응

- 스킬 실행 중 반드시 지켜야 하는 제약을 적는다.
- 현재 환경, 도구, 권한 또는 외부 상태로 인해 스킬이 작업을 수행할 수 없는 조건을 적는다.
- 각 실패 조건이 발생했을 때 스킬이 취할 대응을 적는다. 이전 작업 단계로 돌아가야 한다면 복귀 조건, 돌아갈 단계와 재개에 필요한 조건을 함께 적는다.
- 실패 조건이 발생했을 때 사용자에게 알려야 하는 내용을 적는다.
- 대체 방식이 있다면 해당 방식과 사용 조건을 적고, 필요한 사용자 승인 조건은 [사용자 확인 및 승인 조건](#사용자-확인-및-승인-조건) 항목을 참조한다.

### 사용자 확인 및 승인 조건

- 스킬을 실행하는 AI 에이전트가 작업을 계속하기 전에 사용자 확인을 받아야 하는 조건을 적는다.
- 삭제, 기존 내용의 덮어쓰기, 외부 시스템 변경 또는 배포 등의 작업 중 사용자 승인이 필요한 작업과 그 조건을 적는다.
- 스킬을 실행하는 AI 에이전트가 사용자에게 확인과 승인을 요청해야 하는 시점을 적는다.
- 사용자가 확인 요청에 응답하지 않거나 승인을 거부했을 때, 스킬을 실행하는 AI 에이전트가 중단하거나 대기해야 하는 작업과 계속 수행할 수 있는 범위를 적는다.

### 각 요건의 충족 여부를 검증할 수 있는 기준

- 각 요건에 대응하는 검증 기준과 그 기준에 반영한 [스킬 검증 규격](../../../../../standards/skills/skill-validation.md)의 항목을 연결하여 적는다.
- 검증을 수행하는 주체가 관찰하거나 확인해야 하는 결과를 적는다.
- 각 요건의 충족 여부를 검증하는 데 사용할 검사 방법과 판정에 필요한 근거를 적는다.
- 요건을 충족한 것으로 판정할 조건을 적는다.
- 검증 기준을 정하지 못한 요건은 요건 정의의 완료를 막는 미확인 사항으로 구분한다.
- 이 문서의 [확인하지 못한 사항과 사용자의 판단이 필요한 사항](#확인하지-못한-사항과-사용자의-판단이-필요한-사항)에 있는 작성 지침에 따라,
    해당 요건과 이유 및 보완에 필요한 사항을 대상 스킬 명세서의 "확인하지 못한 사항과 사용자의 판단이 필요한 사항" 항목에 적는다.

### 확인하지 못한 사항과 사용자의 판단이 필요한 사항

- 현재까지 확인하지 못한 사항을 적는다.
- 사용자의 판단이 필요한 사항을 적는다.
- 각 사항을 확인하거나 판단해야 하는 이유를 적는다.
- 각 사항이 요건 정의의 완료를 막는지 구분한다.
- 현재 단계에서 해결해야 한다면 필요한 정보 또는 사용자 질문을 적는다.
- 후속 단계에서 확인할 수 있다면 그 이유와 확인할 단계를 적는다.
- 해당 사항이 없다면 `없음`이라고 적는다.
