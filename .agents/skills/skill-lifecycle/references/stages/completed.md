# 완료 단계 초안

## 단계 운영 규칙

### 진입 조건

- 명세서 프론트매터의 `current_stage`가 `completed`이다.
- `compatibility-validation` (호환성 검증)의 완료 조건과 근거가 확인되었다.
- `cross-validation` (교차 검증)의 완료 조건과 근거가 확인되었다.
- 이전 생명 주기 단계에서 다시 수행하도록 지정된 작업이나 검증이 남아 있지 않다.

### 수행 작업

- 명세서에 기록된 모든 생명 주기 단계의 완료 조건과 근거를 최종 확인한다.
- 해결되지 않은 미확인 사항과 남은 위험이 완료 판단을 허용하는지 확인한다.
- 작업 결과가 `problem-definition` (문제 정의)에서 정한 목적과 범위를 충족하는지 확인한다.
- 작업 결과가 `requirements-definition` (요건 정의)에서 정한 완료 기준을 충족하는지 확인한다.
- 생명 주기의 완료 여부에 대한 판단과 그 근거를 명세서에 기록한다.
- 완료 조건을 모두 충족하면 명세서의 현재 단계를 `completed` (완료)로 변경한다.

### 산출물

- 생명 주기의 완료 여부에 대한 판단
- 생명 주기의 완료 여부를 판단한 근거
- 완료 여부를 판단하는 시점에 남아 있는 미확인 사항과 위험
- 완료 조건을 충족한 경우 `completed` (완료)로 변경된 현재 단계

### 완료 조건

- 명세서에 기록된 모든 생명 주기 단계의 완료 조건과 근거가 확인되었다.
- 다시 수행해야 할 작업이나 검증이 남아 있지 않다.
- 남아 있는 미확인 사항과 위험이 명세서에 기록되었다.
- 남아 있는 미확인 사항과 위험을 수용하고 완료할 수 있는 근거가 명세서에 기록되었다.
- 작업 결과가 `problem-definition` (문제 정의)에서 정한 목적과 범위를 충족한다.
- 작업 결과가 `requirements-definition` (요건 정의)에서 정한 완료 기준을 충족한다.
- 생명 주기가 완료되었다는 판단과 그 근거가 명세서에 기록되었다.

### 허용 전이

- 완료 조건을 모두 충족하면 `completed` (완료) 상태를 유지한다.
- 완료 조건이 충족되지 않았거나 완료 후 기존 전제가 더 이상 성립하지 않는 사실이 확인되면, 재수행이 필요한 생명 주기 단계로 돌아간다.
- 갱신, 통합 또는 폐기처럼 새로운 작업이 시작되면 기존 생명 주기를 되돌리지 않고 새로운 생명 주기를 `problem-definition` (문제 정의)부터 시작한다.
- 새로운 생명 주기를 시작할 때는 새 명세서 프론트매터의 `current_stage`를 `problem-definition`으로 설정한다.
- 이전 단계로 돌아갈 때는 전이 사유와 근거를 기록한 뒤 명세서 프론트매터의 `current_stage`를 돌아갈 단계의 식별자로 변경한다.


## 명세서 기록 항목

### 생명 주기의 완료 여부에 대한 판단

- 생명 주기의 완료 조건을 모두 충족하여 완료할 수 있는지 판단한 결과를 적는다.
- 완료할 수 없다고 판단했다면 충족하지 못한 완료 조건과 다시 수행해야 할 작업이나 검증을 적는다.
- 이전 단계로 돌아가야 한다면 돌아갈 단계와 해당 단계를 선택한 근거를 적는다.

### 생명 주기의 완료 여부를 판단한 근거

- 명세서에 기록된 각 생명 주기 단계의 완료 조건과 근거를 최종 확인한 결과를 적는다.
- 각 단계의 완료 조건을 확인하는 데 사용한 명세서 항목, 파일 또는 검증 결과의 위치를 적는다.
- 작업 결과가 `problem-definition` (문제 정의)에서 정한 목적과 범위를 충족하는지와 그 판단 근거를 적는다.
- 작업 결과가 `requirements-definition` (요건 정의)에서 정한 완료 기준을 충족하는지와 그 판단 근거를 적는다.
- 다시 수행해야 할 작업이나 검증이 남아 있는지 확인한 결과와 그 근거를 적는다.

### 완료 여부를 판단하는 시점에 남아 있는 미확인 사항과 위험

- 완료 여부를 판단하는 시점에 남아 있는 미확인 사항과 위험을 적는다.
- 각 미확인 사항과 위험이 작업 결과와 완료 판단에 미치는 영향을 적는다.
- 남아 있는 미확인 사항과 위험을 수용해도 완료할 수 있는지와 그 판단 근거를 적는다.
- 남아 있는 미확인 사항과 위험이 없으면 `없음`으로 적는다.

### 완료 조건을 충족한 경우 `completed` (완료)로 변경된 현재 단계

- 완료 조건을 모두 충족하면 명세서 프론트매터의 `current_stage`를 `completed`로 변경한다.
- 현재 단계 값은 프론트매터에서 관리하고 본문에 중복해서 기록하지 않는다.
