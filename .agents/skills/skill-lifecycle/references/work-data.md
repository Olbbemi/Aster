# skill-lifecycle 작업 자료 배치

`skill-lifecycle`로 진행하는 스킬 개발 자료에 적용한다.

공용 접근 경로와 기록 및 보존 원칙은 [Aster 작업 규칙](../../../../AGENTS.md#공유-작업-데이터-접근)이 연결하는 규격을 따른다.
다른 내부 스킬이나 일반 작업에 이 문서의 단계별 기록을 강제하지 않는다.

## 작업 루트

- 플러그인 스킬은 공용 경로의 `cargo/work/plugins/<플러그인명>/<스킬명>/<작업명>/`을 사용한다.
- 플러그인과 개발 대상 스킬의 확정된 이름 및 대소문자를 사용한다.
- 내부 스킬은 `cargo/work/internal/<스킬명>/<작업명>/`을 사용한다.
- 기존 작업은 공유 작업 경로와 아래 완료 기록 경로를 함께 확인한다.
  - 완료 이관 전에는 관련 명세서와 기록에서 확인한 작업 루트를 유지하고, 이관 후에는 보존 정본을 사용한다.

- 단계의 의미와 진입/완료 조건은 [생명 주기 운영 규칙](lifecycle.md)과 각 단계 문서를 따른다.
- 공용 템플릿이 선택 사항이어도 lifecycle 전용 명세서와 진행 중 history의 필수 기록은 유지한다.
- lifecycle 자체 수정에는 [SKILL.md](../SKILL.md)의 제한된 절차를 적용한다.

## 완료 기록의 배치

보존 경로는 Aster 저장소 루트 기준이다.

| 대상 | 완료 기록 루트 |
| --- | --- |
| 플러그인 스킬 | `records/plugins/<플러그인명>/<스킬명>/<작업명>/` |
| 내부 스킬 | `records/internal/<스킬명>/<작업명>/` |

- 개발 대상의 확정된 이름과 대소문자, 기존 작업명을 유지한다.
  - 작업명 없이 스킬 자료 루트에 직접 기록한 기존 작업은 이관할 때 목적을 식별하는 작업명을 정한다.
- 기존 보존 작업과 충돌하는 이름을 사용하거나 서로 다른 작업을 같은 명세서에 합치지 않는다.
- 보존 루트는 실제 파일을 이관할 때 생성한다.

- `specification.md`는 보존 루트의 정본으로 유지한다.
- 나머지 파일은 [완료 산출물 정리와 보존](completion-records.md)에 따라 선별한다.
- 진행 중의 단계별 디렉토리 구조를 그대로 복제할 의무는 없다.

- 같은 작업을 재개하면 보존 명세서를 그 위치에서 갱신한다.
  - 새 중간 산출물은 대응하는 공유 작업 경로에 두며 명세서를 data로 다시 복사하지 않는다.
  - 보존한 history가 있으면 그 정본을 사용한다.
    없으면 필요한 진행 이력을 공유 작업 경로에 기록한다.
- 작업을 다시 완료할 때 자료를 선별하여 기존 보존본을 갱신한다.
- 별도 작업이면 기존 완료 기록을 변경하지 않고 새 작업 루트와 명세서를 사용한다.

## 진행 중 작업 루트 안의 배치

아래 표는 최초 완료 이관 전의 공유 작업 루트 기준이다.
이관 후 재개할 때는 위 [완료 기록의 배치](#완료-기록의-배치)를 따른다.

| 작업 루트 기준 위치 | 보관할 자료 |
| --- | --- |
| `specification.md` | 전체 단계의 단일 명세서, 현재 판단과 근거 자료 링크 |
| `history.md` | 해당 스킬 개발의 작업 목적, 수행 내용과 결과, 남은 작업 및 관련 자료 위치 |
| 루트의 공용 자료 | 여러 단계에서 함께 참조하는 작업 기준과 입력 자료. 특정 단계에만 쓰는 초안이나 실행 결과는 해당 단계 디렉토리에 둔다. |
| `structure-design/` | 설계 비교안, 초안과 논의 그룹별 구현용 상세 정의. 명세서에서 설명/상대 링크로 연결 |
| `mechanical-validation/` | 기계 검사 입력, 실행 명령/환경, 항목별 결과와 원시 출력 |
| `behavioral-validation/` | 동작 시험 시나리오, 실행 입력/로그와 관찰 결과 |
| `compatibility-validation/` | 하네스별 환경, 설치/실행 조건과 호환성 검증 결과 |
| `cross-validation/` | 검증 요청, 독립 검토 결과와 후속 판단. 하위 구성과 작성 기준은 [교차 검증 기록](../../../../standards/work-data.md#교차-검증-기록)을 따른다. |

## 관리 규칙

- 작업명은 새 작업을 시작할 때 목적을 식별할 수 있도록 정하고, 같은 스킬 자료 루트의 기존 작업과 구분한다.
- 기존 작업을 재개하거나 보완할 때는 명세서와 남아 있는 history의 정본을 확인한다.
  - 이관 전후의 위치와 재개 시 기록은 위 배치 기준을 따른다.
- 디렉토리는 미리 만들지 않는다.
  - 해당 단계의 산출물을 실제 저장할 때 필요한 디렉토리가 없으면 함께 생성한다.
- 자료는 생성 당시의 현재 단계보다 그 자료의 용도에 따라 분류한다.
  - 설계 중에 수행한 독립 교차 검증 기록도 교차 검증 자료로 관리한다.
- 자료가 존재한다는 사실은 해당 단계의 진입이나 완료를 뜻하지 않는다.
- 완료 이관 전의 단일 명세서는 공유 작업 루트에 유지한다.
  - 단계별 디렉토리에는 상세 근거를 두고 명세서에서 판단과 해당 근거의 위치를 연결한다.
- 여러 단계가 같은 자료를 사용하면 원본을 복제하지 않고 참조한다.
- 진행 중 작업 기록은 `history.md` 정본 한 파일로 관리하며 단계별로 나누지 않는다.
  - 작성 형식과 상태 관리는 [공용 기록 관리](../../../../standards/work-data.md#기록-관리)를 따른다.
- 작업별 디렉토리 기준은 새로 시작하는 별도 작업에 적용한다.
  - 기준 도입 전에 스킬 자료 루트에 직접 저장한 기존 작업은 해당 위치를 작업 루트로 유지한다.
- 기존 다른 작업의 자료는 자동으로 이동하지 않는다.
- 현재 작업의 완료 이관은 위 보존 기준을 따른다.
- 배치를 변경할 때는 해당 자료를 가리키는 명세서와 작업 기록의 참조도 함께 갱신한다.
