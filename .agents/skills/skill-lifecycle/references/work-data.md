# skill-lifecycle 작업 자료 배치

`skill-lifecycle`로 진행하는 스킬 개발 자료에 적용한다.

공용 접근 경로와 기록 및 보존 원칙은 [Aster 작업 규칙](../../../../AGENTS.md#공유-작업-데이터-접근)이 연결하는 규격을 따른다.
다른 내부 스킬이나 일반 작업에 이 문서의 단계별 기록을 강제하지 않는다.
lifecycle 자체 수정에는 [SKILL.md](../SKILL.md)의 제한된 절차를 적용한다.

## 경로 확정

스킬의 사용 형태를 내부용 또는 플러그인 배포용으로 정할 때 이름과 저장 경로를 함께 확정한다.
첫 파일 작성 전에 스킬 소스 경로와 아래 작업 루트를 정하며,
로컬 시험 자료가 필요하면 대응하는 로컬 자료 루트도 함께 확인한다.

- 스킬 소스 경로는 [저장소 배치 규격의 스킬 배치](../../../../standards/repository-layout.md#스킬-배치)를 따른다.
  실제 스킬 파일은 초안부터 그 경로에 작성하고 같은 파일을 계속 수정한다.
- 명세서, 설계 초안과 검증 문서는 아래 `records/` 작업 루트에서 처음부터 작성한다.
  초안이라는 이유로 별도의 임시 정본이나 작업 루트를 만들지 않는다.
- 스킬 이름과 경로는 명세서의 `name`과 `target_path`에 기록한다.
  기록 및 필요한 로컬 자료 루트는 요건 정의의 "스킬의 사용 형태" 항목에 기록한다.
  최초 기록 전에는 대화에서 확정한 경로를 사용한다.
- 사용 형태, 이름이나 작업명이 미정이어서 경로를 정할 수 없으면 필요한 논의를 먼저 이어간다.
  임의 경로에 파일을 만들거나 이름이 미정인 디렉토리를 생성하지 않는다.
  기록 요청이 있으면 경로를 정하는 데 필요한 정보와 아직 기록하지 못한 이유를 알린다.
- 경로 확정은 빈 디렉토리 생성이나 구현 착수, 단계 완료를 뜻하지 않는다.
  파일 역할과 작성 기준은 해당 단계에서 정하고, 디렉토리는 파일을 실제 작성할 때 생성한다.

## 작업 루트

기록 루트는 저장소 기준이며, 로컬 자료 루트는 공용 접근 경로 `~/.local/share/aster/` 기준이다.

| 대상 | 기록 루트 | 로컬 자료 루트 |
| --- | --- | --- |
| 플러그인 스킬 | `records/plugins/<플러그인명>/<스킬명>/<작업명>/` | `cargo/work/plugins/<플러그인명>/<스킬명>/<작업명>/` |
| 내부 스킬 | `records/internal/<스킬명>/<작업명>/` | `cargo/work/internal/<스킬명>/<작업명>/` |

플러그인과 스킬의 확정된 이름 및 대소문자를 사용한다.
작업명은 [작업명과 제목](specification.md#작업명과-제목)에 따라 목적과 변경 결과를 나타내며 같은 스킬의 다른 작업과 구분한다.
서로 다른 작업을 같은 명세서에 합치거나 기존 경로를 덮어쓰지 않는다.

단계의 의미와 진입/완료 조건은 [생명 주기 운영 규칙](lifecycle.md)과 각 단계 문서를 따른다.
공용 템플릿이 선택 사항이어도 lifecycle 전용 명세서와 진행 중 history의 필수 기록은 유지한다.

## 기록 루트 안의 배치

다음 문서는 초안부터 같은 위치에서 갱신한다.
작은 내용은 명세서에 직접 기록하고 상세 문서가 필요한 경우에만 분리한다.

| 기록 루트 기준 위치 | 보관할 자료 |
| --- | --- |
| `specification.md` | 전체 단계의 단일 명세서, 현재 판단과 근거 자료 링크 |
| `history.md` | 작업 목적, 수행 내용과 결과, 남은 작업 및 관련 자료 위치 |
| 루트의 공용 자료 | 여러 단계에서 함께 참조하는 작업 기준과 입력 정의 |
| `structure-design/` | 설계 초안, 비교안과 논의 그룹별 구현용 상세 정의 |
| `mechanical-validation/` | 기계 검사의 명령, 환경, 항목별 결과와 판정 근거 |
| `behavioral-validation/` | 동작 검증 시나리오, 실행 조건과 관찰 결과 |
| `compatibility-validation/` | 하네스별 환경, 설치/실행 조건과 호환성 검증 결과 |
| `cross-validation/` | 검증 요청, 독립 검토 결과와 필요한 후속 판단 |

교차 검증의 하위 구성과 작성 권한, 회차 관리는
[교차 검증 기록](../../../../standards/work-data.md#교차-검증-기록)을 따른다.

## 로컬 자료의 배치

원시 대화/실행 로그, 시험용 복제본, 일회성 입력과 반복 출력은 로컬 자료 루트에 둔다.
여러 단계가 사용하는 자료는 루트의 공용 자료로 두며,
특정 검증에만 쓰는 자료는 해당 검증 단계 디렉토리에 모은다.
파일을 만들 때마다 별도의 작업 루트를 지정하지 않는다.

진행 중에는 기록에서 로컬 근거를 연결할 수 있다.
완료할 때는 필요한 결과와 재현 정보를 기록 루트에 보존하고,
로컬 자료 없이도 최종 판단을 이해할 수 있도록 정리한다.
보관 기간과 삭제는 [시험 정리](scenario-validation.md#시험-생성물과-임시-기록-정리)를 따른다.

## 완료와 재개

완료할 때는 [완료 산출물 정리와 보존](completion-records.md)에 따라
기록 루트에서 명세서와 부가 파일을 최종 정리하고 보존 대상을 선별한다.
새 작업은 완료를 이유로 명세서를 이동하거나 사본을 만들지 않는다.
파일 위치는 진행 상태나 완료 및 실제 커밋 여부를 대신하지 않는다.

같은 작업을 재개하면 해당 위치의 명세서와 남아 있는 history를 갱신한다.
history를 명세서에 통합하여 별도 파일이 없으면 필요한 진행 이력을 기록 루트에 다시 작성한다.
별도 작업이면 기존 완료 기록을 변경하지 않고 새 작업 루트를 사용한다.

### 기존 작업의 경로

기준 변경 전에 시작한 작업은 `records/`와 공유 작업 경로에서 관련 명세서와 history를 확인하고,
기록과 실제 파일을 대조하여 정본을 식별한다.
기존 기록은 해당 위치에서 재개하며 다른 작업의 자료를 일괄 이동하지 않는다.

기존 명세서가 로컬 경로에 있다면 현재 작업의 기록 경로 전환 또는 완료 정리 시
[기존 로컬 기록의 이관](completion-records.md#기존-로컬-기록의-이관)을 수행한다.
작업명 없이 스킬 자료 루트에 직접 저장한 기존 기록은 전환할 때 목적을 식별하는 작업명을 정한다.
경로 전환 전까지 기존 명세서와 작업 루트를 유지하고 정본을 중복 생성하지 않는다.

## 관리 규칙

- 자료는 생성 당시의 단계보다 용도에 따라 배치한다.
  설계 중 수행한 독립 교차 검증도 교차 검증 자료로 관리한다.
- 자료가 존재한다는 사실은 단계 진입이나 완료를 뜻하지 않는다.
- 명세서에는 판단과 근거의 위치를 연결하고, 여러 단계가 같은 자료를 사용하면 정본을 참조한다.
- 진행 중 작업 기록은 `history.md` 한 파일로 관리하며 단계별로 나누지 않는다.
  작성 형식과 상태는 [공용 기록 관리](../../../../standards/work-data.md#기록-관리)를 따른다.
- 확정한 경로를 변경해야 하면 변경 이유와 영향 및 새 경로를 사용자와 논의한다.
  실제 이동 전에 명세서에 반영하고 관련 참조를 함께 갱신한다.
