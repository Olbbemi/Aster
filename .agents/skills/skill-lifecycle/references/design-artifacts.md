# 구조 설계 산출물

`structure-design`의 뼈대를 정하고 최종 설계 결과를 정리할 때 읽는다.
명세서의 필수 기록 항목과 단계 전이 조건은 기존 규격을 따른다.

## 뼈대와 상세

먼저 책임, 입력/결과, 파일 역할, 참조/의존 관계와 주요 조건/전이를 정한다.
규모가 크면 이 뼈대를 기준으로 구현 순서와 함께 검토할 논의 그룹을 정한 뒤 상세를 구체화한다.
모든 내부 함수와 보조 자료구조를 처음부터 논의하지 않는다.

구현에 적용할 계약, 조건과 검증 기준은 구현 전에 확정한다.
현재 구현을 막는 미정 사항과 후속 작업에서 구체화할 내부 세부사항을 구분하며,
필수 설계가 미정인 상태를 구조 설계 완료나 구현 재량으로 넘기지 않는다.

## 구현용 정의

설계 종료 시 다음 중 대상에 해당하는 정의를 표, 선언 또는 도식으로 남긴다.
자연어는 선택 이유, 제약과 정의를 이해하는 데 필요한 설명에 사용한다.
설계 내용을 설명 문장만으로 대체하지 않는다.

| 대상 | 남길 정의 |
| --- | --- |
| 파일/구성 | 경로, 생성 조건, 역할, 대응 요건과 정본 위치 |
| 참조/의존 | 참조하는 대상, 방향, 사용 조건과 배포 경계 |
| 입력/결과/데이터 | 이름, 형식/타입, 필수성, 제약과 오류. 실제 필요한 구조체/스키마만 포함 |
| 처리/상태 | 진입/종료, 주요 분기, 실패/중단/재개 조건과 상태 전이 |
| 검증 | 요건, 조건/입력, 기대 결과와 판정 기준의 대응 |

한 규칙의 정의는 한 곳에 둔다.

명세서에는 전체 구조와 판단을 남기고, 긴 정의는 논의 그룹별 상세 문서로 연결한다.
저장 위치는 [전용 작업 자료 배치](work-data.md#진행-중-작업-루트-안의-배치)를 따른다.

그룹의 간단한 설명과 상대 링크를 기록하며 흐름 하나마다 파일을 만들지 않는다.
작은 설계는 명세서 안에서 정의하고 분리를 강제하지 않는다.

## 도식 정리와 표시 확인

- 주요 분기나 관계를 도식으로 설명하는 편이 명확하면 ASCII 흐름도를 사용한다.
  - 단순한 순서나 표로 충분한 내용까지 모두 도식으로 그리지 않는다.
- 중간 초안은 논의에 필요할 때 작성하며 매 응답/수정마다 다시 그리지 않는다.
- 구조 설계를 마무리할 때 현재 정의와 도식 및 인계 내용을 대조한다.

- 도식은 `text ascii-flow` fenced code block에 두고 ASCII 연결 기호와 공백을 사용한다.
- 짧은 세로 흐름과 영문 식별자를 우선하고, 긴 설명은 도식 밖에 둔다.
  - 한글을 포함하면 고정폭 글꼴에서도 글자 폭이 달라질 수 있으므로 실제 표시로 확인한다.

- 도식을 작성하거나 수정했다면 [검사 스크립트 사용 가이드라인](../../../../tools/guidelines.md)과
  [ASCII 도식 검사 안내](../../../../tools/references/check-ascii-flows.md)에 따라 문자 형식을 검사한다.
  - 검사한 도식 수와 위반 위치를 확인하고 형식 오류를 보완한다.
- 도식이 없는 작업에 검사용 도식을 새로 만들지 않는다.

- 원문과 고정폭 렌더링에서 줄바꿈, 연결선 끝점/분기와 설명의 대응을 확인한다.
  - 깨지는 부분은 폭과 배치를 단순화하고 다시 확인한다.

- 사용한 표시 환경, 확인 범위와 결과를 설계 정리 근거에 남긴다.
- 직접 표시를 확인하지 못하면 미확인으로 알리고 사용자 확인을 받는다.
- 문자/참조 검사를 통과했다는 사실로 표시 확인을 완료 처리하지 않는다.
