# 공용 모델 선택 기준

내부 스킬과 플러그인 스킬이 작업 성격에 맞는 모델과 추론 강도를 제안할 때 읽는다.
작업 묶음, 사용자 승인과 실제 적용 절차는 호출하는 스킬의 지침을 따른다.

## 선택 원칙

- 아래 조합은 Aster의 권장 시작점이며 실제 비교 시험으로 입증한 성능 순위가 아니다.
  사용자가 지정한 모델과 추론 강도 및 적용 범위를 우선한다.
- 단계명이나 파일 수보다 판단의 복잡도, 요건의 명확성, 변경 영향과 시간 및 사용량을 고려한다.
  표의 각 행을 별도의 필수 작업이나 모델 호출로 취급하지 않는다.
- 자연어 중심의 문서 작성과 스킬 생성 및 지침 설계는 Astra를 우선 권장한다.
  구현 단계라도 작성 대상이 스킬 지침이면 이 기준을 적용한다.
- 권장 모델과 강도를 해당 실행 환경에서 사용할 수 있는지 확인한다.
  사용할 수 없으면 가능한 대안과 선정 이유를 제시하고 호출 스킬의 승인 절차를 따른다.
- 같은 추론 강도 이름도 모델 간 같은 연산량이나 품질을 뜻하지 않는다.
  강도를 높이면 시간과 사용량이 늘어날 수 있으며 모델과 강도를 함께 선택한다.

## Codex

| 작업 상황 | 권장 모델 | 추론 강도 |
| --- | --- | --- |
| 범위와 기준이 명확한 작은 수정, 형식 확인 | GPT-6 Luna (`gpt-6-luna`) | low |
| 확정한 설계에 따른 일반 코드 구현 | GPT-6.1 Sol (`gpt-6.1-sol`) | medium |
| 개별 로직 분석, 일반적인 변경 영향 검토 | GPT-6.1 Sol (`gpt-6.1-sol`) | high |
| 스킬 생성, 요건과 지침 설계, 자연어 중심 문서 작성 | GPT-6 Astra (`gpt-6-astra`) | high |
| 여러 지침의 충돌, 예외와 단계 연결이 복잡한 스킬 설계 | GPT-6 Astra (`gpt-6-astra`) | xhigh |
| 여러 모듈과 비동기, 스레드, 동기화가 얽힌 코드 분석 | GPT-6 Astra (`gpt-6-astra`) | xhigh |
| 깊이 분석해도 핵심 쟁점이 풀리지 않는 고난도 문제 | GPT-6 Astra (`gpt-6-astra`) | max를 별도 제안 |

복잡한 코드 분석은 여러 모듈의 실행 순서와 공유 상태, 동시성, 재시도 및 회귀 원인을
함께 추적해야 하는 경우를 포함한다.
코드를 읽는 모든 작업을 이 범주로 분류하지 않는다.
max는 일반 작업의 기본값으로 두지 않으며 모든 강도를 순서대로 실행할 필요도 없다.

## Claude

Aster의 주된 활용인 교차 검토를 중심으로 후보를 제시한다.
세부 조합은 실제 검토 범위와 실행 환경에 맞춰 제안하며 단계마다 고정 배정하지 않는다.

| 검토 상황 | 모델 후보 | 강도 선택 기준 |
| --- | --- | --- |
| 일반 검토 | Sonnet | 명확한 범위는 medium, 경계 조건과 검증 판단이 중요하면 high |
| 복잡한 설계, 연관 동작과 동시성 검토 | Opus | high를 시작점으로 삼고 여러 제약과 실행 흐름을 깊게 추적해야 하면 xhigh |

2026-10-01 확인한 Anthropic API 기준 후보는 Sonnet 5.5와 Opus 5.5다.
`sonnet`, `opus` 별칭이 가리키는 버전은 제공자와 설정에 따라 다르므로 실제 선택 모델을 확인한다.
Codex와 Claude의 표가 같은 작업을 다룬다는 사실을 동등한 성능의 근거로 사용하지 않는다.

## 근거와 갱신

확인 날짜: 2026-10-01.

모델의 용도와 강도 설명은 아래 공식 안내를 참고하고,
자연어 작업의 Astra 우선 선택과 작업별 조합은 Aster에서 합의한 운영 기준으로 관리한다.
실제 스킬에서의 품질이나 시간 및 사용량 개선을 시험한 결과는 아니다.

- [OpenAI 모델 선택 안내](https://developers.openai.com/api/docs/guides/model-selection)
- [Claude Code 모델과 추론 강도 안내](https://code.claude.com/docs/en/model-config)

모델 제공 범위나 공식 안내가 바뀌거나 실제 작업에서 추천의 한계가 확인되면
이 정본의 후보, 선정 근거와 확인 날짜를 함께 갱신한다.
이미 승인받아 진행 중인 작업의 모델을 표 갱신만으로 변경하지 않는다.
개별 스킬에 표의 사본을 만들어 따로 갱신하지 않는다.
